- ODR-264 [THR-8], [CLO-10], [FN-6], grammar `fn_type` lead (helper AD's question 1): a written callable type may say its values are `Send`: `fn(A) -> R + Send`, as a generic bound already writes it (`F: fn() + Send`); a closure becomes one only when everything it captures is `Send`, checked there (`E7004`, naming the capture); a function always is; a value of a callable type without `+ Send`, or a callable parameter not bounded `Send`, may hold anything and is not (`E7004`); a `+ Send` value is the same value without it. A parameter written `f: fn() + Send` is `F: fn() + Send`. After a return type the `+ Send` is the callable's whose return type it ends (`fn() -> fn() + Send` is a `Send` callable giving a `fn()`), as the bound form reads it; in a bound list `+` keeps separating bounds. A callable value is never `Sync` (a call may change what it captured), so `+ Sync` is `E7005` (narrowed from the first wording, "`Send` (or `Sync`)": a `Sync` callable would need calls that change nothing, which the type cannot say). The next cut writes the grammar `fn_type := … ["->" type] ["+" "Send"]` and `[CLO-10]`/`[THR-8]` so. BUILT (tests/conformance/CLO-10/accept_a_callable_type_written_send_holds_only_what_is_send.em, reject_a_send_callable_type_takes_only_what_is_send.em).

- ODR-277 [BEN-5], [TST-28] lead (helper AF's AF4): none of AF's options; AF's cause (full LTO and C's undefined overflow) was not the cause. `int_math` was a defect of the benchmark: its Ember line added to `total` three times a pass (`total = total + a + b - c`) where its C twin adds once (`total += …`), and LLVM's loop strength reduction built three more multiplications a pass from that form (38 instructions and 6 multiplications against 30 and 4). Written as the twin is (`60588521`), the LLVM-built loop is the twin's instruction for instruction. `a10_recursion`'s gap is the overflow check on `+` (Clang turns the twin's `fib(n-1) + fib(n-2)` into a loop with a running total, which LLVM's accumulator recursion elimination refuses while a check sits between the `+` and the `return`): deleting only the check closes it, a valid end under the owner's rule. A loop rewrite keeping the checks (a wide running total, every partial sum checked at the end) was proved equivalent by brute force and then measured slower and larger than the current build (131.5 ms against 116.1 ms, 192-byte frames against 80; C 68.6 ms, 64 bytes), and dropped. AF's (b), `nsw`/`nuw` from a proved-away check, stays an idea to measure before building (helper AI). SETTLED.
