# Round 3: the open ODRs ruled for the best solution (2026-11-08, the lead, solo)

The owner's instruction: "for the ODRs can you go for the best solution possible? that matches all the goals we
are trying to achieve?", then "go solo no agents". A design workflow was started and stopped at the owner's word;
two designer results for ODR-260 had finished (`results/odr-260-designs.json`, both "shape B stands with wording
fixes") and are used as input below. Everything else is the lead's own reading of the text
(`docs/spec-source/Ember_v0.9.20_Hardened_3.md`, the verdicts in `tasks/96/redesign/JOB.md`, the round-2 records).
The four goals weighed for each: C-like speed, Python-like readability, Rust-like memory safety without lifetime
names, and a complete, consistent text. Every departure from an owner verdict is named.

|---|---|---|---|
| ODR-260 `thread_shared … using` | **stands** (shape B), nine wording fixes, one adjacent hole closed | A (refuse every manager): drops a feature C++'s `std::allocate_shared` over a `pmr` resource and Rust's `Arc::new_in` have, for a hazard that counting away from the making line removes. A manager-any-thread-may-call-only or arena-only limit: fixes a form where B states the property. Dropping the word by `FoundByAddress` for every manager: asks more of every manager than B's placement, which already costs no byte. A smaller header, or the maker's id kept in the header (two counts kept): departs from verdict 101 for a figure. The queue place is free for a value counted away from birth because only the below-zero subtract of `[RC-4]` point 2 writes it, and such a value's away count never goes below zero. The hand-over to an unscoped thread is allowed from a `static` instance only: a `static mut` may be reset by a line of the main thread while the thread runs, a fact of the whole program (`[BLD-16]`); the message gives the three lines to write (the built-in manager; a `static` manager that locks inside; a scope). Fixes: `[TYP-46a]` (growth and end count for `[THR-11]` as the calls they make, by the methods' summaries; the accepted clause), `[LT-4]`, `[ALC-5]`, `[OBJ-1]` (why the queue place is free, one method body per class), `[RC-4]` point 4 (both reasons for the mark), `[ALC-1]` (`using x` through any name where `allocate` reads the instance), the two §X.4 rows (the mark a constant store; the give-back one load), registry row E3063. Adjacent hole: `into_raw()` on a value Ember made `using` another manager is `E2114`, since C ends it through `ember_rt_object_release`, which gives back only blocks of the built-in manager (`[FFI-54]`). In a generic body the making line is refused at the definition, not per instance: `thread_shared T using a` with `a` of a type parameter `A` needs a manager any thread may call (`[TYP-46a]`), a property no bound on `A` provides, and inside a generic body only the operations the bounds provide are available (`[TYP-17]`, `E2040`); a spelling of that property in a bound would be a new word and no program seen needs it. | 19, 47, 101, 107, 164, 165 kept |
| ODR-261 `open` class promise; `Error`'s markers | **class half stands; `Error` half changes** to Rust's shape | The class promise is the one shape a package decides from a declaration it sees (`[BLD-16]`; verdict 61's word over a search). Edits: `[ERR-3]`, `[ERR-8]`, `[ERR-1]`, `[DRV-1]`, `[THR-9]`, `[THR-8]`'s example, `[TYP-17]`, the §IV.8 listing, registry rows E2040 and E2080. Send-only (c) was set aside: a scoped task reads a `Result` through `ref`, so `AnyError` needs both. | 110 restored to its letter; 61 as Hardened_3 reported |
| ODR-262 C++ overloads, `at`/`at_mut` | **stands** | `at_mut` is the language's own spelling of the same thing everywhere (`get_mut`, `iter_mut`, `index_mut`, `span_mut`), written at the call, so nothing is read from the name the object is reached through; reading the member from the object's kind would make one line mean two things. The C aliases stay transparent, as Rust's `c_int` and Swift's `CInt` are; a distinct nominal `c_int` (Zig) would tax every C call for one case (two overloads differing only in `int`/`long` where both are 32 bits), which `E5035` names and one `rename`/`hide` settles. | 131, 132, 60 kept |
