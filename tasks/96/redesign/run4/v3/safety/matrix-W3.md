# Safety matrix, writer W3: R7 (kept views) and R8 (views and changes, checked when compiling)

Writer W3 of safety validation (b). `V3` = `tasks/96/redesign/run4/v3/`; "line N" without a file is a
line of `V3/rules.md`; "verdict N" is the owner's verdict N in `V3/inputs/JOB.md`; "AN-N" is the answer
in `V3/area-*.md`. Nothing was compiled or run (brief, "Machine limits"). Tests are in
`V3/conformance/R7/` (40 files) and `V3/conformance/R8/` (82 files): 57 `accept_`, 62 `reject_`,
3 `run_`. Every `reject_` file marks the refused line with `#$ error[CODE]: message` and gives the
line the message offers in `#$ help:`; every line number a message names was checked against its file
by `target/redesign5/W3/lines.py`.

**How every row is verified once the model is built.** `compile-fail`: the conformance runner checks
the code and the message on the marked line (and the `#$ help:` text). `run-pass`: the runner compares
stdout with `#$ stdout:`. `run-fail`: the runner checks the panic starts with `#$ panics:`. Where a row
guards memory (a moved buffer, a freed text, a freed block), its accepted programs are also run once
under AddressSanitizer (the C backend with Clang `-fsanitize=address`), which must report nothing: that
shows the accepted program is not only accepted but safe.
