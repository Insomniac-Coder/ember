# Safety matrix, writer W1: rules R1, R2, R3, R13

R13 654-667; section 2 lines 763-800; section 3 lines 802-892; section 4 lines 894-971), words from

owner's verdicts in `V3/inputs/JOB.md`, and the answers named in each row. Nothing was compiled or run.
The tests are in `V3/conformance/R1/`, `R2/`, `R3/` and `R13/` (133 files). Every test's `## ` comment
quotes its guarantee and names its answer; every refused line carries `#$ error[CODE]: ...` and the
file's `#$ help:` gives the line to write.

How a result is verified once the model is built, for every row:
- `compile-fail`: the conformance runner (`tests/conformance`, today's harness in
  `compiler/ember_driver/tests/`) checks the code and the message on the marked line, and the `#$ help:`
  text; one mistake gives one message (R18), so a second diagnostic fails the test.
- `compile-pass` / `run-pass`: the runner checks that it compiles with no error and that stdout equals
  the `#$ stdout:` lines.
- `run_` tests (the run-time rows of section 2): the same stdout check, and the same program built with
  AddressSanitizer and LeakSanitizer (today's sanitizer profile of `ember_rt`), which must report
  nothing: each block allocated and freed once, no read of freed memory.

"Enforced by" names the part that would enforce the rule and today's source file doing that kind of
work: parser (`compiler/ember_parser/src/body.rs`, `decls.rs`), type checker
(`compiler/ember_typeck/src/lib.rs`, `errors.rs`, `habits.rs`), borrow check (the MIR pass:
`compiler/ember_mir/src/lower.rs`, `compiler/ember_analysis/src/borrows.rs` for views and E3060/E3021,
`drops.rs` for moves and drop flags, `regions.rs` and `stores.rs` for lifetimes and E3063), code
generator (`compiler/ember_codegen_c/src/lib.rs`, `compiler/ember_codegen_llvm/src/arenas.rs`,
`closures.rs`), runtime (`runtime/ember_rt/src/ember_rt.c`).
