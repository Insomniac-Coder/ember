# Safety matrix, group W6: R14, R15, R16 and the C side

Run 4, step 3, agent 12 (test updater for group W6), from the matrix writer W6 wrote in safety validation
(b) and its checker's results (`V4/safety/check-V6.md`). Rules: R14 (interface values, kind tests,
casts, and verdict 46's `dyn ... changes`), R15 (threads), R16 (`unsafe`), and the C side of R12 and R15
(kept callbacks, `@ffi(no_callbacks)`, the checked trampoline, variadic calls; verdicts 31, 39, 62).
Sources: `V4/rules.md` (cited as `rules.md:N`, the v4 file as agent 01 left it), `V4/vocabulary.md`,
`V4/changes.md`, `V4/inputs/JOB.md` (verdicts 1 to 82), `V4/inputs/worklist.md`, `V4/safety/check-V6.md`,
`V4/safety/completeness.md`. Nothing was compiled or run.

The tests are in `V4/conformance/R14/` (38), `V4/conformance/R15/` (116, and the C library of the
trampoline and callback tests, `kept_events.c` with `kept_events.h`) and `V4/conformance/R16/` (16, and
the C function of the variadic tests, `wide_sum.c` with `wide_sum.h`): 170 tests (60 `accept_`, 91
`reject_`, 19 `run_`). Line numbers inside expected messages and stop texts are the test file's own lines
(checked by `target/redesign6/12/check_lines.py`, which prints the text of every line a message names,
output `check_lines.txt`; the files are written by `target/redesign6/12/gen.py` from `tests_r14.py`,
`tests_r15.py`, `tests_r15_c.py`, `tests_r16.py`, which reproduce v3's files byte for byte before this
step's edits). Where a guarantee is also another group's, the row names that group's test (`R9/...`, W4).

How every result is verified once the model is built: the conformance runner (`ember test`,
`compiler/ember_driver/src/test_runner.rs`) compiles each file and compares the output with its `#$`
lines: for `compile-fail` the code and the message of each `#$ error` on its line, and `#$ help:`; for
`compile-pass` the `#$ warning` lines; for `run-pass` the stdout lines in order; for `run-fail` the
stdout before the stop and the start of the stop's text (`#$ panics:`). The thread tests are also run
once under ThreadSanitizer and the trampoline, callback and cast tests under AddressSanitizer (C backend,
Clang), which must report nothing: that shows the run-time checks stop the program before memory is
touched wrongly, and that the compile-time checks leave no data race.

"Enforcing part": parser `compiler/ember_parser/src/body.rs`, `decls.rs` (lexer
`compiler/ember_lexer/src/token.rs`); type checker `compiler/ember_typeck/src/lib.rs` (old spellings in
`compiler/ember_typeck/src/habits.rs`); borrow check = the MIR passes of `compiler/ember_analysis/src/`
(`borrows.rs`, `regions.rs`, `stores.rs` for E3026, `coroutines.rs` for E2221, `static_safe.rs` for
E4030, `effects.rs` for today's effect sets, the nearest existing work to checking `changes`); MIR
lowering `compiler/ember_mir/src/lower.rs` (`lower_class_downcast`), `compiler/ember_mir/src/parallel.rs`;
code generator `compiler/ember_codegen_c/src/lib.rs` (the downcast stop, `AssertKind::Downcast`; the C
trampolines), `compiler/ember_codegen_llvm/src/ffi.rs` and `dispatch.rs`; interface files
`compiler/ember_build/src/interface.rs` (R17); runtime `runtime/ember_rt/src/ember_rt.c`
(`ember_downcast`, locks, thread checks). The codes section 4 marks bold (not in today's
`compiler/ember_diag/src/codes.rs`) are emitted nowhere today; the row names the part that would.

## Open points (each is in the form's `for_owner`)

1. **The trampoline tag's layout.** `run_c_holds_a_tagged_number_not_an_address.em` checks AN-78's
   `0x4080` in the top 16 bits; the rules say only "a tagged `{slot, generation}` number, never an
   address" (`rules.md:866-868`). No verdict settles it.
2. **The stop of a used-up `callback(once)` called again.** Section 2's table (`rules.md:958-959`) has
   texts for a call after the token ended and for a wrong thread, none for this case;
   `run_fail_c_calls_a_once_callback_twice.em` checks only the start both texts share ("C called the
   callback registered on line 29").
3. **E5013's message says what `sum_wide` reads** (`int64_t`), which the compiler cannot see in C; R18
   (`rules.md:912`) says a message says only what the compiler knows. The test uses the worklist's text
   (section 4, item 12) as given.
4. **A `thread_shared` object whose class has a field of a plain function type.** Verdict 61 says such
   fields "use such types" (`thread_shared fn()`); no code or line is given for one that does not, so no
   test is written for it.
5. **A scoped task's loop name without `with copy of`: E3026.** R15 (`rules.md:836-840`) puts the loop's
   own variable and a round local in one sentence and names no code; the test uses the round local's
   (AN-73's E3026). For an unscoped thread E7004 applies (no capture word).
6. **Verdict 65's copy for a string loop variable.** `with copy of t` for `for t in texts:` copies each
   `String` into its task (one allocation per task), where Rust's scoped threads borrow `&t`; the tests
   follow the verdict as written.
7. **A plain `thread_shared Log` argument beside a `fn() changes Log` argument of one call** (check-V6
   item 10, `V4/changes.md` section 12 item 5): `reject_a_call_through_a_function_value_that_may_take_the_held_lock.em`,
   `reject_a_function_value_that_changes_another_log_inside_the_lock.em`,
   `accept_the_function_value_called_after_the_lock_is_let_go.em` and
   `reject_a_walk_under_the_lock_across_a_function_value_that_changes_log.em` take R4 (`rules.md:268-277`)
   to allow it; no verdict settles it.
8. **`owns` on the making line of an `Option[owns T]` field** (verdict 74's reach): the generator tests
   write `next=Some(owns Link(value=1))`; the verdict names `owns T` fields, not an `Option` of one.
9. **A change a callee names by a type, on the caller's own local** (`V4/changes.md` section 12 item 3):
   `accept_a_task_takes_the_lock_itself.em` follows R5 as written (`main` and the task say
   `changes Mutex[Array[int]]`).
10. **Which line carries E2040 when two operations of a `pub` body need the missing bound** (check-V6's
    U6): the test now uses section 3's one-operation example (`rules.md:1001`); R14 (`rules.md:818-819`)
    still does not say it for two.
11. **E7010's second way out and E7015.** Section 3's E7010 message (`rules.md:1056`) offers guarding
    the fields of `shares mut Player` objects that `@parallel` chunks on other threads change through
    `ref mut` views; R9 (`rules.md:484-485`) says a `shares` value never reaches another thread (E7015).
    Whether a chunk's view of such an object counts as reaching it is not said; if it does, the way out
    runs into E7015 (verdict 73). The test keeps the message (its first way out compiles).
