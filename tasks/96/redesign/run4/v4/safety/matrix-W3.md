# Safety matrix, group W3: R7 (kept views) and R8 (views and changes, checked when compiling)

Run 4, step 3, agent 09 (test updater for W3), from writer W3's table of safety validation (b), brought to
verdicts 1 to 82. `V4` = `tasks/96/redesign/run4/v4/`; "line N" without a file is a line of
`V4/rules.md`; "verdict N" is the owner's verdict N in `V4/inputs/JOB.md`; "AN-N" is the answer in
`V4/area-*.md`; "check-V3" is `V4/safety/check-V3.md`; "G-N" is gap N of `V4/safety/completeness.md`.
Nothing was compiled or run (brief, "Machine limits"). Tests are in `V4/conformance/R7/` (43 files) and
`V4/conformance/R8/` (100 files): 67 `accept_`, 73 `reject_`, 3 `run_`. Every `reject_` file marks the
refused line with `#$ error[CODE]: message` and gives a line of that message in `#$ help:`; every
"line N" a message names was checked against its file (`target/redesign5/W3/lines.py`,
`target/redesign5/V3/linecheck.py`), and every `#$ help:` text was found in its message
(`target/redesign5/V3/helpcheck.py`). The files as this step found them are in
`target/redesign6/09/orig/`; the edits were made by `target/redesign6/09/r7_edits.py` and
`r8_edits.py` through `apply.py`.

**How every row is verified once the model is built.** `compile-fail`: the conformance runner checks
the code and the message on the marked line (and the `#$ help:` text). `run-pass`: the runner compares
stdout with `#$ stdout:`. `run-fail`: the runner checks the panic starts with `#$ panics:`.
`#$ assert-c-count:` lines are checked on the emitted C by today's runner
(`compiler/ember_driver/tests/milestones.rs`, `assert_c_count`). Where a row guards memory (a moved
buffer, a freed text, a freed block), its accepted programs are also run once under AddressSanitizer
(the C backend with Clang `-fsanitize=address`), which must report nothing: that shows the accepted
program is not only accepted but safe.
