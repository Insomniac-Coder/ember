# Safety matrix, group W3: R7 (kept views) and R8 (views and changes, checked when compiling)

Run 4, step 4, agent 06 (test updater for group T2), brought to verdicts 1 to 97 and the corrected
records of verdicts 53 and 58. `V5` = `tasks/96/redesign/run4/v5/`; "line N" without a file is a line of
`V5/rules.md`; "verdict N" is the owner's verdict N in `V5/inputs/JOB.md`; "AN-N" is the answer in
`V5/area-*.md`; "the worklist" is `V5/inputs/worklist.md`; "G-N" is gap N of `V5/safety/completeness.md`.
Nothing was compiled or run (brief, "Machine limits"). Tests are in `V5/conformance/R7/` (46 files) and
`V5/conformance/R8/` (110 files): 73 `accept_`, 80 `reject_`, 3 `run_`. Every `reject_` file marks the
refused line with `#$ error[CODE]: message` and gives a line of that message in `#$ help:`; every "line N"
a message names was checked to point at a code line of its file, and every `#$ help:` text was found in
its message (`target/redesign7/06/`, the check after `r8_edits.py`). The files as this step found them are
in `target/redesign7/06/orig/`; the edits were made by `target/redesign7/06/r7_edits.py` and
`r8_edits.py` (helpers in `lib.py`: every replacement must match exactly once, and a comment block whose
length changes shifts the `line N` references below it).

**How every row is verified once the model is built.** `compile-fail`: the conformance runner checks
the code and the message on the marked line (and the `#$ help:` text). `run-pass`: the runner compares
stdout with `#$ stdout:`. `run-fail`: the runner checks the panic starts with `#$ panics:`.
`#$ assert-c-count:` lines are checked on the emitted C by today's runner
(`compiler/ember_driver/tests/milestones.rs`, `assert_c_count`). Where a row guards memory (a moved
buffer, a freed text, a freed block), its accepted programs are also run once under AddressSanitizer
(the C backend with Clang `-fsanitize=address`), which must report nothing: that shows the accepted
program is not only accepted but safe.

**What a change is, since verdict 86.** No first line says what a function changes or reads, and no
function type says it either. Every row below that uses "what a call may change, end or reshape" gets that
fact from the code, as R5 (lines 362-384) says: the callee's own lines, the functions it calls, every
function the program can put in a function value it calls (R12, lines 662-671), and the `drop` of every
object it may end; the message names the chain of calls (R18, lines 952-954).
