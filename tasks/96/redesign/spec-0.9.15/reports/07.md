## 4. Technical points settled (safely), with reasons

1. **`E3032` for verdict 99's refusal.** A new code was needed (L3001 was a warning); E3032 is the next
   free one after E3031 in the ownership range. Checked unused: `grep -rlw E3032 compiler docs/spec-source
   std tests tasks` finds no file (`target/redesign9/07/free_code_E3032.txt`).
2. **One meaning each.** Section 4 gives the cases of five of today's codes to other codes: a field taken
   out of a class object and a function value's capture given away to `E3013` (so `E3012`, `E3030`
   retire), a part handed over then its owner used whole to `E3040` (`E3042`), a value outliving its
   memory manager's instance to `E3063` (`E3061`), a lambda parameter's word against the function type
   to `E2020` (`E2228`). Keeping both codes would give one case two codes. Codes whose subject is gone
   retire: `E3025` (a method's field set is always worked out), `E3065`, `L3014` (no regions: a result
   points into every view argument it may come from), `E3080`, `L3013` (no access checked while running),
   `L3011` (`RefCell`), `E2229` (a generator method's result is a view of its object; changes are
   `E3020`/`E3021`), and, by section 4, `E3041`, `E7001`, `E7003`, `E7005`, `W2111`.
3. **`E3095` stays**, narrowed to "two single-object references given to `assert_disjoint`" (`[DSJ-4]`):
   area A keeps it as today's code (`V5/area-A.md` 3134, 3621) and section 4 does not remove it.
4. **`E5054` gains `char`** (C28 names E5054 for it): "range type, or `char`, in a foreign signature".
5. **`E2173`** keeps one meaning, "a type position holding what is not a type": section 4's bare
   interface name (`Array[Shape]`) and today's grammar case are the same kind of mistake.
6. **`E2031` stays** with `from` for `@borrows`: the design says nothing of a `from` naming a parameter a
   view cannot point into, so today's rule stands in the new spelling.
7. **The stop texts sit in `[PRF-4]`** (the crosswalk puts section 2 in PRF too); the same table is
   expected in COST (p10) and RT (p18): it must be identical there.
8. **`ember explain --borrow` becomes `--view`**, with the model's words; it reads the compiler's own
   facts (`[BCK-1]`).
9. **Shapes**: O3, O4, O5, B8, B14, B15 and X1 are dropped (their codes retired or folded; a sentence
   under the table says so, so the ids are not reused); B16 (`E3031`) and B17 (`E3032`) are added, and
   `E3028` joins B10, so every `E3xxx` code has exactly one shape (`[DIA-7a]`). N15 to N18 classify the
   model's new name and type codes (`[DIA-12]` fails CI on an unclassified one).
10. **`[DIA-9]`** no longer forbids suggesting a copy first: section 3's own messages offer
    `copy of` first (E3031, E3040), so the rule now forbids `unsafe` while a safe fix compiles and
    `shares` alone where a one-owner fix compiles.
11. **`[ERR-4]`'s eager methods** take the function as a type parameter (verdict 38: a library function
    that calls a function right away), written on its own line in prose as "`[...]` above `fn ...`"
    (verdict 50); `Result.map_err` and `Result.or_else` name the function type `G` because `F` is their
    error type.

    rewrite what it can) and what needs a choice the source does not say (`Shared[T]`, `RefCell`, `@sync`,
    `owned fn`, `mem.forget`). `@view` is no longer removed by the migration (vocabulary row `@view`).
