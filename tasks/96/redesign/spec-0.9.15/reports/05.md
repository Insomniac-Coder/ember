## 4. Technical points I settled, with reasons

1. **`.cloned()` goes with `.copied()`** (`[STD-19]`, E1010 "write `.copy_each()`"): `copy_each` gives
   what `copy of` makes, which is `Clone`'s copy, so `.cloned()` would be a second spelling of one
   meaning (the vocabulary's "one spelling for a copy", `.copy()` and `.clone()` rows).
2. **`sorted(...)` copies nothing** (`[STD-26]`, `[STD-16]`): AN-46's NEW (`for k in sorted(m.keys())`,
   "views of m's own keys, sorted: no copy"); `sorted(m)` is `sorted(m.keys())`.
3. **A non-`Send` component in `run_parallel`** is E7015, not E7004: E7004 now means a missing capture
   word only (section 4), E7015 is "a one-thread owner or a lent value reaches another thread".
4. **`@derive(Copy)` on a class** is E2080 (section 0: a class object is never `Copy`).
5. **`[SIMD-3]` carries R4's noalias point** for `ref mut` parameters and "`this` never", since it is the
   spec's one rule about alias facts and `[CG-LL-3]` and the C backend cite it.
6. **`format_to` says `from buf`** (R6): its result is a view of the text it wrote into `buf`.
7. **Maps and sets of views** follow R7 (bounded life, E3063) instead of "only `static` views".
8. Markers: new rules `*(new in 0.9.15)*`, changed ones `*(changed in 0.9.15)*`, as agent 07 did.
9. **Kept, and flagged:** `[ECS-4]`'s check of systems passed as values (their sets compared before any
   starts, a conflict panics). The design says nothing about it; R12 would let the compiler work out the
   sets of every function the program can put in such a list and refuse a possible conflict when
   compiling (E7020), which would refuse programs that run today. Left as today; raised for the owner.
