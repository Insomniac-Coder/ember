## 4. Technical points I settled

1. **Reserved or contextual.** Reserved (lexed as keywords): `owns`, `shares`, `sharedref`,
   `thread_shared`, `this`, `using`, `weakref` (52 keywords). Contextual: `copy` (only before `of`),
   `of` (only after `copy`; `Count.of` in `std/src/core.em` stays a method), `exists` (between a value
   and `as` in an `if`/`elif`/`while` header), `cast` (at the start of an operand before a name or
   `this`, as today's parser does, `ember_parser/src/body.rs:1047`), `guarded`/`by`, and `from` in its
   new places. `owned` and `self` stay reserved so no program can name anything with them; every use is
   E1010 with the word to write (V5 says `self` is refused "anywhere").
2. **`as?` and `as!`** are still lexed as single tokens, only so they get E1010 with the line to write.
3. **The named kind test** (`if s is Circle as c:`) is legal only in an `if` or `elif` header (R14
   names no other place); the `as` after the type there names and never converts; elsewhere E0100.
4. **The type-parameter line** comes after a declaration's attributes and before `pub`
   (`[T: Add[T, Output = T]]` above `pub fn total(...)`, as V5's E2040 message writes it). Brackets
   after the name are E0100 (the vocabulary gives no code). The parser looks at the next line's first
   tokens to tell it from a list expression: the one place it looks past a line's end.
5. **Capture words** follow the brackets and come before `->` (verdict 83's `fn() owns count -> int:`),
   the same order R5 gives a method's `owns this`.
6. **`using` binds tighter than the words before a value** (a new precedence level 18), so
   `owns Mesh(...) using current` makes the mesh in `current` and hands it over; in a type, `using`
   applies to the whole type before it.
7. **`static fn` in interface and `extend` bodies**: they are type bodies, so `Default.default` and
   `From.from` are `static fn` in the interface sketch.
8. **Non-`pub` bounds worked out from the body** (R14): a method called on a type parameter gives the
   interface in scope that declares it; two such interfaces are E2070 (today's ambiguity code), none is
   E2072.
9. **`ThreadShared` is never written but in a bound** (R15: "written only in bounds; `Send` is
   declared only by an `unsafe extend` author"), so `unsafe extend X implements ThreadShared:` is E2040;
   `T: Sync` is E1010 (section 4 lists "`Sync` as a property" under E1010).
10. **`.get()` on an `owns` value** is E2072 (the lookup fails on the `T` it reads as), with the
    vocabulary's message.
11. **E2228** (today's lambda parameter-mode mismatch) is not in V5's code table; V5 gives that case
    E2020 (verdict 71), which `[TYP-23]` now uses.
12. **`[HASH-3]`**: a `hash` or `eq` that may change the map it is called from is now caught when
    compiling, by the map operation's worked-out facts (E3031), instead of a `RefCell` panic.
13. **`once fn` as a lambda prefix** stays (today's grammar; V5 silent).
14. **The marker table** keeps today's facts that V5 does not touch (raw pointers and `extern fn` are
    `Copy`; `ref T` is `Send` when `T` is `ThreadShared`) and moves the rest to the new words; the
    details stay `[THR-8]`/`[THR-9]`'s.
