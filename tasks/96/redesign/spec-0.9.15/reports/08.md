## 4. Technical points settled, with reasons

1. **A value made `using` an instance migrates only in place** (same size and alignment), else plan
   refuses. Rebuilding it through its instance would run the user's `allocate` in prepare, which may
   panic (against `[HR-34]`) and changes the arena before commit (against `[HR-2]`); and the value's end
   hands `deallocate` the layout of its type, which must be the layout the block was given. The
   inventory allowed "rebuild by its instance, or refuse in the plan"; this is the refusal, narrowed
   to the case that needs it.
2. **An `Allocator` type's schema change is refused while values made in its instances live**: a
   field-wise or `migrate_from` rebuild of an arena would change its state other than through its own
   methods, which C14 forbids.
3. **A changed `@cached` body clears the kept results through migration** (a removed field and an added
   one with no value), not by stores in commit, since commit makes only pointer stores into memory
   prepare reserved (`[HR-2]`).
4. **Generator frames (U1)**: the frame's schema is its layout and its states; equal, live frames
   resume in the new code (and count for `[HR-44]` as frames that still call what the body calls);
   different, refused while a frame lives. A frame the runtime cannot enumerate counts as live (the
   safe reading).
5. **`[HR-35]`**: a cast and a count at its maximum, the language's new stopping checks, are added to the
   checks that return `Err` inside `migrate_from`, which may never stop the program.
6. **`[GPU-12]`**: what per-draw compares cannot see (index values, indirect arguments, shader reads)
   relies on robust buffer access; a backend without it is visible (`device.robust_access()`) and
   listed by `ember tcb` as an asserted fact; `unsafe: cmd.native()` records without the compares.
7. **No version markers added**: the brief asks for no history in rule text. Existing `*(changed in
   ...)*` markers are left as they were. `check_ids.py` therefore reports my five new IDs as
   NEW-UNMARKED (its pattern accepts only 0.9.9 and 0.9.10 markers); the other writers' new IDs show
   the same.
8. **`Cell` is not named in the glossary**: by R5 a plain name changes nothing (a `Cell` field
   included); only `Atomic`, `Mutex`, `RwLock`, channel ends and `guarded by` fields change through a
   name that only reads, so "interior mutability" is defined by them.
