## Needs the lead's eye

1. **The brief is out of date for M0.** The tree has M0's A5-1 (and its reversal to _4), A5-2, A6-12, A6-16 (twice: `with (header_hash)`, then `ember.overlays`), plus A3-1/A7-1..3/A7-17/A7-18. The gap map's A5-1 ("an `unsafe fn` body is not an unsafe context") is now the opposite of both the spec and the tree. MILESTONES M0 description and the gap's A5-1 text, tests and "Depends on" need rewriting; I did not edit them.
2. **Contradiction between the gap map and the spec on A5-1**: the gap says UNS-12 is "not built"; the compiler has it built to the _4 text. What was built in _4 versus what _5 to _12 added (E2020 for an `unsafe fn` `drop`/override/interface implementation; UNS-1's foreign-code pointer rules) I could not separate from the diffs, which start at _1. Someone should diff _4 to _12 for UNS-1, UNS-7, UNS-12, FFI-8 and FFI-55 (rows marked "built to _4" or "maybe").
3. **Items that no longer fit their size/milestone:** A6-2 (S, M12) now needs a header classifier, GCC shim-assembly reading, `unsafe_libs` with per-system tables and object-file default-library scans, and the unused-library check (FFI-51 + BLD-FFI-3); A5-8 (M4) needs the class-promise machinery (THR-8/THR-9) that belongs with M11; A6-20 (M13) now carries HR-2/HR-2a/HR-3b/HR-44 changes to the existing in-place migration.
4. **Rules the diffs cite that have no gap row or are not in my files:** FFI-57 (several declarations of one C++ name), HR-44a, HR-45 (exists), HR-48 (lambda captures), HR-15c, HR-24, FFI-17f, FFI-35a (exists in part: E5051), FFI-17f, EFF-26, BLD-16, MNG-6 instances, `[RC-4]` home/away counts. These are new work of areas 03/04/07/09 or of the new spec; they affect rows above (THR-2, THR-11, HR-14, HR-41, HR-12).
5. **Unsure / low confidence:** UNS-1 (which of its new clauses the built E3100 code covers); THR-5 (does a scope's opening thread ever run a task itself? I only found the `@parallel` helper loop at `ember_rt.c.in:2284`); FFI-2a, FFI-10 (the empty-span sentinel's location); FFI-11 (whether bare `owned` is still accepted); FFI-30c and HR-3b (not traced); FFI-21 (the `once` token and `E5041` for `once`).
6. **Possible tension between rules:** THR-9 says a `thread_shared Circle(...)` of a class with `@cached` is E7015 (verdict 165) while THR-1 says a `thread_shared` value's type must be `Send` and `ThreadShared`, and THR-8 says `thread_shared T` of an `open`/`abstract` `T` is Send/ThreadShared "whatever its class promises"; the three read consistently only if "made by a line that checks the object's own class" (THR-1) is the whole check — worth confirming with the owner that an `open` class's own `@cached` is judged at the making line, not by the promise. 7. **Kinds:** no rule in these two files is `new` relative to _1; I counted added sentences inside old rules as `meaning`. UNS-4 is `meaning` only as an obligation on unsafe-code authors (nothing to build). The `owns`-at-call example edits (CORO-14, THR-3, THR-17, FFI-22, FFI-39c) are `wording` because the general rule (`[FN-2a]`, E3028) is built and already demands the word.
