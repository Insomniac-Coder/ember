## Needs the lead's eye

1. **BLD-16 against decisions S-1 and S-3 of MILESTONES.md.** BLD-16 forbids a package's layout from depending on which types are made `thread_shared` or which classes a `weakref` names, and says a layout fact is decided by the declaring package and recorded with the type. S-1 (twin type index told by thread-shared use) and S-3 (the 12-byte header is "a whole-program fact", interface records carry it, a change rebuilds modules) read as exactly what BLD-16 refuses. Also TYP-44a's per-process type index. A3-4 and the M6b layout change need a new decision. Confidence: medium (I did not read the gap file text of A3-4 in full).
2. **TYP-45a / GRM-3a against the compiler's `Box`.** The compiler still handles `Box` (`borrows.rs:4032`, `coroutines.rs:659`); TYP-45a makes naming it `E1010`. Unsure whether M1's gone-names (A7-15) already refuse it; not checked.
3. **LT-48 is partly in `borrows.rs`** (verdict 151, after the map) though the brief says nothing of it is built. I did not verify how much runs (parser token, table fact, run-time test). Same for MAN-9 and BLD-15, which are built (verdicts 127, 124).
4. **GRM-29 and A8-2.** `(e,)` is now `E0100`; A8-2's one-element tuple `registry.view[(A,)]` is dead, replaced by TYP-47's packs. Existing parser, `std/src/ecs.em` and tests may use `(A,)`; not checked in tests.
5. **Rows marked `unsure`/low confidence**: PHIL-13 (is there a `debug_assert` form at all?), TYP-45a, CTL-10, DSP-2, UNS-5 (no `copy`/`copy_nonoverlapping` found in `std/`), FFI-20a, LEX-16, LEX-18, ERR-10 (`with_context` not found in `std/`).
6. **PAR-2b / SIMD-5**: the analysis is keyed on "placed in the inline header" (C backend); the new text keys on criteria, so the LLVM backend (now default) and reload builds must be read through too. Check that M5/M9 pick this up.
7. **FFI-2's limit on raw pointers** will turn existing `safe fn` declarations and overlays in `std/` and tests into `E5002`; list them before M12.
