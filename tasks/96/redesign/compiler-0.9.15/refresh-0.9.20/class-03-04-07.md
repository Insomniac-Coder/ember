# Classification of the 0.9.15_Hardened_1 to 0.9.20_Hardened_12 changes: areas 03, 04, 07

Method: each diff read with the rule's new text; work items from the gap files' "Completes/Rules" lines and
`MILESTONES.md`; "affects built code" checked with Grep in `compiler/` and `std/` (file:line given). `new` = a rule with no
earlier id: none of the 115 rows of these three diff files is one (the new ids TYP-45a, TYP-46a, TYP-44a, MOD-9a are in
`diffs-xx.md`). Milestone letters: M-numbers of MILESTONES.md. "RC-4 item" below = the new work named in row RC-4.

Two facts about the tree found while checking (they differ from the brief and matter for "affects built"):
- M1 as built already follows the grammar of about Hardened_5..10, not Hardened_1: `needs` bounds (`ember_parser/src/decls.rs:1855`), `[GRM-40]`'s one message for a stray `[...]` line (`ember_parser/src/lib.rs:833`, tests `ember_parser/tests/parsing.rs:848-889`), `safe:`, `threads`, `module`, `pub(package)`, `E0005` for any keyword used as a name (`ember_parser/src/lib.rs:394`), `owns fn` refused with E0109 (verdict 158, `ember_typeck/src/lib.rs:47014`), E3028 (`:58309`), per-place function targets of verdicts 122/128/129 (`ember_analysis/src/targets.rs:1-20`), `with (header_hash)` gone from overlays (`decls.rs:679`).
- `E2113`, `E2119`, `E2122`, `E7017` are in the code registry (`ember_diag/src/codes.rs:246,252,255,439`) but E2113 is emitted nowhere.
