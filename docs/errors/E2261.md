# E2261 — the returns of a `some` function have different types

```ember,fails
fn pick(big: bool) -> some Display:
    if big:
        return 100
    return "small"

fn main():
    println(pick(true))
```

```text
error[E2261]: this returns `str`, but an earlier `return` gave `i64`
```

## Why

`some I` in a return type stands for one concrete type, chosen by the function's body: the compiler
knows it and compiles every caller for it, with no indirection. Each `return` must therefore produce
that same type. An `int` and a `str` both implement `Display`, but they are two types, and a caller
compiled for one cannot be handed the other.

## The fix

Return one type on every path, here text on both:

```ember,fixed
fn pick(big: bool) -> some Display:
    if big:
        return "a hundred"
    return "small"

fn main():
    println(pick(true))
```

Or, when the paths really produce different types, return a `Box[dyn I]`, which holds any type
implementing `I` and calls it through a table.
