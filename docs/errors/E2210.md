# E2210 — a value of one range type where another was expected

```ember,fails
type Roughness = f32 in 0.0 ..= 1.0
type Metallic  = f32 in 0.0 ..= 1.0

fn main():
    r: Roughness = 0.5
    m: Metallic  = r
    print(1)
```

```text
error[E2210]: `Roughness` is not `Metallic`
 --> page.em:6:20
  |
6 |     m: Metallic  = r
  |                    ^ this is `Roughness`
  |
  = note: both are `f32` underneath, and telling them apart is what a range type is for [RNG-2]
```

## Why

Both of these are a number between zero and one, and a renderer has a dozen of
them: roughness, metallic, occlusion, opacity, a blend factor. They have the
same representation, the same range, and no relationship whatever — passing one
where another is wanted is a bug that no amount of care catches, because there
is nothing on the page to notice. A `f32` parameter accepts all of them
silently.

A range type is nominal for exactly this reason. `[RNG-2]` makes two of them
distinct types "even when representation and range are identical", which is the
whole feature: it is not the range that catches this, it is the name.

The cost is nothing. `[COST-3]` classes a range type as *not observable* — it
erases to its representation, and the emitted code is the same code.

## The fix

Say which one you meant. A range type erases to its representation at any
coercion site (`[TYP-5]`), so going *out* of one is free and implicit; coming
back *in* is a construction, and `[RNG-3]` decides which form.

```ember,fixed
type Roughness = f32 in 0.0 ..= 1.0
type Metallic  = f32 in 0.0 ..= 1.0

fn main():
    r: Roughness = 0.5
    # `r` erases to `f32`, and `Metallic.clamped` takes it back in.
    m: Metallic = Metallic.clamped(r)
    v: f32 = m
    print(v)
```
