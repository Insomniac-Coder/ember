# E5040 — a capturing lambda where C expects a function pointer

```ember,fails
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(param(handler, callback(borrowed)))
    safe fn call_plain(handler: extern "C" fn(i32) -> i32) -> i32

fn main():
    k: i32 = 5
    println(call_plain(fn(x: i32) -> i32 => x + k))
```

```text
error[E5040]: expected `extern "C" fn(i32) -> i32`, found a lambda that captures
```

## Why

A C function pointer is an address and nothing else: C calls it with the arguments its type names,
and there is no place in the call for the values a lambda captured. A lambda that captures `k` needs
`k` beside it on every call; given to C as a bare function pointer, it would have to find `k` in a
global, which two registrations at once would share. When the C function takes user data beside the
pointer — a `void*` it passes back to the callback — the contract `callback(…, user_data=p)` says
so, and the compiler passes the lambda's captures through it; without one, only a function or a
lambda that captures nothing fits.

## The fix

Declare the user data the C function passes back, or capture nothing:

```ember,fixed
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(param(handler, callback(borrowed)))
    safe fn call_plain(handler: extern "C" fn(i32) -> i32) -> i32

fn main():
    println(call_plain(fn(x: i32) -> i32 => x + 5))
```
