# E4030 — a `@static_safe` function keeps a dynamic aliasing check

```ember,fails
class Bag:
    items: Array[int]

    fn add(mut self, x: int):
        self.items.push(x)

@static_safe
fn fill(mut b: Bag, mut other: Bag):
    for i in 0..3:
        b.add(i)
        other.add(i)

fn main():
    b = Bag([])
    c = b
    fill(b, c)
    for x in c.items:
        println(x)
```

```text
error[E4030]: `@static_safe` function `fill` keeps an exclusivity check on a class object here
```

## Why

`@static_safe` promises that nothing in the function checks at run time
whether another part of the program holds the same data. Bounds, arithmetic
and stale-handle checks are allowed; aliasing checks are not, because a
data-oriented inner loop can always be arranged so that none is needed. A
`mut self` call through a class handle checks that no one else is using the
object, unless the compiler proves it (`[EXC-3]`); here `b` and `other` may be
the same object, and elsewhere the program iterates a `Bag`'s items, so the
check stays. A `RefCell` borrow is such a check too.

## The fix

Use value types, which have no run-time aliasing checks:

```ember,fixed
struct Bag:
    items: Array[int]

@static_safe
fn fill(mut b: Bag):
    for i in 0..3:
        b.items.push(i)

fn main():
    b = Bag([])
    fill(b)
    for x in b.items:
        println(x)
```

Or keep the class and pass one handle the function does not reassign, so the
compiler can prove the accesses; or take the data through a query yielding
`ref mut`.
