# E5059 — a trampoline's C++ base has no virtual destructor

```cpp,file=shape.hpp
#pragma once

class Shape {
public:
    Shape() noexcept {}
    virtual int sides() const noexcept { return 0; }
};
```

```cpp,file=shape_fixed.hpp
#pragma once

class Shape {
public:
    Shape() noexcept {}
    virtual ~Shape() {}
    virtual int sides() const noexcept { return 0; }
};
```

```ember,file=shape_overlay.em
unsafe overlay cpp "shape.hpp":  # SAFETY(ffi): each entry matches its declaration in the header

    type Shape
```


## Why

The C++ object an Ember object owns is of the trampoline subclass, and C++ code holds it as a pointer
to the base. Deleting it through that pointer — which C++ does whenever it owns the object
(`owner="foreign"`) — runs the destructor the base declares; without a virtual one, the subclass's
destructor never runs, the Ember part is never destroyed, and the deletion is undefined behaviour in
C++ itself. A base with a virtual destructor sends every deletion to the trampoline, which ends the
Ember object first.

## The fix

Give the C++ class a virtual destructor (or put such a base between it and Ember):

```ember,fixed
import cpp "shape_fixed.hpp" with (overlay = "shape_fixed_overlay.em")

class Square(cpp.Shape):
    override fn sides(self) -> i32:
        return 4

fn main():
    println(Square().sides())
```
