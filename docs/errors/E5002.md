# E5002 — a foreign call needs `unsafe` or a complete safe contract

```ember,fails
unsafe extern "C":
    fn abs(x: i32) -> i32

fn main():
    print(abs(-42))
```

```text
error[E5002]: a foreign call without a complete safe contract requires `unsafe`
 --> page.em:5:11
  |
5 |     print(abs(-42))
  |           ^^^^^^^^
  |
  = help: wrap the call in `unsafe:` or declare a scalar-only `safe fn`
```

## Why

An `unsafe extern` block asserts that a foreign declaration has the written
ABI. It does not by itself assert that every call is safe. A function without
`safe fn` must be called inside `unsafe:` or an `unsafe fn`.

## The fix

For a scalar-only signature whose safety the declaring package can uphold,
`safe fn` makes that separate assertion:

```ember,fixed
unsafe extern "C":
    safe fn abs(x: i32) -> i32

fn main():
    print(abs(-42))
```

A pointer parameter or result still needs a complete `@ffi` contract before
`safe fn` can be accepted. The current compiler supports a borrowed single
place through `mut p: T` with `@ffi(param(p, borrowed, one, exclusive))`, or a
shared `ref T` with `@ffi(param(p, borrowed, one))`; `nullable` maps those
references to `Option`. A borrowed `count(n)` maps `Span[T]` or exclusive
`MutSpan[T]` to a C pointer. In a hand declaration, write integer `n` at its
C parameter position; the compiler hides it from safe callers and supplies
the span length. Other contract shapes remain explicit implementation gaps;
keep those declarations unsafe and isolate their calls in a checked wrapper.
