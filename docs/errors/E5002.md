# E5002 — a foreign call needs `unsafe` or a complete safe contract

```ember,fails
unsafe extern "C":
    fn abs(x: i32) -> i32

fn main():
    print(abs(-42))
```

```text
error[E5002]: a foreign call without a complete safe contract requires `unsafe`
 --> page.em:5:11
  |
5 |     print(abs(-42))
  |           ^^^^^^^^
  |
  = help: state the facts on its declaration: `safe fn abs`
  = help: or wrap the call in `unsafe:`, as its caller's own assertion
  = note: unknown: `abs` is not asserted safe to call (`safe fn`)
```

## Why

An `unsafe extern` block asserts that a foreign declaration has the written
ABI. It does not by itself assert that every call is safe: a scalar can be an
address (`void free_addr(uintptr_t)`), so whether a call can break memory safety
is a fact only a person can state. Until every fact of the contract is stated —
that the function is safe to call, and for each pointer its ownership, count,
nullability and, for a result, its lifetime — a call must be inside `unsafe:` or
an `unsafe fn` (`[FFI-2]`). The error names each fact still unknown and prints
the declaration line that states them (`[DIA-18]`), each unknown one a
`TODO(…)` word to replace (`[FFI-11c]`).

## The fix

For a scalar-only signature whose safety the declaring package can uphold,
`safe fn` makes that separate assertion:

```ember,fixed
unsafe extern "C":
    safe fn abs(x: i32) -> i32

fn main():
    print(abs(-42))
```

A pointer parameter or result needs a complete `@ffi` contract before
`safe fn` is accepted, and the declaration then writes the safe type its words
give: `ref T` for `borrowed, one`, `mut p: T` with `exclusive`, `Span[T]` or
`MutSpan[T]` for `count(n)` (the integer `n` written at its C position, hidden
from safe callers), `cstr` for `nul_terminated`, and `Option[…]` with
`nullable`. A raw `*T` is never safe to expose.
