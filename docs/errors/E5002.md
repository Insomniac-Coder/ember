# E5002 — a foreign declaration whose contract cannot stand

```ember,fails
unsafe extern "C":  # SAFETY(ffi): strlen is declared as C's string.h declares it
    safe fn strlen(s: *u8) -> usize

fn main():
    pass
```

```text
error[E5002]: `safe fn` needs an `@ffi` contract for pointer parameter `s`
 --> page.em:2:20
  |
2 |     safe fn strlen(s: *u8) -> usize
  |                    ^^^^^^
```

The same code is given to two destructors declared for one foreign type. A call of a foreign function
whose contract is not verified, outside `unsafe`, is `E3100`, as any unsafe step is (`[UNS-1]`).

## Why

An `unsafe extern` block asserts that a foreign declaration has the written ABI. It does not by itself
assert that every call is safe: a scalar can be an address (`void free_addr(uintptr_t)`), so whether a
call can break memory safety is a fact only a person can state. `safe fn` states it, and lets safe code
call the function with no `unsafe` around it. That promise can only be kept when every fact the call
depends on is written down: for each pointer its ownership, count, nullability and, for a result, its
lifetime (`[FFI-2]`, `[FFI-11]`). A `safe fn` with a raw `*T` and no contract promises safety the
compiler can neither check nor generate code for, so it is refused here, at the declaration, rather
than at every call.

## The fix

Write the contract, and the safe type its words give: `ref T` for `borrowed, one`, `mut p: T` with
`exclusive`, `Span[T]` or `MutSpan[T]` for `count(n)`, `cstr` for `nul_terminated`, and `Option[…]` with
`nullable`:

```ember,fixed
unsafe extern "C":  # SAFETY(ffi): strlen is declared as C's string.h declares it
    @ffi(param(s, borrowed, nul_terminated))
    safe fn strlen(s: cstr) -> usize

fn main():
    println(strlen(c"four"))
```

Or keep the declaration without `safe fn`, and call it inside `unsafe:` with a `# SAFETY:` note saying
why the call is as C requires. A raw `*T` is never safe to expose.
