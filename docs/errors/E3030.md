# E3030 — a once-only closure is required to be reusable

```ember,fails
fn consume(owned values: Array[i32]) -> i32:
    return values[0]

fn twice(f: fn() -> i32) -> i32:
    return f() + f()

fn main():
    values: Array[i32] = Array[i32]()
    values.push(7)
    task = owned fn() => consume(values)
    println(twice(task))
```

```text
error[E3030]: closure would move a captured value out
  --> page.em:11:19
   |
11 |     println(twice(task))
   |                   ^^^^ this closure is callable only once
   |
   = help: declare the parameter `owned f: fn(...) -> ...` so it accepts `CallableOnce`, or use `mem.take` when the capture implements `Default`; clone only as a last resort
   = note: the closure moves a non-`Copy` capture out of its environment [CLO-2]
```

## Why

The closure owns `values`, and calling its body gives that Array to `consume`.
After one call there is no Array left in its environment, so passing it to a
parameter that promises a reusable `Callable` would make a second safe call
observe a moved value. The distinction is about the closure body's ownership
behavior, not merely whether the closure captured by move: an `owned fn` that
only reads its captures may still be called repeatedly.

## The fix

If the caller intends to consume the callable, declare the parameter `owned`
so it is bounded by `CallableOnce`:

```ember,fixed
fn consume(owned values: Array[i32]) -> i32:
    return values[0]

fn invoke(owned f: fn() -> i32) -> i32:
    return f()

fn main():
    values: Array[i32] = Array[i32]()
    values.push(7)
    task = owned fn() => consume(values)
    println(invoke(task))
```

When a closure needs to remain reusable, do not move its non-`Copy` capture
out of the body. A type with `Default` may instead keep the value in an
explicit `Option[T]` and use `mem.take`; cloning is appropriate only when the
extra copy is actually intended.
