# W3012 — `unsafe` with no safety note

```ember,fails
unsafe extern "C":  # SAFETY(ffi): abs is declared as C's stdlib.h declares it
    unsafe fn abs(x: i32) -> i32

fn main():
    unsafe:
        println(abs(-4))
```

```text
warning[W3012]: this `unsafe` has no safety note
```

The same holds for an `unsafe` implementation: `unsafe extern`, `unsafe extend` and `unsafe overlay`.

## Why

An `unsafe:` block or an `unsafe` implementation is where the compiler stops checking and the
programmer takes over an obligation: that a foreign function is called as C declares it, that memory
is initialised before it is read, that no other reference reaches what a raw pointer writes. `[UNS-8]`
asks that the reason the obligation holds be written where it is taken, so a reviewer can check it and
a tool can list it. A block with no note leaves the reader to rebuild the argument, and leaves nothing
to check when the code around it changes. (An `unsafe fn` is the other position: it says what its
callers must make true, with `@safety`, `[UNS-7]`.)

## The fix

Write the note on the line before, or at the end of the `unsafe:` line, with a category when one fits
(`ffi`, `layout`, `aliasing`, `intrinsic`, `performance`, `uninit`):

```ember,fixed
unsafe extern "C":  # SAFETY(ffi): abs is declared as C's stdlib.h declares it
    unsafe fn abs(x: i32) -> i32

fn main():
    unsafe:  # SAFETY(ffi): abs takes any i32 and touches no memory
        println(abs(-4))
```
