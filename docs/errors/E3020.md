# E3020 — iterable is mutated while the loop borrows it

```ember,fails
fn main():
    values: Array[i32] = Array[i32]()
    values.push(owns 1)
    for value in values.as_span().iter():
        values.push(owns 2)
        println(value)
```

```text
error[E3020]: `values.push(owns 2)` (line 5) adds to `values`, which this loop walks (line 4); collect what it adds in a list of your own: write `added: Array[i32] = []` before the loop, `added.push(owns 2)` in place of line 5, and `values.extend(owns added)` after the loop
```

## Why

While a `for` loop walks a collection, nothing changes it but the loop's own
handle on the item it is on (`[CTL-2]`, `[BRW-18]`): adding, removing or
writing items through the collection's own name, or through a call that may
change it, could leave the walk on items that moved or ended. The message
names the line that changes it, the loop's line, and the lines to write.

## The fix

The message gives the lines for the change it found: a push collects in a
list of your own, extended after the loop; an element or a map's value is
changed through the loop's own handle (`for ref mut x in values:`, then `x =
5` for `values[0] = 5`); anything else moves below the loop.

```ember,fixed
fn main():
    values: Array[i32] = Array[i32]()
    values.push(owns 1)
    added: Array[i32] = []
    for value in values.as_span().iter():
        added.push(owns 2)
        println(value)
    values.extend(owns added)
```

A counting loop, `for i in 0..values.len():`, reads the length once and
walks nothing: it may write elements and add at the end, but a call that
shortens the list is `E3020` too ("walk backwards, or collect the indices and
remove after the loop").
