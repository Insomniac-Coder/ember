# E2010 — a literal that does not fit its type

```ember,fails
fn main():
    x: u8 = 300
    println(x)
```

```text
error[E2010]: the literal `300` does not fit in `u8`
```

## Why

An integer literal without a suffix takes the type its context expects, and a value that does not fit that type is rejected (`[LEX-16]`) instead of being cut to its low bits: a program that writes `300` for a `u8` has made a mistake, and a number that quietly became `44` would hide it. A literal with a suffix has the suffix's type and is checked the same way; a minus directly before a literal forms the negative constant of that type, so `-128i8` fits and `128i8` does not.

## The fix

Give the number a type that holds it, or write the number the type holds:

```ember,fixed
fn main():
    x: u16 = 300
    println(x)
```
