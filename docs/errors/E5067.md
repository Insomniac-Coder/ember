# E5067 — an overlay that states facts is not declared `unsafe overlay`

```ember,fails
overlay c "string.h":
    fn strlen(s: borrowed nul_terminated)

fn main():
    pass
```

```text
error[E5067]: an overlay that states facts about foreign code is not declared `unsafe overlay`
 --> page.em:1:1
  |
1 | overlay c "string.h":
  | ^^^^^^^^^^^^^^^^^^^^^
2 |     fn strlen(s: borrowed nul_terminated)
  |        ------ the entry for `strlen`, which asserts it safe to call states a fact
  |
  = help: write `unsafe overlay`: the overlay asserts what the header cannot say
```

## Why

A header says what C's types are; it cannot say who owns a pointer, how many
elements it points at, whether it may be null, or whether a call can break
memory safety at all. An overlay says those things, and the compiler then lets
safe code call the function on the strength of them. Nothing checks that the
words are true: they are an assertion, made by a person, that safe code rests
on. `[TIER-1]` allows exactly three places where such an assertion enters a
program — an `unsafe:` block or `unsafe fn`, an `unsafe extern` declaration,
and an `unsafe overlay` — so that a reviewer can find every one by looking for
`unsafe`. An overlay that only renames or hides declarations asserts nothing
and needs no `unsafe`.

## The fix

Declare the overlay `unsafe overlay`, and keep its facts true:

```ember,fixed
unsafe overlay c "string.h":  # SAFETY(ffi): each entry matches its declaration in the header
    fn strlen(s: borrowed nul_terminated)

fn main():
    pass
```
