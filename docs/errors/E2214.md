# E2214 — arithmetic between two distinct range types

```ember,fails
type Roughness = f32 in 0.0 ..= 1.0
type Metallic = f32 in 0.0 ..= 1.0

fn main():
    r: Roughness = 0.5
    m: Metallic = 0.5
    bad = r + m
    println(bad)
```

```text
error[E2214]: `+` is not defined between `Roughness` and `Metallic`
 --> page.em:7:11
  |
7 |     bad = r + m
  |           ^^^^^ these are two different range types
  |
  = help: convert one side to `f32` at a place of that type first, as `x: f32 = a` does [RNG-2]
  = note: arithmetic on a range type yields its representation, and two distinct range types share no operator [RNG-5]
```

## Why

Two range types are distinct even when their representation and range are equal (`[RNG-2]`), so arithmetic between
them has no meaning: which one would the result belong to? Arithmetic on a range value yields its representation
(`[RNG-5]`), and the compiler wants the author to say which values are being combined.

## The fix

Convert one side to the representation at a place of that type first:

```ember,fixed
type Roughness = f32 in 0.0 ..= 1.0
type Metallic = f32 in 0.0 ..= 1.0

fn main():
    r: Roughness = 0.5
    m: Metallic = 0.5
    plain: f32 = m
    bad = r + plain
    println(bad)
```
