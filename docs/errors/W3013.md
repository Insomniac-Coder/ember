# W3013 — a `# SAFETY:` note on an `unsafe fn`

```ember,fails
@safety("p points to a readable byte")
# SAFETY: the caller guarantees a readable byte at `p`
unsafe fn read_first(p: *u8) -> u8:
    # SAFETY: the caller promised a readable byte at `p` (`@safety` above)
    unsafe:
        return p.read()

fn main():
    pass
```

```text
warning[W3013]: `read_first` says what its callers must make true with `@safety`; a `# SAFETY:` note says why one block is sound and goes above each `unsafe:` block inside it: remove this line
```

At the end of the `unsafe fn` line the same note is `W3013` too ("remove this note"); on a function
with no `@safety`, the warning asks for its reason to go there.

## Why

`unsafe` means one thing by its position (`[UNS-11]`). Before a declaration it says that whoever uses
it must vouch, and `@safety` says for what. Before a block it says that this code vouches, and a
`# SAFETY:` note says why. A note on an `unsafe fn` line mixes the two: it reads as a reason the
function is sound, yet nothing in the body is vouched for by it, since the body's own unsafe steps
each sit in a block of their own (`[UNS-12]`). Kept, it says the same thing as `@safety` in a place
no tool reads as the callers' condition.

## The fix

Say the callers' condition once, with `@safety`, and keep the reasons on the blocks:

```ember,fixed
@safety("p points to a readable byte")
unsafe fn read_first(p: *u8) -> u8:
    # SAFETY: the caller promised a readable byte at `p` (`@safety` above)
    unsafe:
        return p.read()

fn main():
    pass
```
