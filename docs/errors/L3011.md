# L3011 — `RefCell` guard held across a call

```ember,fails
fn log_it(n: i32):
    println(n)

fn main():
    c: RefCell[i32] = RefCell(1)
    with g = c.borrow():
        log_it(g)
```

```text
warning[L3011]: `RefCell` guard held across a call
  --> page.em:8:9
   |
 8 |         log_it(g)
   |         ^^^^^^^^^ live across this call
   |
   = help: read the value out of the guard and end the borrow before the call
   = note: a guard live across a call that could re-enter the same cell turns a
           compile-time question into a runtime panic [CELL-7]
```

This is a **lint, not an error**: the program compiles and runs. `[CELL-7]` says
the lint *fires* — it is not opt-in, and it does not need `[MAN-3]`'s `[lints]`
configuration the way `[LT-1b]`'s `L3014` does.

## Why

`RefCell` moves `[BRW-1]`'s question from compile time to run time. That trade
is worth making only where the answer is obvious locally, and a guard that is
still live across a call stops being locally obvious: the callee may reach the
same cell, and `[CELL-5]` will then panic rather than refuse at compile time.

The danger is not the call itself — it is that the panic appears in whichever
caller happens to be holding a guard when some distant callee borrows. The lint
fires at the place where the lifetime can actually be shortened, which is the
only place a person can fix it.

`[CELL-10]` is the same instinct in the other direction: a borrow-error
diagnostic may suggest `RefCell` **only** when the conflicting accesses are
provably not simultaneous, and never as a first suggestion. Runtime borrow
checking is a considered choice, not an escape from the compile-time one.

## The fix

End the borrow before the call. Read what the callee needs out of the guard and
let the guard drop, so nothing is live across the call boundary:

```ember,fixed
fn log_it(n: i32):
    println(n)

fn main():
    c: RefCell[i32] = RefCell(1)
    n = 0
    with g = c.borrow():
        n = g
    log_it(n)
```

Where the value cannot be copied out, narrow the `with` block so it ends before
the call rather than enclosing it. A guard whose scope is the smallest thing
that needs it never trips this lint, and never panics.
