# E9041 — the C compiler cannot honour a floating-point attribute

The failing example is valid Ember that only a C compiler without the flag rejects, so it is marked
`ember,fails,toolchain`: it must check clean, and its build fails with `E9041` only on such a compiler.

```ember,fails,toolchain
@fp(contract)
fn dot(a: f64, b: f64, c: f64, d: f64) -> f64:
    return a * b + c * d

fn main():
    println(dot(1.0, 2.0, 3.0, 4.0))
```

```text
error[E9041]: `cl` cannot compile a function with `@fp(contract)` as written: it does not take `/fp:contract`
```

## Why

`@fastmath` and `@fp(contract)` relax floating point for one function: Ember builds that
function in a unit of its own, compiled with the flag that allows the relaxation
(`/fp:contract` or `/fp:fast` for MSVC, `-ffp-contract=fast` and the fast-math flags for
clang and gcc). A C compiler that does not know the flag ignores it (MSVC's `D9002`) or
refuses it, and the function would then be built with strict arithmetic, or not at all.
An attribute is never ignored, so the build stops and names the compiler and the flag.

## The fix

Build with a C compiler that takes the flag (MSVC from Visual Studio 2022 17.0, clang or
gcc), or remove the attribute, which keeps strict IEEE arithmetic:

```ember,fixed
fn dot(a: f64, b: f64, c: f64, d: f64) -> f64:
    return a * b + c * d

fn main():
    println(dot(1.0, 2.0, 3.0, 4.0))
```
