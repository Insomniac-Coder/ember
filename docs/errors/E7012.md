# E7012 — another thread reaches a module variable of the main thread

```ember,fails
import std.thread

static mut FRAME: int = 0

fn tick():
    FRAME += 1

fn main():
    h = thread.spawn(owns tick)
    h.join()
    println(FRAME)
```

```text
error[E7012]: `tick` changes `FRAME`, a module variable of the main thread, and this thread runs beside it; guard it with one lock: write `from std.sync import Lock` at the top, `static TICK_LOCK: Lock = Lock()`, then `static mut FRAME: int guarded by TICK_LOCK = 0` instead of line 3, and put `tick`'s body inside `with TICK_LOCK:`
```

## Why

A `static mut` that no lock guards belongs to the main thread: only it, and the
tasks and jobs of the scopes it opens, which end before their scope does, may
reach it. A thread started with `thread.spawn`, or a job submitted outside a
scope, runs beside the main thread for as long as it likes, so the two could
change the variable at the same moment, and what it then holds would depend on
how the processor happened to interleave them. The compiler works out from each
function's body, and from the functions it calls, every module variable a
thread's function may read or change, so nothing about it is checked while the
program runs.

## The fix

Give the thread what it needs and take its result back from `join`, so only
the main thread touches the variable:

```ember,fixed
import std.thread

static mut FRAME: int = 0

fn next_frame() -> int:
    return 1

fn main():
    h = thread.spawn(owns next_frame)
    FRAME += h.join()
    println(FRAME)
```

Where several threads must share the variable, guard it with one lock, as the
message says, and reach it only inside that lock's `with` block.
