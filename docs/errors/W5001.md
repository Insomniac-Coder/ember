# W5001 — a macro is not imported

```c,file=macros.h
#define TWICE(x) ((x) * 2)
```

```c,file=twice.h
static inline int twice(int x) { return x * 2; }
```

```ember,fails
import c "macros.h"

fn main():
    pass
```

```text
warning[W5001]: macro `TWICE` is not imported from `macros.h`: a function-like macro: Ember has no macros (a `static inline` C function in a header of your own can call it)
 --> page.em:1:1
  |
1 | import c "macros.h"
  | ^^^^^^^^^^^^^^^^^^^
  |
  = note: defined at macros.h:1 [FFI-6a]
```

## Why

A macro is text the C preprocessor pastes in; it has no type and no address. An object-like macro
whose expansion Clang evaluates to an integer, floating or string constant becomes an Ember
constant of that C type. Anything else — a function-like macro, one that expands to a type or to a
call — has no Ember counterpart, and inventing one would mean guessing its argument and result types.
So the importer says which macros it left out, with Clang's reason, rather than letting a name the
header declares go missing in silence.

## The fix

Call the macro from a C function, which has the types the macro does not, and import that:

```ember,fixed
import c "twice.h"

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        println(c.twice(21))
```
