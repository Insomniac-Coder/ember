# E3105 — `UnsafeCell` in `@static_safe` code

```ember,fails
from std.mem import UnsafeCell

@static_safe
fn read_value() -> i32:
    cell = UnsafeCell(41)
    return cell.into_inner()

fn main():
    println(read_value())
```

## Why

`@static_safe` requires the relevant safety property to be established
statically. `UnsafeCell` deliberately delegates its interior-mutability
invariant to audited unsafe implementation code, so the two contracts cannot
be combined.

This diagnostic does not recommend introducing `UnsafeCell`; it reports an
already-present use of the expert facility required by `[UNS-10b]`.

## The fix

Keep the `@static_safe` function entirely on the statically verified side of
the boundary. Put the `UnsafeCell`-based implementation in ordinary code that
does not claim this contract, or remove `@static_safe` when the contract is not
required.

```ember,fixed
@static_safe
fn read_value() -> i32:
    return 41

fn main():
    println(read_value())
```
