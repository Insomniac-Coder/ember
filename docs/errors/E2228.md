# E2228 — callable parameter mode mismatch

```ember,fails
fn apply(f: fn(mut i32) -> i32, mut value: i32) -> i32:
    return f(value)

fn main():
    value: i32 = 4
    println(apply(fn(x) => x, value))
```

## Why

Callable parameter modes are part of the canonical callable type. The omitted
mode is the ordinary shared-borrow mode; it is not interchangeable with
`mut`, even when the parameter types and return type are otherwise identical.
The callback above supplies `fn(i32) -> i32` where the call requires
`fn(mut i32) -> i32`.

This diagnostic also applies at a late-bound callback boundary such as
`std.borrow.with_views*_mut`. The late-bound region contract and the callable
parameter modes are checked independently; a late-bound callback does not turn
an omitted mode into an implicit mutable borrow.

## The fix

Declare the callback parameter with the required mode:

```ember,fixed
fn apply(f: fn(mut i32) -> i32, mut value: i32) -> i32:
    return f(value)

fn main():
    value: i32 = 4
    println(apply(fn(mut x) => x, value))
```

For a named callback, use a matching declaration such as
`fn increment(mut x: i32) -> i32`. Do not rely on `MutSpan[T]` or another
mutable-looking value type to imply the callable parameter mode.
