# E7020 — systems in one parallel run have conflicting access sets

```ember,fails
from std.ecs import World, Query, Mut, Component

@derive(Copy, Component)
struct Pos:
    x: int

fn movement(mut q: Query[Mut[Pos]]):
    for p in q.iter_mut():
        p.x += 1

fn report(mut q: Query[Pos]):
    for p in q.iter():
        println(p.x)

fn main():
    world = World()
    world.run_parallel([movement, report])
```

```text
error[E7020]: systems `movement` and `report` cannot run at once: `movement` writes `Pos`, which the other uses
```

## Why

Systems given to one `run_parallel` may run at the same time, each over its own query, and a
query holds the storages it names for the whole of its system. Two systems may share a
component only to read it: if one writes it while the other reads or writes it, one would see the
other's writes half done. Each query's reads and writes follow from its type (`Mut[T]` writes
`T`, a plain `T` reads it), so the compiler compares the systems written in the call before the
program runs; systems passed as an array value are compared when the call runs, and a conflict
panics before any of them starts.

## The fix

Run the two in turn, one `run_parallel` each, or give the parallel run only systems whose
writes no other system in it uses:

```ember,fixed
from std.ecs import World, Query, Mut, Component

@derive(Copy, Component)
struct Pos:
    x: int

fn movement(mut q: Query[Mut[Pos]]):
    for p in q.iter_mut():
        p.x += 1

fn report(mut q: Query[Pos]):
    for p in q.iter():
        println(p.x)

fn main():
    world = World()
    world.run_parallel([movement])
    world.run_parallel([report])
```
