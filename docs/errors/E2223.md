# E2223 — `@never_specialize` on a generic that is not shareable

```ember,fails
interface Scale:
    fn factor(self) -> f64

struct Unit:
    f: f64

extend Unit implements Scale:
    fn factor(self) -> f64:
        return self.f

@never_specialize
fn twice[T: Scale](x: T) -> f64:
    y: T = x
    return y.factor() * 2.0

fn main():
    println(twice(Unit(1.0)))
```

```text
error[E2223]: `twice` cannot share one body: `T` is named here
```

## Why

`@never_specialize` asks for one body that every instance shares, taking a table of the bound's
methods where each instance would have had the type itself. That body knows nothing of the type but
those methods: not its size, so it cannot copy or store a value of it, nor its fields, nor anything
another function needs to know of it. A generic that uses the type for more than calling its bounds'
methods on a parameter would compute something else when shared, so the attribute is refused rather
than quietly specialising.

## The fix

Use the parameter only as the receiver of its bounds' methods, or remove `@never_specialize`.

```ember,fixed
interface Scale:
    fn factor(self) -> f64

struct Unit:
    f: f64

extend Unit implements Scale:
    fn factor(self) -> f64:
        return self.f

@never_specialize
fn twice[T: Scale](x: T) -> f64:
    return x.factor() * 2.0

fn main():
    println(twice(Unit(1.0)))
```
