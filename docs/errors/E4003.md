# E4003 — a `@noblock` function reaches an operation that may wait

```ember,fails
@noblock
fn ask() -> String:
    return input()

fn main():
    println(ask())
```

```text
error[E4003]: `@noblock` function `ask` reaches an operation that may wait
  = note: ask -> `input`, which reads the console
```

## Why

A function that may wait — for input, a lock, another thread — can hold up whoever called it for
as long as the thing it waits for takes. `@noblock` promises that the function always makes
progress on its own, which a game loop or an event handler needs. Reading the console waits for
the user.

## The fix

```ember,fixed
fn ask() -> String:
    return input()

@noblock
fn greet(name: str) -> int:
    return name.len()

fn main():
    name = ask()
    println(greet(name.as_str()))
```

Do the waiting outside the `@noblock` function and pass the result in.
