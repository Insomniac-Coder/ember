# E2041 — overlapping implementations

```ember,fails
interface Named:
    fn name() -> int

[A, B]
struct Pair:
    a: A
    b: B

extend[T] Pair[T, int] implements Named:
    fn name() -> int:
        return 1

extend[U] Pair[String, U] implements Named:
    fn name() -> int:
        return 2

fn main():
    println("x")
```

```text
error[E2041]: `Pair[String, U]` and `Pair[T, i64]` can be one type, and both implement `Named`
  = note: two implementations of one interface may not apply to one type [TYP-19]
```

## Why

A call must reach one implementation. Where two could apply to the same type, here `Pair[String, int]`, the program would need a rule to choose, and Ember has no specialisation (`[TYP-19]`). Overlap is decided where the implementations are declared, whether or not any value meets both, so a later change elsewhere cannot make a working program ambiguous.

## The fix

Make the two apply to different types:

```ember,fixed
interface Named:
    fn name() -> int

[A, B]
struct Pair:
    a: A
    b: B

extend[T] Pair[T, int] implements Named:
    fn name() -> int:
        return 1

extend[U] Pair[String, Array[U]] implements Named:
    fn name() -> int:
        return 2

fn main():
    println("x")
```
