# E3022 — one place changed through two names

```ember,fails
fn update_both(ref mut left: i32, ref mut right: i32):
    left = 10
    right = 20

fn main():
    value: i32 = 0
    update_both(ref mut value, ref mut value)
    println(value)
```

```text
error[E3022]: `value` is already mutably borrowed
 --> page.em:7:5
  |
7 |     update_both(ref mut value, ref mut value)
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ conflicting access here
  |     ----------------------------------------- mutable borrow of `value` starts here
  |
  = help: use one mutable access rather than borrowing the same place twice; split the owner's mutable view with `split_at` when the intended operands are disjoint parts of it
  = note: a borrow lasts until its last use, not to the end of the scope (BRW-2)
```

## Why

Two arguments of one call, at least one of them changeable, may not name one place (`[BRW-11]`): the callee would
hold two names that both change `value`, and the order of its writes would decide the result. The conflict
exists at call entry, even though both parameter types are valid. It is refused when compiling (`[BRW-1]`).

## The fix

Give each parameter its own place:

```ember,fixed
fn update_both(ref mut left: i32, ref mut right: i32):
    left = 10
    right = 20

fn main():
    a: i32 = 0
    b: i32 = 0
    update_both(ref mut a, ref mut b)
    println(a)
    println(b)
```

## See also

* `[BRW-1]` — one name changes, or any number read.
* `[BRW-11]` — arguments do not overlap a changeable one.
