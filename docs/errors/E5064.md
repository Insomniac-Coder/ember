# E5064 — interior NUL in a value converted to `cstr`

```ember,fails
fn main():
    greeting = c"hi\0there"
```

```text
error[E5064]: a C string literal may not contain a NUL byte
```

A `String` converted with `.to_cstring()` whose text holds a NUL fails the same way at run time,
with an error rather than a diagnostic (`[FFI-15]`).

## Why

C reads a string up to its first NUL. A `cstr` with a NUL inside would be read by C as the part
before it, so the rest would be lost without a word: `[TXT-3]` keeps a `c"…"` literal to the text C
will see, and the compiler adds the terminating NUL itself.

## The fix

Leave the NUL out, or pass the text as two strings:

```ember,fixed
fn main():
    greeting = c"hi there"
```
