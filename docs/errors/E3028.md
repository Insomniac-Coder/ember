# E3028 — a call's word does not match its parameter

```ember,fails
fn take(owns xs: Array[int]):
    println(xs)

fn main():
    xs = [1, 2]
    take(xs)
```

```text
error[E3028]: `take` takes `xs` over (its first line says `owns xs: Array[int]`)
```

## Why

A call says, before each argument, what the callee does with it, in the words of the parameter:
`ref mut` before an argument the callee may change (`bump(ref mut a)` for `fn bump(ref mut c:
Counter)`), and `owns` before one it takes over (`take(owns xs)` for `fn take(owns xs:
Array[int])`). So the line of the call says what happens to `xs`, as the first line of `take` does,
and a reader of `main` sees that `xs` is gone after it. A missing word, or one written where the
parameter does not say it (`show(owns xs)` for `fn show(xs: Array[int])`, which only reads), is
`E3028`.

No word is written where the value is given as `=` gives it: after `return`, for a constructor's
argument (`Words(names=xs)`), and for a function from a variable lent to the standard library
(`xs.iter().for_each(h)`).

## The fix

Write the parameter's word at the call:

```ember,fixed
fn take(owns xs: Array[int]):
    println(xs)

fn main():
    xs = [1, 2]
    take(owns xs)
```

To keep your own list, give `take` a copy: `take(owns copy of xs)`. `owns` binds as `-` does, so
a value of more than one operand takes brackets: `m.insert(owns (i * 7), owns i)`.
