# E3042 — partial move followed by whole-value use

```ember,fails
struct Resource:
    value: i32

    fn drop(mut self):
        println(self.value)

struct Pair:
    first: Resource
    second: Resource

fn consume(owned pair: Pair):
    println(pair.second.value)

fn main():
    pair = Pair(Resource(1), Resource(2))
    first = pair.first
    consume(pair)
```

```text
error[E3042]: `pair` is partially moved
  --> page.em:19:13
   |
17 |     pair = Pair(Resource(1), Resource(2))
   |     -------------------------------------- `pair` is declared here
18 |     first = pair.first
19 |     consume(pair)
   |             ^^^^ used here as a whole after one of its fields was moved
   |
   = help: reassign the moved field, or destructure the whole struct up front
   = note: moving a field out leaves the rest of the struct live, but the struct cannot be used as a whole [EXP-6]
```

## Why

`first = pair.first` transfers only the `first` field. The disjoint
`pair.second` field remains live and may still be used, but `pair` no longer
denotes a fully initialised `Pair`, so it cannot be moved, borrowed, returned,
or otherwise used as one complete value.

This differs from `E3040`: an ordinary whole-value move leaves no field behind.
A partial move leaves the unmoved fields with their original owner, and those
fields are still destroyed normally.

## The fix

Reinitialise the field before using the aggregate again:

```ember,fixed
struct Resource:
    value: i32

    fn drop(mut self):
        println(self.value)

struct Pair:
    first: Resource
    second: Resource

fn consume(owned pair: Pair):
    println(pair.second.value)

fn main():
    pair = Pair(Resource(1), Resource(2))
    first = pair.first
    pair.first = Resource(3)
    consume(pair)
```

Or destructure the complete value up front when its fields are meant to travel
to separate owners.
