# E7008 — a thread-bound value sent to another thread

```ember,fails
import std.thread

unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(destroys(gadget_close), threads(creator))
    type Gadget
    @safety("`gadget` is a gadget C made, not closed yet")
    unsafe fn gadget_close(gadget: *mut Gadget)
    @ffi(result(returns_owned(destructor=gadget_close), one))
    safe fn gadget_new() -> owns Gadget

fn look(gadget: owns Gadget):
    pass

fn main():
    gadget = gadget_new()
    worker = thread.spawn(owns owned fn() => look(gadget))
    worker.join()
```

```text
error[E7008]: the thread's function captures `gadget`, an `owns Gadget`, which is not Send
  --> src/main.em:16:5
   |
16 |     worker = thread.spawn(owns owned fn() => look(gadget))
   |              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

## Why

An `owns T` of a foreign type whose contract says `threads(creator)` (or `threads(main)`) belongs to
the thread that made it: the library it comes from may use the object on that thread only, and its
end runs there. Such a value is not `Send`, so safe code never hands one to another thread
(`[THR-8]`, `[FFI-33b]`); a thread-bound value that is sent anyway is `E7008`, where any other value
that may not move to another thread is `E7004`. A guard, a `Scope` and a raw pointer are thread-bound
the same way.

## The fix

Make the object on the thread that uses it:

```ember,fixed
import std.thread

unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(destroys(gadget_close), threads(creator))
    type Gadget
    @safety("`gadget` is a gadget C made, not closed yet")
    unsafe fn gadget_close(gadget: *mut Gadget)
    @ffi(result(returns_owned(destructor=gadget_close), one))
    safe fn gadget_new() -> owns Gadget

fn look(gadget: owns Gadget):
    pass

fn main():
    worker = thread.spawn(owns owned fn() => look(gadget_new()))
    worker.join()
```
