# L3014 — return region is the intersection of parameters

```ember,fails
fn pick(a: Span[i32], b: Span[i32]) -> Span[i32]:
    return a
```

```text
warning[L3014]: return region is the intersection of 2 parameters
 = help: write `@borrows(a, b)` to make the intended return region explicit
```

This is an opt-in lint: enable it with `l3014 = "warn"` or `l3014 = "deny"`
in the package's `[lints]` manifest section. The program still compiles.

## Why

Returning a view tied to multiple inputs makes the caller's usable lifetime
the overlap of those inputs. That is easy to miss at a call site, where an
otherwise independent value can become unavailable while the result lives.
Naming the inputs makes the API contract visible to the implementation and to
every caller.

## The fix

Write the region relationship deliberately with `@borrows`. Naming every
view-typed parameter keeps the intersection while showing that it was chosen,
and naming fewer parameters describes a less restrictive return contract when
the implementation supports one.

```ember,fixed
@borrows(a, b)
fn pick(a: Span[i32], b: Span[i32]) -> Span[i32]:
    return a
```
