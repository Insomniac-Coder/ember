# E9033 — retired: a `release` build ignores `reload`

`E9033` is no longer emitted. It refused hot reload in the final build (then called `shipping`), so a
package that asked for reload in its manifest had to edit the manifest before every such build.

Since 0.9.10_Hardened_13 (ODR-117, ODR-118) the profiles are `debug`, `development` and `release`, and a
`release` build ignores `[build] reload` and `ember build --reload` with a note, building the ordinary
program:

```text
$ ember build --profile release main.em
note: hot reload is off in release builds [MAN-7]
```

## Why

A reloadable build reaches its functions through thunks, keeps a reload manifest in its image, links
a shared runtime and gives every object a larger header. The build users get pays none of that, so it
is never reloadable; the manifest's `reload` is for the profiles you develop in.

## See also

* `[MAN-7]` — a `release` build ignores `reload` and prints the note.
* `[PRF-2]` — hot reload is a build mode of `debug` and `development`.
