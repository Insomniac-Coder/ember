# W5002 — a declaration is not imported

```c,file=variadic.h
int log_line(const char* format, ...);
```

```c,file=fixed_log.h
#include <stdio.h>
static inline int log_number(int n) { return printf("%d\n", n); }
```

```ember,fails
import c "variadic.h"

fn main():
    pass
```

```text
warning[W5002]: `log_line` is not imported from `variadic.h`: variadic (`...`): Ember's variadic foreign calls are not built yet
 --> page.em:1:1
  |
1 | import c "variadic.h"
  | ^^^^^^^^^^^^^^^^^^^^^
  |
  = help: to use it, declare it by hand in an `unsafe extern "C":` block with types Ember has, or wrap it in a C function the header declares
  = note: declared at variadic.h:1 [FFI-20a]
```

## Why

Some C declarations have no Ember form yet — a variadic function, `long double`, a union's fields —
and some are not callable at all, such as a global with internal linkage. The importer leaves such a
declaration out rather than writing one that guesses (`[FFI-38]`), and says so at the import, naming
the construct and a way around it. A program that uses the name is told the same, never that the name
does not exist.

## The fix

Wrap the declaration in a C function with types Ember has, and import that:

```ember,fixed
import c "fixed_log.h"

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        c.log_number(7)
```
