# E5065 — `Shared`/`Weak` and `CppShared`/`CppWeak` do not interconvert

```ember,fails
from std.ffi import CppShared

fn give_to_cpp(pointer: CppShared[i32]):
    pass

fn main():
    shared: Shared[i32] = Shared(5)
    give_to_cpp(shared)
```

```text

 --> page.em:8:17
  |

  |                ----------------------- parameter `pointer` is declared `std.ffi.CppShared[i32]` here
...
8 |     give_to_cpp(shared)
  |                 ^^^^^^ this is `Shared[i32]`

  = help: keep each object on its own side: an Ember value in a `Shared`, a `std::shared_ptr` C++ made in a `CppShared`, and share the object itself through a reference or a C++ call
  = note: `Shared[i32]` is counted by Ember and `std.ffi.CppShared[i32]` by C++; a conversion would leave each count believing it owns the object, and both would free it [SEL-2]
```

## Why

A `Shared` is counted by Ember, in the header of the block Ember allocated; a `std::shared_ptr` is
counted by C++, in a control block C++ allocated. Turning one into the other would give the object
two counts, each believing it owns the object: when either reaches zero it frees the object, and the
other frees it again. So neither converts into the other, in either direction and in every position
(an argument, a return, an annotated local); a `Weak` of either is the same.

## The fix

Keep each object on its own side. A `std::shared_ptr` C++ made stays a `CppShared`, cloned through
C++'s count; an Ember value stays a `Shared`. Share the object itself through a reference or a call
into C++.

```ember,fixed
from std.ffi import CppShared

fn give_to_cpp(pointer: ref CppShared[i32]):
    pass

fn keep_in_ember(pointer: Shared[i32]) -> i32:
    return pointer.get()

fn main():
    shared: Shared[i32] = Shared(5)
    println(keep_in_ember(shared))
```
