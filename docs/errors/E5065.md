# E5065 — `shares`/`weakref` and `CppShared`/`CppWeak` do not interconvert

```ember,fails
from std.ffi import CppShared

fn give_to_cpp(pointer: CppShared[i32]):
    pass

fn main():
    shared: shares mut i32 = shares mut 5
    give_to_cpp(shared)
```

```text
error[E5065]: `shares mut i32` does not convert to `std.ffi.CppShared[i32]`: Ember's and C++'s reference counts are different counts
 --> page.em:8:17
  |

  |                ----------------------- parameter `pointer` is declared `std.ffi.CppShared[i32]` here
...
8 |     give_to_cpp(shared)
  |                 ^^^^^^ this is `shares mut i32`

  = help: keep each object on its own side: an Ember value held `shares`, a `std::shared_ptr` C++ made in a `CppShared`, and share the object itself through a reference or a C++ call
  = note: `shares mut i32` is counted by Ember and `std.ffi.CppShared[i32]` by C++; a conversion would leave each count believing it owns the object, and both would free it [SEL-2]
```

## Why

A `shares` value is counted by Ember, in the header of the block Ember allocated; a `std::shared_ptr` is
counted by C++, in a control block C++ allocated. Turning one into the other would give the object
two counts, each believing it owns the object: when either reaches zero it frees the object, and the
other frees it again. So neither converts into the other, in either direction and in every position
(an argument, a return, an annotated local); a `weakref` link and a `CppWeak` are the same.

## The fix

Keep each object on its own side. A `std::shared_ptr` C++ made stays a `CppShared`, cloned through
C++'s count; an Ember value stays held `shares`. Share the object itself through a reference or a
call into C++.

```ember,fixed
from std.ffi import CppShared

fn give_to_cpp(ref pointer: CppShared[i32]):
    pass

fn keep_in_ember(pointer: shares mut i32) -> i32:
    return pointer

fn main():
    shared: shares mut i32 = shares mut 5
    println(keep_in_ember(shared))
```
