# E2050 — interface is not `dyn`-compatible

```ember,fails
interface Factory:
    fn clone(self) -> Self

fn take(value: ref dyn Factory): #$ error[E2050]: interface `Factory` is not `dyn`-compatible
    pass
```

```text
error[E2050]: interface `Factory` is not `dyn`-compatible
```

## Why

`dyn I` requires an interface whose methods have a vtable-safe callable
contract. Every method must have a receiver, no method may be generic, and a
method may not return `Self` by value unless it is a default method explicitly
constrained with `where Self: Sized`. The example's `clone` method returns
`Self` by value, so there is no one vtable result type for `dyn Factory`.

The diagnostic identifies the offending method and compatibility condition.
It is reported when the `dyn` type is formed, including when the type is used
behind a reference.

## The fix

Use an object-safe result type, or keep the operation on a statically known
concrete type. A default method that is intentionally unavailable through the
dynamic interface may opt into the `Self`-sized exception:

```ember,fixed
interface Factory:
    fn clone(self) -> Self where Self: Sized:
        todo()

fn take(value: ref dyn Factory):
    pass
```
