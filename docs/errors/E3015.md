# E3015 — a `@must_drop` value would be leaked

```ember,fails
@must_drop
struct Guard:
    id: int

    fn drop():
        println(f"released {this.id}")

fn make() -> Guard:
    g = Guard(1)
    return g

fn main():
    _g = make()
```

```text
error[E3015]: `Guard` holds a `@must_drop` value, which may not be returned from the function that made it
```

## Why

A type is `@must_drop` when a safety guarantee depends on its `drop` running
at a known point: a scope that joins the threads it started, a guard that
restores what it changed. So the value's drop may not be skipped or put off
indefinitely: it may not be stored in a class field, a `Shared`,
`SyncShared` or an `owns` block, or a collection, captured by an `owned fn`, or returned
from the function that made it. A struct, enum or tuple holding one is
`@must_drop` too.

## The fix

Keep the value in a local, and let its scope end it:

```ember,fixed
@must_drop
struct Guard:
    id: int

    fn drop():
        println(f"released {this.id}")

fn main():
    g = Guard(1)
    println(g.id)
```
