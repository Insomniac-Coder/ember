# E3015 — a `@must_drop` value would be leaked

```ember,fails
import std.mem

@must_drop
struct Guard:
    id: int

    fn drop(mut self):
        println(f"released {self.id}")

fn main():
    g = Guard(1)
    mem.forget(g)
```

```text
error[E3015]: `Guard` holds a `@must_drop` value, which may not be forgotten
```

## Why

A type is `@must_drop` when a safety guarantee depends on its `drop` running
at a known point: a scope that joins the threads it started, a guard that
restores what it changed. So the value's drop may not be skipped or put off
indefinitely: it may not be forgotten, stored in a class field, a `Shared`,
`SyncShared` or `Box`, or a collection, captured by an `owned fn`, or returned
from the function that made it. A struct, enum or tuple holding one is
`@must_drop` too.

## The fix

Keep the value in a local, and let its scope end it:

```ember,fixed
@must_drop
struct Guard:
    id: int

    fn drop(mut self):
        println(f"released {self.id}")

fn main():
    g = Guard(1)
    println(g.id)
```
