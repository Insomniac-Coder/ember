# L4002 — dynamic dispatch on a final type

```ember,fails
interface Shape:
    fn area(self) -> f64

struct Square:
    side: f64

extend Square implements Shape:
    fn area(self) -> f64:
        return self.side * self.side

fn main():
    sq = Square(2.0)
    d: ref dyn Shape = ref sq
    println(d.area())
```

```text
warning[L4002]: this `Shape` call is dispatched dynamically, but its receiver is always a `Square`, a final type
```

## Why

A call through `dyn` reads the method from the value's table and jumps to it: the compiler cannot
see which method runs, so it cannot inline it or optimise across it. When the value converted to
`dyn` right there is always one final type, the table always holds the same method, and the call
pays for a choice that is never made.

## The fix

Call the method on the value itself: the call is direct, and can be inlined.

```ember,fixed
interface Shape:
    fn area(self) -> f64

struct Square:
    side: f64

extend Square implements Shape:
    fn area(self) -> f64:
        return self.side * self.side

fn main():
    sq = Square(2.0)
    println(sq.area())
```
