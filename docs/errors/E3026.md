# E3026 — a lambda would outlive what it borrows

```ember,fails
fn main():
    callbacks: Array[fn() -> int] = []
    for i in 0..3:
        name = f"item {i}"
        callbacks.push(fn() => name.len())
    println(callbacks.len())
```

```text
error[E3026]: this lambda borrows what it captures, so it may not be stored as `fn() -> i64`
```

## Why

A lambda that reads a variable borrows it, so the lambda is a view of that
variable and lives no longer than it. A `fn(A) -> R` written outside a
parameter is an owned callable value, which may go anywhere an owned value may:
into a list, a class field, a function's result, another thread. A borrowing
lambda stored there would call through a variable that is gone (`name` above
ends with each turn of the loop). A lambda that only reads `Copy` values copies
them instead (`[CLO-13]`); a `String` is not `Copy`.

## The fix

Write the lambda `owned fn`, which moves or copies each capture into the value:

```ember,fixed
fn main():
    callbacks: Array[fn() -> int] = []
    for i in 0..3:
        name = f"item {i}"
        callbacks.push(owned fn() => name.len())
    println(callbacks.len())
```

For a thread, take the borrowed values into a `thread.scope()`, which ends
before they do (`[THR-5]`).
