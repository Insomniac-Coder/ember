# E2116 — `copy of` before what it cannot copy as itself

```ember,fails
struct File:
    fd: int = 0

    fn drop():
        println("closed")

fn main():
    f = File(fd=3)
    g = copy of f
    println(g.fd)
```

```text
error[E2116]: `File` has no `Clone`, so `copy of` cannot make one
  = help: write `@derive(Clone)` above `struct File`, or keep a view of it: `ref f`
```

## Why

`copy of x` makes a value of the program's own with `Clone`, which changing leaves `x` as it was.
A type with a `drop` of its own manages something a field-by-field copy would duplicate (a file it
closes, memory it frees), so it is `Clone` only when it says so. A view is never copied either: its
text or its items are another value's, and a copy of the view would still point into them; `String(w)`
makes text of your own from a `StrView` `w`.

## The fix

```ember,fixed
@derive(Clone)
struct File:
    fd: int = 0

    fn drop():
        println("closed")

fn main():
    f = File(fd=3)
    g = copy of f
    println(g.fd)
```
