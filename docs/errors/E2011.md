# E2011 — negative literal index

```ember,fails
fn main():
    xs = [10, 20, 30]
    println(xs[-1])
```

```text
error[E2011]: negative literal index
```

## Why

An index counts from the start of the container and is never negative.
Python reads `xs[-1]` as "one from the end"; Ember does not, because the same
expression with a computed index (`xs[i - 1]` where `i` is `0`) would then
silently read the last element instead of reporting a mistake. A negative
index computed at run time panics as out of bounds; a negative literal, which
can only be the Python habit, is rejected here.

## The fix

Count from the length:

```ember,fixed
fn main():
    xs = [10, 20, 30]
    println(xs[xs.len() - 1])
```

For the last element, `xs.last()` returns it as an `Option`.
