# E7003 — a `@sync` class field is written after initialization

```ember,fails
@sync
class Token:
    value: int

    fn init(mut self):
        self.value = 1

fn main():
    token = Token()
    token.value = 2
```

```text
error[E7003]: cannot write field `value` of an `@sync` class after `init` or after using `self` as a whole
```

## Why

Many threads may hold the same class handle. A plain field write after `init`
could race with another thread's read. The same rule bars `ref mut`, passing a
field to a `mut` parameter, and `mut self` methods on the class. Within `init`,
field writes must finish before using `self` as a whole.

## The fix

Finish ordinary field assignments in `init`. For later changes, put an integer
in `Atomic[int]` or other mutable state in a synchronizing field such as
`Mutex[T]`, and use that field's operations.

```ember,fixed
@sync
class Token:
    value: int

    fn init(mut self):
        self.value = 2

fn main():
    token = Token()
    println(token.value)
```
