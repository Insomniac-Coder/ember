# E2173 — a type position holding what is not a type

```ember,fails
interface Shape:
    fn area() -> int

struct Square implements Shape:
    side: int

    fn area() -> int:
        return this.side * this.side

fn main():
    shapes: Array[Shape] = Array[Shape]()
    println(shapes.len())
```

```text
error[E2173]: `Shape` is an interface, and the types implementing it are values, not classes
  --> page.em:11:19
   |
11 |     shapes: Array[Shape] = Array[Shape]()
   |                   ^^^^^
   |
   = help: hold such a value behind a pointer: `Box[dyn Shape]` in a field or a collection (`Box(v)` makes one), `ref dyn Shape` for a parameter; or take a type parameter, `[T: Shape]`, and pass the value itself
   = note: an interface's name as a type is a class handle typed by it [OBJ-2]; a value of a type implementing `Shape` has its own size, which `dyn Shape` keeps behind a pointer (ODR-182)
```

## Why

A type says how its value is held (`[TYP-45]`). A bare interface name does not say who owns the values
behind it, and here the types implementing `Shape` are values with sizes of their own, so the name is not a
type that `Array` could hold. The author has to say who owns the values (`[IFC-5]`, `[OBJ-2]`).

## The fix

Name the one type the list holds. (For values of several types the rule's spelling is `owns dyn Shape`, `[TYP-45]`;
this compiler does not build `owns` before a type yet, `E0900`.)

```ember,fixed
interface Shape:
    fn area() -> int

struct Square implements Shape:
    side: int

    fn area() -> int:
        return this.side * this.side

fn main():
    shapes: Array[Square] = Array[Square]()
    println(shapes.len())
```
