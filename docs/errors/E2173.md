# E2173 — a type position holding what is not a type

```ember,fails
interface Shape:
    fn area() -> int

struct Square implements Shape:
    side: int

    fn area() -> int:
        return this.side * this.side

fn main():
    shapes: Array[Shape] = Array[Shape]()
    println(shapes.len())
```

```text
error[E2173]: `Shape` is an interface, so `Array[Shape]` does not say who owns the shapes; say who owns them: write `shapes: Array[owns dyn Shape]` in place of line 11 (the list is their only owner)
  --> page.em:11:19
   |
11 |     shapes: Array[Shape] = Array[Shape]()
   |                   ^^^^^
   |
   = help: `owns dyn Shape` holds the value alone in a block of its own (`owns v` makes one); with `shares dyn Shape` other names own it too, and each is made `shares`; `ref dyn Shape` is a view; or take a type parameter, `[T: needs Shape]`, and pass the value itself
   = note: an interface's name as a type does not say who owns its values [OBJ-2]; a value of a type implementing `Shape` has its own size, which `dyn Shape` keeps behind a pointer
```

## Why

A type says how its value is held (`[TYP-45]`). A bare interface name does not say who owns the values
behind it, whatever implements the interface (a struct, an enum or a class), in a parameter's type as in a list's.
The author has to say who owns the values (`[IFC-5]`, `[OBJ-2]`): `dyn Shape` is a parameter's read-only view.

## The fix

Name the one type the list holds. (For values of several types the rule's spelling is `owns dyn Shape`, `[TYP-45]`;
this compiler does not build `owns` before a type yet, `E0900`.)

```ember,fixed
interface Shape:
    fn area() -> int

struct Square implements Shape:
    side: int

    fn area() -> int:
        return this.side * this.side

fn main():
    shapes: Array[Square] = Array[Square]()
    println(shapes.len())
```
