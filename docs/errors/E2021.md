# E2021 — arguments that do not fit the parameters

```ember,fails
fn area(w: int, h: int, scale: int = 1) -> int:
    return w * h * scale

fn main():
    println(area(w=2, 3))
```

```text
error[E2021]: `area(w=2, 3)` gives `3` after the named `w=2`, and positional arguments come first; write `area(w=2, h=3)`
```

## Why

A call says which value goes to which parameter by position or by name, and the two are never mixed in a way that leaves the reader counting: positional arguments come first, each parameter is given once, and a parameter with no default is given a value. A call that breaks one of these has the wrong *shape*, which is a different mistake from a value of the wrong type (`E2020`), so it has its own code and its own help: the message shows the callee's first line, and for a positional argument after a named one, the call with that argument named by the first parameter nothing before it gives. The same holds for a memberwise constructor (`[STR-1]`) and `super.init(…)` (`[CLS-3]`), whose parameters are the fields.

## The fix

Name the argument, as the message writes it:

```ember,fixed
fn area(w: int, h: int, scale: int = 1) -> int:
    return w * h * scale

fn main():
    println(area(w=2, h=3))
```
