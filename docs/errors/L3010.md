# L3010 — `unsafe` block larger than necessary

```ember,fails
fn main():
    p: *mut i32
    unsafe:  # SAFETY: one slot, written before it is read and freed once
        p = alloc[i32](1)
        write(p, 0, 42)
        println(read(p, 0))
        println("freeing")
        free(p, 1)
```

```text
warning[L3010]: this `unsafe` block is larger than necessary
 = help: move the statements that need no `unsafe` out of the block; it should hold only what needs it [UNS-3]
```

This is a lint, not an error: the program compiles and runs.

## Why

An `unsafe:` block marks the operations whose safety the programmer answers for instead of the
compiler (`[UNS-1]`), and its `# SAFETY:` note says why each holds. A statement in it that needs no
`unsafe` — here `println("freeing")` — widens what a reader must check against that note for no
reason, and hides which lines the note is about (`[UNS-3]`). A block holding nothing that needs
`unsafe` is reported the same way.

A statement counts as needing `unsafe` when anything in it does: a loop whose body writes through a
pointer needs it, a `println` of a value read through one needs it.

An `unsafe:` block written directly inside unsafe code (an `unsafe fn`'s body, another `unsafe:`
block) is `L3010` too: that code is unsafe already, so the block adds nothing (`[UNS-12]`).

## The fix

Keep only what needs `unsafe` in the block. A binding the block sets can be declared before it and
assigned inside, since an `unsafe:` block is a scope of its own:

```ember,fixed
fn main():
    p: *mut i32
    unsafe:  # SAFETY: one slot, written before it is read and freed once
        p = alloc[i32](1)
        write(p, 0, 42)
        println(read(p, 0))
    println("freeing")
    unsafe:  # SAFETY: `p` is freed once
        free(p, 1)
```
