# E2102 — a derived `init` uses its object before `super.init`

```ember,fails
open class Shape:
    name: String

    fn init(owns name: String):
        this.name = name
        this.describe()

    virtual fn describe():
        println(this.name)

class Label(Shape):
    text: String

    fn init(owns text: String):
        super.init("label")
        this.text = text

    override fn describe():
        println(this.text)

fn main():
    _l = Label("hello")
```

```text
error[E2102]: field `text` is not assigned on every path before `super.init(...)`
```

## Why

Construction is two-phase (`[CLS-11]`). The base's `init` may call a
`virtual` method that the derived class overrides, and that override may read
the derived class's own fields. If the derived `init` assigned them only after
`super.init(…)`, the override would read a field that holds no value yet.

So before `super.init(…)`, a derived `init` assigns every field its class
declares without a default, on every path. It does not read an inherited field
or use `self` as a whole there: the base part of the object has no values
until the base constructor runs. After `super.init(…)` it may do anything.

## The fix

Assign the class's own fields first, then call `super.init(…)`:

```ember,fixed
open class Shape:
    name: String

    fn init(owns name: String):
        this.name = name
        this.describe()

    virtual fn describe():
        println(this.name)

class Label(Shape):
    text: String

    fn init(owns text: String):
        this.text = text
        super.init("label")

    override fn describe():
        println(this.text)

fn main():
    _l = Label("hello")
```
