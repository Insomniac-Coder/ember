# E3023 — cannot mutate a borrowed value parameter

```ember,fails
struct Counter:
    pub value: i32

fn increment(counter: Counter):
    counter.value = counter.value + 1

fn main():
    counter = Counter(1)
    increment(counter)
```

```text
error[E3023]: cannot mutate borrowed parameter `counter`
  --> page.em:5:5
   |
 4 | fn increment(counter: Counter):
   |              ---------------- `counter` is borrowed here
 5 |     counter.value = counter.value + 1
   |     ^^^^^^^^^^^^^ this write needs mutable access
   |
   = help: restructure to a single owner and declare this parameter `mut counter: Counter`
   = help: if the value is genuinely shared, use `RefCell[T]` for runtime-checked borrows
   = help: if the value has identity, make it a `class`
   = note: `RefCell` adds a one-word runtime borrow-state check in every profile; a class adds allocation, reference-counting, exclusivity, and `@static_safe` costs
```

## Why

A parameter with no explicit mode is a shared borrow, even when the compiler's
calling convention can pass a small value in a register. Letting the callee
write that private ABI copy would violate the source-level borrowing contract
and, worse, make the write silently disappear when control returns to the
caller. Parameter modes therefore govern mutation independently of physical
argument passing.

The first repair keeps one owner and explicitly grants the callee mutable
access:

```ember,fixed
struct Counter:
    pub value: i32

fn increment(mut counter: Counter):
    counter.value = counter.value + 1

fn main():
    counter = Counter(1)
    increment(counter)
    println(counter.value)
```

Use `Cell` or `RefCell` only when the value is genuinely shared and ordinary
single-owner restructuring does not express the design. Those alternatives
carry different runtime and API costs, so they are not the diagnostic's first
suggestion.
