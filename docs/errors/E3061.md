# E3061 — an arena allocation outlives its arena

```ember,fails
fn escaped() -> ref mut i32:
    arena = Arena.with_capacity(64)
    return arena.alloc(1)

fn main():
    println(0)
```

```text
error[E3061]: arena allocation cannot outlive `arena`
 --> page.em:6:24
  |
5 |     arena = Arena.with_capacity(64)
  |     ------------------------------- `arena` is local to this frame
6 |     return arena.alloc(1)
  |                        ^ this allocation view escapes the arena's region
  |            -------------- `arena` is borrowed for the allocation here
  |
  = help: move the `Arena` to an outer scope, or copy the value out before it is reset
  = note: Arena allocation views carry the region of the arena borrow (LT-4, ARN-1)
```

## Why

An arena allocation is a view into bytes owned by that arena. `alloc` takes a
shared borrow of the arena and the returned `ref mut T` carries that borrow's
region. Here `arena` is local to `escaped`, so it is dropped when the function
returns; returning the reference would leave it pointing into freed chunks.

Growth is not the problem. A growing arena appends stable chunks, so earlier
allocations do not move. The lifetime of the arena owner is the boundary.

## The fix

Put the arena in a scope that outlives every returned allocation. A wrapper
that returns arena-backed storage must make the parameter-to-result relationship
part of its signature with `@borrows(arena)`; omitting it is also E3061. If the
value itself must outlive the caller's arena, copy or move an owned value out
before resetting or dropping the arena.

```ember,fixed
@borrows(arena)
fn allocate_one(arena: Arena) -> ref mut i32:
    return arena.alloc(1)

fn main():
    arena = Arena.with_capacity(64)
    result = allocate_one(arena)
    println(result)
```
