# E4072 — relaxed floating point inside a `@deterministic` function

```ember,fails
@fastmath
fn fused(a: f64, b: f64, c: f64) -> f64:
    return a * b + c

@deterministic
fn step(x: f64) -> f64:
    return fused(x, 2.0, 1.0)

fn main():
    println(step(1.0))
```

```text
error[E4072]: `@deterministic` function `step` reaches relaxed floating point (`@fastmath`, `@fp(contract)`)
  = note: step -> fused -> a function with `@fastmath` or `@fp(contract)`
```

## Why

`@fastmath` and `@fp(contract)` let the C compiler fuse, reorder and reassociate floating-point
operations, and different compilers and machines do it differently, so the last bits of a result
change. A `@deterministic` function needs the same bits everywhere.

## The fix

```ember,fixed
fn fused(a: f64, b: f64, c: f64) -> f64:
    return a * b + c

@deterministic
fn step(x: f64) -> f64:
    return fused(x, 2.0, 1.0)

fn main():
    println(step(1.0))
```

Drop the relaxation, or use `mul_add`, which rounds once on every target (`[STD-3]`).
