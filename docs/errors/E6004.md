# E6004 — panic during compile-time evaluation

```ember,fails
const FRAME_BYTES: i32 = 4096 * 1024 * 1024

fn main():
    println(FRAME_BYTES)
```

```text
error[E6004]: evaluating `FRAME_BYTES` panics: integer overflow in `*`
```

## Why

A `const` is worked out while the program compiles, not each time it is used,
and it is worked out exactly as the program would: in its own type, so
`4096 * 1024 * 1024` overflows an `i32` as it would at run time. A panic
there cannot wait for the program to run, because the constant has no value
to put where it is used; so the compiler reports it, with the message the
program would have panicked with. The same holds for a division by zero and
for a shift by as many bits as the type has, or more. It is the earliest a
mistake in a constant can be found, and the cheapest.

## The fix

Give the constant a type that holds the value:

```ember,fixed
const FRAME_BYTES: i64 = 4096 * 1024 * 1024

fn main():
    println(FRAME_BYTES)
```
