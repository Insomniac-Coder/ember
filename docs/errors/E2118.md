# E2118 — `from` missing, or naming what a view cannot point into, or two things

```ember,fails
struct Parser:
    src: StrView

    fn next_word(src: StrView) -> StrView from src:
        return src

fn main():
    p = Parser(src = "a b")
    println(p.next_word("c"))
```

```text
error[E2118]: `src` is both a parameter and a field of `Parser`, so `from src` could mean either
  = help: rename the parameter: then `from src` names the field, and `from` with the new name names the parameter
```

## Why

`from` says what a view points into: after a function's result type, one parameter or one field of
`this` written bare (`[LT-1a]`); after the type of a class's view field, what the field may point
into for the object's whole life (`[LT-45]`, `[TYP-15]`). A name both a parameter and a field could
mean either, and the two mean different things to the callers: the parameter's argument stays viewed
while the result lives, or the object does. Ember does not choose for you.

A class's view field needs its `from` too, naming something that lives as long as the object and does
not move under the view: a `let` field whose contents live in their own heap block (a `String`, an
`Array`, an `owns T`), or `from static` for text written in the program. Without one, or with one
naming a field that may change, a fixed array or a struct stored inline, the field is `E2118` as well.

## The fix

Rename the parameter, and say which one the result points into:

```ember,fixed
struct Parser:
    src: StrView

    fn next_word(line: StrView) -> StrView from src:
        return this.src

fn main():
    p = Parser(src = "a b")
    println(p.next_word("c"))
```

`from line` would point into the argument instead, and the body would return a view of `line`.
