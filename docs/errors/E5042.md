# E5042 — a function C may call returns a pointer into a parameter C passes as a copy

```ember,fails
struct Pair:
    left: i32
    right: i32

fn address_of(value: Pair) -> *Pair:
    return ref_to_ptr(ref value)

fn give() -> extern "C" fn(Pair) -> *Pair:
    return address_of

fn main():
    println(give() == give())
```

```text
error[E5042]: `address_of` returns a pointer into `value`, which C passes as a copy
```

## Why

A borrowed parameter is the caller's own value when Ember calls the function.
C passes its arguments by value, so when the function's value becomes an
`extern "C" fn`, a call from C gives the function a copy the call makes, and
that copy ends when the call returns. A pointer the function returns into it
would point at nothing by the time C reads it. The compiler follows the pointer
through copies, conversions and aggregates in the function; a value read
through the parameter, or a pointer stored in it, is not into the copy.

## The fix

Take the parameter as a pointer, so the pointer C gets back is the one it
passed:

```ember,fixed
struct Pair:
    left: i32
    right: i32

fn same(value: *Pair) -> *Pair:
    return value

fn give() -> extern "C" fn(*Pair) -> *Pair:
    return same

fn main():
    println(give() == give())
```
