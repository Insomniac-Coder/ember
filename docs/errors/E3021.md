# E3021 — a read and a change of one place overlap

```ember,fails
struct Enemy:
    hp: int

fn main():
    enemies = [Enemy(hp=1)]
    boss = ref enemies[0]
    enemies[0].hp = 3
    println(boss.hp)
```

```text
error[E3021]: `enemies[0]` cannot be written while it is borrowed
```

## Why

At every point of a program a place is reached through any number of read-only views, or through exactly one
name that may change it (`[BRW-1]`). `boss` is a read-only view of `enemies[0]` and is still used after the line,
so the enemy may be read through it but not changed through another name: `boss` would see a value change under
it. A change that may move or free what the view points into (`enemies.push(...)`) ends the view instead, and its
later use is `E3060`. The conflict is found when compiling; nothing is checked while the program runs.

## The fix

Finish with the view before the change, or change the enemy through the view's own name made with `ref mut`:

```ember,fixed
struct Enemy:
    hp: int

fn main():
    enemies = [Enemy(hp=1)]
    boss = ref enemies[0]
    println(boss.hp)
    enemies[0].hp = 3
    println(enemies[0].hp)
```

* `[BRW-11]` — arguments that overlap a changeable one.
