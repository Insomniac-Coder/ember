# E3021 — a read and a change of one place overlap

```ember,fails
fn main():
    a: Array[i32] = Array[i32]()
    a.push(owns 1)
    v: Span[i32] = a
    a.push(owns 2)
    println(v[0])
```

```text
error[E3021]: `a` is borrowed here and mutably borrowed elsewhere
 --> page.em:5:5
  |
4 |     v: Span[i32] = a
  |                    - borrow of `a` starts here
5 |     a.push(owns 2)
  |     ^^^^^^^^^^^^^^ conflicting access here
6 |     println(v[0])
  |               - borrow later used here
  |
  = help: end the borrow before this: `v` is what keeps it alive, so shorten its last use or put it in a block of its own
  = note: a borrow lasts until its last use, not to the end of the scope (BRW-2)
```

## Why

At every point of a program a place is reached through any number of read-only views, or through exactly one
name that may change it (`[BRW-1]`). `v` is a read-only view into `a` and is still used after the line, so `a`
may be read through it but not changed: `push` may reallocate, which would leave `v` pointing at freed memory.
The conflict is found when compiling; nothing is checked while the program runs.

## The fix

Finish with the view before changing the owner:

```ember,fixed
fn main():
    a: Array[i32] = Array[i32]()
    a.push(owns 1)
    v: Span[i32] = a
    println(v[0])
    a.push(owns 2)
```

## See also

* `[BRW-1]` — one name changes, or any number read.
* `[BRW-11]` — arguments that overlap a changeable one.
