# E7004 — a value crossing to another thread is not `Send`

```ember,fails
import std.thread

fn main():
    count = Shared(0)
    worker = thread.spawn(owned fn() => count.get() + 1)
    println(worker.join())
```

```text
error[E7004]: the thread's function captures `count`, a `Shared[i64]`, which is not Send
```

## Why

What a thread's function captures moves to the new thread, and what it returns
comes back through `join`. A value is `Send` when another thread may own it: a
`Shared`'s counts and a non-`@sync` class's are plain memory, and two threads
changing them at once would corrupt them.

## The fix

Share it with a type whose counts are atomic, such as `SyncShared`, and change
what it holds through a lock or an atomic:

```ember,fixed
import std.thread
from std.sync import Atomic, SyncShared

fn main():
    count = SyncShared(Atomic(0))
    theirs = count
    worker = thread.spawn(owned fn() => theirs.get().fetch_add(1))
    worker.join()
    println(count.get().load())
```
