# E7004 — a value crossing to another thread is not `Send`

```ember,fails
import std.thread

[F: needs fn() -> int]
fn run_later(owns task: F) -> int:
    worker = thread.spawn(owns owned fn() -> int => task())
    return worker.join()

fn main():
    println(run_later(owns owned fn() -> int => 1))
```

```text
error[E7004]: the thread's function captures `task`, an `F`, which is not Send
```

## Why

What a thread's function captures moves to the new thread, and what it returns
comes back through `join`. A value is `Send` when another thread may own it, and a
type parameter may stand for a type that is not: a `shares` value's counts are plain
memory, and two threads changing them at once would corrupt them.

## The fix

Say that the type must be `Send`, so each call is checked against it:

```ember,fixed
import std.thread

[F: needs (fn() -> int, Send)]
fn run_later(owns task: F) -> int:
    worker = thread.spawn(owns owned fn() -> int => task())
    return worker.join()

fn main():
    println(run_later(owns owned fn() -> int => 1))
```
