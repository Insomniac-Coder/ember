# E7014 — a `thread_shared` value changed directly

```ember,fails
class Names:
    count: int = 0

fn main():
    names = thread_shared Names()
    names.count = 1
```

```text
error[E7014]: `names` is shared between threads (line 5), so no owner changes it directly, and `names.count = 1` does
```

## Why

Any thread may hold an owner of a `thread_shared` value and read it at the same moment, so a plain
write through one owner would race every reader. The value says how it changes: through an `Atomic`,
a `Mutex`, an `RwLock`, a channel, or a field `guarded by` a lock.

## The fix

Set the state where the value is made, or keep what changes in an `Atomic` or under a lock:

```ember,fixed
from std.sync import Atomic

class Names:
    count: Atomic[int] = Atomic(0)

fn main():
    names = thread_shared Names()
    names.count.store(1)
```
