# L3001 — potential reference cycle

```ember,fails
class Parent:
    child: Child

class Child:
    parent: Parent
```

```text
warning[L3001]: potential reference cycle: Parent.child -> Child.parent -> Parent
 = help: use `Weak[Child]` for `Parent.child` if this is a back-reference
```

This is a lint, not an error: the declarations compile, but the ownership path
is capable of keeping both allocations alive after every external owner is
dropped.

## Why

Reference counting can reclaim an object only when its strong count reaches
zero. A pair of objects that retains one another never reaches that point, so
the leak depends on a relationship that may be far from the code that created
the objects. Reporting the declared path makes the ownership decision visible
before that relationship becomes a long-running leak.

The compiler reports only statically visible strong paths. It does not claim
that an allocation cycle definitely exists at run time, and it does not change
the program's ownership semantics.

## The fix

Use a weak handle for the back-reference when that link is observational rather
than owning. The forward owner remains strong; upgrading the weak link is an
explicit operation that can account for the target having been destroyed.

```ember,fixed
class Parent:
    child: Child

class Child:
    parent: Weak[Parent]
```
