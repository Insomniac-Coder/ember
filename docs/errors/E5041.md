# E5041 — a retained callback with nothing that unregisters it

```ember,fails
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(param(handler, callback(retained, user_data=data)))
    safe fn keeps(handler: extern "C" fn(*mut void, i32), data: *mut void)

fn main():
    pass
```

```text
error[E5041]: `keeps` keeps `handler` past the call (`callback(retained)`), and nothing unregisters it
```

## Why

A callback C keeps past the call — a listener, a log sink — is called later, with the user data it
was given, and the captures that user data carries must live until C stops calling. Ember frees them
when the registration ends, which it can know only from the foreign function that ends it. Without
one, the captures would either leak or be freed while C still holds the pointer, and the next call
would read freed memory. `destroys(f)` names that function; the registering call then returns a
`Retained` token whose end calls it.

## The fix

Name the function that unregisters the callback:

```ember,fixed
from std.ffi import ForeignCallback

unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    fn unregister(handler: extern "C" fn(*mut void, i32), data: *mut void)

    @ffi(param(handler, callback(retained, user_data=data)), destroys(unregister))
    safe fn keeps(handler: extern "C" fn(*mut void, i32), data: *mut void)

fn main():
    pass
```
