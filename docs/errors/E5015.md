# E5015 — a type may not cross the boundary

```ember,fails
pub extern "C" fn read_text(text: *String) -> i32:
    return 0

fn main():
    pass
```

```text
error[E5015]: exported parameter `text` reaches an owning Ember value
```

The same code names a type with no foreign representation at all, in any `extern` signature or
foreign static:

```ember
struct Frame:
    pub caption: str

extern "C" fn submit(f: Frame) -> i32:    # error[E5015]: `Frame` has no foreign representation
    return 1
```

## Why

A foreign boundary is a promise about *values*, made to code that will never see your source and
does not know Ember's rules. Two kinds of type break it.

An owning Ember value — `String`, `Array`, a class handle, anything with drop glue — cannot be
handed to C: C does not know to drop it, or that it must not copy it. A raw pointer changes the
argument's carrier, but it does not make the `String` behind it a C value. The same restriction
applies to a record containing an owner, and to a callback signature that reaches one through its
parameters or result (`[FFI-31b]`).

A type with no C representation cannot cross at all. `str` is an Ember view over validated UTF-8
bytes with a checked lifetime; it has no standalone C value, and putting it inside `Frame` does not
give the record one. An incomplete foreign type has no size to pass by value. The boundary takes
the scalars, `@layout(c)` structs whose fields are themselves representable, raw pointers, `cstr`,
opaque handles and `extern "C" fn` pointers (`[FFI-5]`, `[FFI-8]`).

## The fix

Keep the Ember type on the Ember side. Pass what the boundary can represent — usually a pointer
and a length — and state its lifetime in the surrounding API:

```ember,fixed
pub extern "C" fn byte_count(data: *u8, len: usize) -> usize:
    return len

fn main():
    println(byte_count(null[*u8](), 0))
```
