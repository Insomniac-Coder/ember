# E5069 — `no_callbacks` on a function that takes a callback

```ember,fails
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(no_callbacks)
    @safety("`compare` orders two of the `n` values at `values`")
    unsafe fn sort_with(values: *mut i32, n: usize, compare: extern "C" fn(*i32, *i32) -> i32)

fn main():
    pass
```

```text
error[E5069]: `sort_with` takes a function pointer (`compare`), so it may call back into Ember; remove `no_callbacks` from its `@ffi(...)`
 = note: `no_callbacks` asserts that a call of the function runs no Ember code [FFI-52]
```

## Why

`@ffi(no_callbacks)` tells the compiler that a call of the foreign function runs no Ember code, so
the call changes nothing a callback, an export or an override would change. A function whose own
contract takes a callback, or that takes a function pointer, may call whatever it is given: the mark
would be false at the very line that hands it the function, and the checks that rely on it would let
a loop walk a list the callback changes.

## The fix

Remove the mark: the function's calls are then counted as running the functions it may call.

```ember,fixed
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @safety("`compare` orders two of the `n` values at `values`")
    unsafe fn sort_with(values: *mut i32, n: usize, compare: extern "C" fn(*i32, *i32) -> i32)

fn main():
    pass
```
