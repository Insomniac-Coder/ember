# E3080 — overlapping access to a class field through the same handle

```ember,fails
class Bag:
    items: Array[int]

    fn init(mut self):
        self.items = [1, 2, 3]

fn main():
    b = Bag()
    v = b.items[..]
    b.items.push(4)
    println(v)
```

```text
error[E3080]: `b.items` is borrowed here and mutably borrowed elsewhere
  --> page.em:10:5
   |
 9 |     v = b.items[..]
   |         ------- borrow of `b.items` starts here
10 |     b.items.push(4)
   |     ^^^^^^^^^^^^^^^ conflicting access here
11 |     println(v)
   |             - borrow later used here
   |
   = help: end the borrow before this: `v` is what keeps it alive, so shorten its last use or put it in a block of its own
   = note: a borrow lasts until its last use, not to the end of the scope (BRW-2)
```

## Why

`v` views the array in `b.items`, and `push` may move that array to a larger
buffer, which would leave `v` pointing at freed memory. Accesses to a class
field are checked at run time, because another handle to the same object can
reach the field where the compiler cannot see it (`[EXC-1]`). When both
accesses go through one local handle, as here, the compiler sees the conflict
and rejects it before the program runs (`[EXC-3]`, shape X1): the run-time
check would fail every time.

## The fix

End the view before the field is changed, or copy what it shows:

```ember,fixed
class Bag:
    items: Array[int]

    fn init(mut self):
        self.items = [1, 2, 3]

fn main():
    b = Bag()
    v = b.items[..]
    println(v)
    b.items.push(4)
    println(b.items)
```
