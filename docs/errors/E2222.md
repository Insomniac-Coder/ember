# E2222 — coroutine where an ordinary function is required

```ember,fails
extern "C" gen fn ticks() -> Generator[int]:
    yield 1

fn main():
    pass
```

```text
error[E2222]: a `gen fn` cannot be `extern` or `@export`ed
 = note: calling a generator builds its frame, a value only Ember code resumes; C calls an ordinary function [CORO-10]
```

## Why

Calling a generator runs none of its body: it builds the generator's frame, a
value of a type the compiler makes for that one function, which `next` resumes
(`[CORO-1]`, `[CORO-3]`). C has no such value to receive, no `next` to call and
no way to drop a suspended frame, so a generator cannot be a C entry point, an
exported symbol, or a callback C calls.

## The fix

Give C an ordinary function, and drive the generator on the Ember side:

```ember,fixed
gen fn ticks() -> Generator[int]:
    yield 1

extern "C" fn first_tick() -> i32:
    for t in ticks():
        return t as i32
    return 0

fn main():
    println(first_tick())
```
