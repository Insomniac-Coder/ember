# W5034 — an entity of an anonymous C++ namespace is not imported

```cpp,file=local.hpp
#pragma once

namespace {
inline int helper() noexcept { return 1; }
}

inline int answer() noexcept { return 42 + helper(); }
```

```cpp,file=named.hpp
#pragma once

namespace detail {
inline int helper() noexcept { return 1; }
}
```

```ember,fails
import cpp "local.hpp"

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        println(cpp.answer())
```

```text
warning[W5034]: `helper` is not imported from `local.hpp`: it is in an anonymous namespace, so each C++ file has its own
 --> page.em:1:1
  |
1 | import cpp "local.hpp"
  | ^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: declared at local.hpp:4 [FFI-41]
```

## Why

Everything in an anonymous namespace has internal linkage: each C++ translation unit that includes
the header gets its own copy, with its own state, and none of them is reachable from another file.
The thunk Ember calls lives in a translation unit of its own, so a `helper` reached through it would
be that file's private copy — not the one the rest of the C++ program sees, which for a variable or
a function with a `static` local is a different object. The importer skips such entities instead,
with a warning, and imports the rest of the header.

## The fix

Declare what Ember should call in a named namespace (here `detail`, imported as `cpp.detail`), so
there is one of it.

```ember,fixed
import cpp "named.hpp"

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        println(cpp.detail.helper())
```
