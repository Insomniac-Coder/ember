# E5010 — overlay does not match the C declaration

```c,file=tally.h
static inline int tally_scale(int value, int by) { return value * by; }
```

```ember,file=drifted.em
unsafe overlay c "tally.h":  # SAFETY(ffi): each entry matches its declaration in the header
    fn tally_scale(value)
```

```ember,file=matching.em
unsafe overlay c "tally.h":  # SAFETY(ffi): each entry matches its declaration in the header
    fn tally_scale(value, by)
```

```ember,fails
import c "tally.h" with (overlay = "drifted.em")

fn main():
    pass
```

```text
error[E5010]: `tally_scale` takes 2 parameters in `tally.h`, and the entry names 1
 --> drifted.em:2:8
  |
2 |     fn tally_scale(value)
  |        ^^^^^^^^^^^
  |
  = note: an overlay entry matches the header's declaration, so overlays cannot drift [FFI-12]
```

## Why

An overlay states what a header cannot: who owns a pointer, how many elements it points at, whether
the function is safe to call. Those facts are about one declaration. When the header changes — a
parameter added, renamed or moved — an entry written for the old declaration would quietly attach its
facts to the wrong argument, and safe code would rest on a contract nobody wrote for the function it
calls. So every entry is checked against the header on every build: its name, its parameter count
and each parameter's name must be the header's.

## The fix

Write the entry for the declaration the header has now:

```ember,fixed
import c "tally.h" with (overlay = "matching.em")

fn main():
    println(c.tally_scale(3, 4))
```
