# E5014 — two imports request the same implementation macro

```c,file=single.h
#ifndef SINGLE_H
#define SINGLE_H
int single_answer(void);
#endif

#ifdef SINGLE_IMPLEMENTATION
int single_answer(void) { return 42; }
#endif
```

```ember,fails
import c "single.h" with (implementation = ["SINGLE_IMPLEMENTATION"])
import c "single.h" with (implementation = ["SINGLE_IMPLEMENTATION"], defines = ["SINGLE_OTHER"]) as other

fn main():
    pass
```

```text
error[E5014]: `single.h`'s implementation (`SINGLE_IMPLEMENTATION`) is already compiled into this build
 --> page.em:2:1
  |
1 | import c "single.h" with (implementation = ["SINGLE_IMPLEMENTATION"])
  | --------------------------------------------------------------------- requested here first
2 | import c "single.h" with (implementation = ["SINGLE_IMPLEMENTATION"], defines = ["SINGLE_OTHER"]) as other
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = help: request it in one `import c` only, or import the header the same way everywhere
  = note: a single-header library's implementation is compiled exactly once per build [FFI-29b]
```

## Why

A single-header library holds its implementation behind a macro: the one C file that defines the
macro before including the header compiles the library's functions. `implementation = [...]` asks the
import's shim to be that file. Two imports asking for it would compile the functions twice, and the
link would fail on duplicate symbols — or, with weak symbols, pick one of two copies built with
different defines. The compiler reports the second request instead.

## The fix

Ask for the implementation in one import; the other imports of the header use the functions it
compiled:

```ember,fixed
import c "single.h" with (implementation = ["SINGLE_IMPLEMENTATION"])
import c "single.h" with (defines = ["SINGLE_OTHER"]) as other

fn main():
    unsafe:  # SAFETY(ffi): a call with no arguments
        println(c.single_answer())
```
