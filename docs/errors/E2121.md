# E2121 — an implementation outside the packages that may write it

```ember,fails
extend bool implements Add[bool]:
    type Output = bool
    fn add(self, other: bool) -> bool:
        return self or other

fn main():
    println(true + false)
```

```text
error[E2121]: `bool` and `Add[bool]` are both another package's, so this package cannot implement one for the other
```

## Why

An implementation of an interface for a type lives with the interface or with the
type (`[TYP-20]`). If any package could write one, two packages could each make
`bool` an `Add[bool]`, and a program using both would have two implementations
with no way to choose; a later version of the standard library adding its own
would break every program that had written one. Separate compilation relies on
each implementation having one package that may write it.

A type of your package among the interface's arguments places it too: the
package that declares `Vec3` may write `extend f32 implements Mul[Vec3]`, since
no other package can name `Vec3` there. Reading the type and then the
interface's arguments, the first of your package's types must come before any
type parameter of the implementation standing alone (ODR-097).

## The fix

Implement your own interface for the type, or the interface for your own type.
Wrapping the value in a type of your own does both:

```ember,fixed
struct Flag:
    on: bool

extend Flag implements Add[Flag]:
    type Output = Flag
    fn add(self, other: Flag) -> Flag:
        return Flag(on = self.on or other.on)

fn main():
    a = Flag(on = true)
    b = Flag(on = false)
    println((a + b).on)
```
