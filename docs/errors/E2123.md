# E2123 — a value made for a place that owns it alone, without `owns`

```ember,fails
struct Mesh:
    points: Array[f64]

struct Entity:
    mesh: owns Mesh

fn main():
    e = Entity(mesh=Mesh(points=[0.0, 1.0]))
    println(e.mesh.points.len())
```

```text
error[E2123]: `mesh` owns its mesh; say so where it is made: `mesh=owns Mesh(points=[0.0, 1.0])`
```

## Why

An `owns` field, an `Option[owns T]` and a list of `owns` values each hold their value in a block of
its own, with one owner (`[TYP-45]`). Making the block is a decision with a cost: an allocation, and an
owner that frees it. The rule is that the line that makes the value for such a place says so with
`owns`, at first and later, so a reader sees where the block is made and that the place takes the
value over (`[OWN-10]`, `[GRM-15]`). Leaving the word off would make an allocation the line does not
show.

## The fix

Write `owns` before the value, on the line that makes it:

```ember,fixed
struct Mesh:
    points: Array[f64]

struct Entity:
    mesh: owns Mesh

fn main():
    e = Entity(mesh=owns Mesh(points=[0.0, 1.0]))
    println(e.mesh.points.len())
```

The same goes for a value given later (`e.mesh = owns Mesh(points=[1.0, 2.0])`, which frees the old
mesh), for `left=Some(owns Tree(value=2, left=None))` where the field is an `Option[owns Tree]`, and
for `pools.push(owns IntPool(items=[1, 2]))` where the list holds `owns` values.
