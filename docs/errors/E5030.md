# E5030 — a C++ function takes a `std::function`

```cpp,file=callbacks.hpp
#pragma once
#include <functional>

inline int apply(std::function<int(int)> f) { return f(1); }
```

```cpp,file=callbacks_fn.hpp
#pragma once

inline int apply(int (*f)(int)) { return f(1); }
```

```ember,fails
import cpp "callbacks.hpp"

fn twice(x: i32) -> i32:
    return x * 2

fn main():
    unsafe:  # SAFETY(ffi): a scalar callback
        println(cpp.apply(twice))
```

## Why

A `std::function` is a C++ object: building one from an Ember function would mean running C++ code
(its constructor, perhaps an allocation) that holds a pointer into Ember with no contract saying for
how long, and calling it means a C++ call back into Ember, whose exceptions and lifetimes neither side
states. The specification makes it never a parameter type (`[FFI-17a]`): a C++ function that takes
one is not imported, and naming it is `E5030`.

## The fix

Give C++ a function that takes what C takes, a function pointer (and a context pointer where the
callback needs state): an Ember `extern "C" fn` is one.

```ember,fixed
import cpp "callbacks_fn.hpp"

extern "C" fn twice(x: i32) -> i32:
    return x * 2

fn main():
    unsafe:  # SAFETY(ffi): a scalar callback
        match cpp.apply(twice):
            Ok(value):
                println(value)
            Err(error):
                println(error.what)
```
