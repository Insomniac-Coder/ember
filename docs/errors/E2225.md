# E2225 — `migrate_from` may not panic

```toml
[build]
reload = "all"
```

```ember,fails
from std.hot import ReloadError

class Gauge:
    level: int = 0

    fn migrate_from(old: ref OldSelf) -> Result[Self, ReloadError]:
        g = Gauge()
        g.level = "4".parse[int]().unwrap() + old.level
        return Ok(g)

fn main():
    println(Gauge().level)
```

```text
error[E2225]: `migrate_from` may not panic: `unwrap` would end the process
```

## Why

`migrate_from` runs while a hot reload prepares the new instances of its type, in a process that is
still running the old code. A reload that cannot build a value must be refused with a report, and
the program must carry on with what it had; a panic there would end the very process the reload
was meant to keep alive. So the function may not panic on purpose (`panic`, `unwrap`, `expect`,
`assert`), and a check it trips by accident (an index out of bounds, an overflow) fails the reload
with `ReloadError.Migration` instead of aborting.

## The fix

Return the failure as a value: `?` passes an error on, and `Err(ReloadError.Migration(…))` names
the type, the instance and what went wrong.

```toml
[build]
reload = "all"
```

```ember,fixed
from std.hot import ReloadError

class Gauge:
    level: int = 0

    fn migrate_from(old: ref OldSelf) -> Result[Self, ReloadError]:
        match "4".parse[int]():
            Ok(extra):
                g = Gauge()
                g.level = extra + old.level
                return Ok(g)
            Err(_):
                return Err(ReloadError.Migration("Gauge".to_string(), 0, "not a number".to_string()))

fn main():
    println(Gauge().level)
```
