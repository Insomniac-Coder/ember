# W5033 — an `&&`-qualified C++ member function is not imported

```cpp,file=builder.hpp
#pragma once

class Builder {
public:
    Builder() noexcept {}
    ~Builder() {}
    int finish() && noexcept { return 1; }
};
```

```cpp,file=build.hpp
#pragma once

// Defined in C++ as `return Builder{}.finish();`: the temporary is C++'s.
int build_one() noexcept;
```

```ember,fails
import cpp "builder.hpp"

fn main():
    pass
```

```text
warning[W5033]: `Builder.finish` is not imported from `builder.hpp`: an `&&`-qualified member function, which only a temporary may call
 --> page.em:1:1
  |
1 | import cpp "builder.hpp"
  | ^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: declared at builder.hpp:7 [FFI-40]
```

## Why

A member function qualified `&&` may be called only on an object about to expire — a temporary, or
one `std::move` gave up — and it is allowed to leave that object gutted. Ember has no such call: a
method takes `self` or `mut self`, and the object stays its owner's, usable after the call. Importing
`finish` as an ordinary method would let Ember code go on using the object C++ was promised it could
consume. So it is left out, and the import says so: a warning, since the rest of the class imports as
ever.

## The fix

Let C++ make and consume the temporary, behind a function Ember can call.

```ember,fixed
import cpp "build.hpp"

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        println(cpp.build_one())
```
