# E5001 — imported type layout does not match

```c,file=packed2.h
#pragma pack(push, 2)
typedef struct Header { unsigned char tag; unsigned int size; } Header;
#pragma pack(pop)
```

```c,file=packed1.h
#pragma pack(push, 1)
typedef struct Header { unsigned char tag; unsigned int size; } Header;
#pragma pack(pop)
```

```ember,fails
import c "packed2.h"

fn main():
    pass
```

```text
error[E5001]: the layout of `Header` does not match `packed2.h`'s: its size is 8 bytes in Ember and 6 in C; its alignment is 4 in Ember and 2 in C; field `size` is at offset 4 in Ember and 2 in C
 --> <import c packed2.h as c.h_packed2>:5:1
  |
5 | pub struct Header:
  | ^^^^^^^^^^^^^^^^^^
  |
  = help: a packing Ember cannot write (`#pragma pack(2)`) cannot be imported; wrap the struct in C functions
  = note: Clang's sizes, alignments and offsets are for this target and these flags; Ember's must equal them [FFI-5]
```

## Why

A struct crosses the boundary by value and by pointer, and both sides read the same bytes: a field
Ember places at offset 4 and C at offset 2 is a different field to each of them, with no error at
run time, only wrong numbers. So the importer does not trust its own reading of the header: it asks
Clang for the size, alignment and every field's offset, for this target and these flags, and the
compiler checks the layout it builds against them. `#pragma pack(2)` aligns each field to at most
two bytes, which no Ember attribute says (`@packed` is one byte), so the two layouts differ and the
struct cannot be imported as a value.

## The fix

Pack the struct to one byte, which Ember writes as `@packed`, or keep the struct on the C side behind
functions that take and return what Ember can lay out:

```ember,fixed
import c "packed1.h"

fn main():
    h = c.Header(tag=1, size=2)
    println(h.size)
```
