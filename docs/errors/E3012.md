# E3012 — cannot move out of a class field

```ember,fails
class Node:
    name: Option[String]

    fn clear(mut self):
        self.name = None

fn main():
    a = Node(name=Some("hello"))
    b = a
    x = a.name
    b.clear()
    println(x)
```

```text
error[E3012]: cannot move out of a class field
  --> page.em:10:9
   |
10 |     x = a.name
   |         ^^^^^^ moved out here
   |
   = help: clone it, or leave a value in its place with `mem.take` or `mem.replace`
   = note: the object keeps the field, and every handle to it can still reach it [EXP-6]
```

A `match` on a class field reports the same code at a pattern that binds a
non-`Copy` part of it: `match a.name: Some(s)` would move the `String` into
`s`.

## Why

A class object is shared: every handle to it reaches the same fields. A move
hands the value to a new owner, but the object still holds it and still
drops it, and any other handle (`b` above) can still reach it. Here
`b.clear()` would free the `String` that `x` holds. A struct field can be
moved out because the struct has one owner, and the compiler tracks that the
field is gone; an object's other handles are not tracked.

## The fix

Clone the value, or leave another value in its place:

```ember,fixed
class Node:
    name: Option[String]

    fn clear(mut self):
        self.name = None

fn main():
    a = Node(name=Some("hello"))
    b = a
    x = a.name.clone()
    b.clear()
    println(x, a.name)
```
