# E5011 — one C identity imported with two layouts

```c,file=common.h
#ifndef COMMON_H
#define COMMON_H
typedef struct Vec2 {
    float x;
    float y;
#ifdef WIDE
    float z;
#endif
} Vec2;
#endif
```

```ember,fails
import c "common.h"
import c "common.h" with (defines = ["WIDE"])

fn main():
    pass
```

```text
error[E5011]: `Vec2` is imported from `common.h` with a layout other than the one `common.h` gave it
 --> page.em:2:1
  |
2 | import c "common.h" with (defines = ["WIDE"])
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = help: give one import its own alias (`as name`), making its entities distinct
  = note: two imports of one C declaration with one layout are one Ember entity [FFI-30]
```

## Why

Two imports of one C declaration are one Ember type, so a `Vec2` one import makes can be handed to a
function of the other. That only holds while both see the same declaration: here a define gives the
second import a third field, and one name would stand for two layouts, a value of one passed where
the other is expected. The compiler refuses to choose between them.

## The fix

Give the import with the other layout a name of its own: its types are then its own, and the two
`Vec2`s are distinct.

```ember,fixed
import c "common.h"
import c "common.h" with (defines = ["WIDE"]) as wide

fn main():
    v = wide.Vec2(x=1.0, y=2.0, z=3.0)
    println(v.z)
```
