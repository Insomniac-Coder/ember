# E2180 — `?` outside a function returning `Option` or `Result`

```ember,fails
fn parse(text: StrView) -> Result[int, String]:
    return Ok(1)

fn main():
    n = parse("1")?
    println(n)
```

```text
error[E2180]: `?` on a `Result[i64, String]` needs the function to return one too, not `void`
 --> page.em:5:9
  |
5 |     n = parse("1")?
  |         ^^^^^^^^^^^
  |
```

## Why

`e?` evaluates to the success payload or returns the failure from the enclosing function (`[ERR-2]`). A
function that returns neither an `Option` nor a `Result` has nothing to return the failure as, so `?` there
has no meaning.

## The fix

Make the function return a `Result` (or an `Option`) so the failure can travel up, or handle the failure
where it happens:

```ember,fixed
fn parse(text: StrView) -> Result[int, String]:
    return Ok(1)

fn run() -> Result[int, String]:
    n = parse("1")?
    return Ok(n)

fn main():
    match run():
        Ok(n):
            println(n)
        Err(e):
            println(e)
```
