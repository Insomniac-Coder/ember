# E4042 — a `@nolock` function acquires a lock

```ember,fails
fn apply(f: fn(int) -> int, x: int) -> int:
    return f(x)

@nolock
fn run(f: fn(int) -> int) -> int:
    g = f
    return g(1)

fn double(x: int) -> int:
    return x * 2

fn main():
    println(apply(double, 2), run(double))
```

```text
error[E4042]: `@nolock` function `run` acquires a lock
  = note: run -> a call through a function value, whose effects nothing declares
```

## Why

A function that takes a lock — even with `try_lock`, which never waits — can deadlock with a
caller that holds another, and couples its speed to every other thread using that lock. `@nolock`
keeps it free of locks. A call through a function value carries every effect, since nothing in its
type says which it has, so the contract cannot be proved through one.

## The fix

```ember,fixed
fn apply(f: fn(int) -> int, x: int) -> int:
    return f(x)

@nolock
fn run() -> int:
    return apply(double, 1)

fn double(x: int) -> int:
    return x * 2

fn main():
    println(run())
```

Pass the function itself to a callable parameter, so the compiler checks the function actually
passed, or call it directly.
