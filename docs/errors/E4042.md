# E4042 — a `@nolock` function acquires a lock

```ember,fails
from std.sync import Mutex

@nolock
fn bump(counter: ref Mutex[int]) -> int:
    _guard = counter.lock()
    return 1

fn main():
    counter = Mutex(0)
    println(bump(ref counter))
```

```text
error[E4042]: `@nolock` function `bump` acquires a lock
  = note: bump -> `Mutex.lock`
```

## Why

A function that takes a lock — even with `try_lock`, which never waits — can deadlock with a
caller that holds another, and couples its speed to every other thread using that lock. `@nolock`
keeps it free of locks, through every function it calls; a call through a function value carries
the effects of the functions of its type that the program has (`[EFF-2]`), so one that locks
counts too.

## The fix

```ember,fixed
from std.sync import Atomic

@nolock
fn bump(counter: ref Atomic[int]) -> int:
    return counter.fetch_add(1) + 1

fn main():
    counter = Atomic(0)
    println(bump(ref counter))
```

Count with an atomic, which takes no lock, or take the lock in a caller that is not `@nolock`.
