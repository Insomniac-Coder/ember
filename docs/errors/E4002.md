# E4002 — a `@nosync` function reaches a synchronising operation

```ember,fails
@sync
class Token:
    n: int

@nosync
fn shares(t: Token) -> int:
    copies = [t, t]
    return copies.len()

fn main():
    println(shares(Token(1)))
```

```text
error[E4002]: `@nosync` function `shares` reaches a synchronising operation
  = note: shares -> retaining a `@sync` handle
```

## Why

Synchronising operations — atomic counts, locks, channel operations — make other cores wait or
flush their caches, and their cost depends on what the other threads are doing. `@nosync` keeps a
function free of them, so its speed does not depend on contention. A `@sync` class's handles count
atomically, so copying one synchronises.

## The fix

```ember,fixed
@sync
class Token:
    n: int

@nosync
fn read(t: Token) -> int:
    return t.n

fn main():
    println(read(Token(1)))
```

Read through the handle you were given instead of copying it, or use a class that is not
`@sync`, whose counts are plain integers.
