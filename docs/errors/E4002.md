# E4002 — a `@nosync` function reaches a synchronising operation

```ember,fails
class Token:
    n: int

@nosync
fn share_count(t: thread_shared Token) -> int:
    copies = [thread_shared t, thread_shared t]
    return copies.len()

fn main():
    println(share_count(thread_shared Token(1)))
```

```text
error[E4002]: `@nosync` function `share_count` reaches a synchronising operation
  = note: share_count -> one more owner of a `thread_shared` object
```

## Why

Synchronising operations — atomic counts, locks, channel operations — make other cores wait or
flush their caches, and their cost depends on what the other threads are doing. `@nosync` keeps a
function free of them, so its speed does not depend on contention. The owners of a `thread_shared` value
are counted atomically, so making one synchronises.

## The fix

```ember,fixed
class Token:
    n: int

@nosync
fn read(t: thread_shared Token) -> int:
    return t.n

fn main():
    println(read(thread_shared Token(1)))
```

Read through the owner you were given instead of making another, or use a value that is not
`thread_shared`, whose counts are plain integers.
