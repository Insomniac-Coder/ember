# E3016 — `self` escapes its own drop

```ember,fails
class Token:
    fn drop(mut self):
        retained: Array[Token] = Array[Token]()
        retained.push(self)

fn main():
    token = Token()
```

```text
error[E3016]: `self` escapes its own drop
  --> page.em:4:9
   |
4 |         retained.push(self)
  |         ^^^^^^^^^^^^^^^^^^^ published here
  |
  = note: a destructor may not publish a handle to the object being destroyed [CLS-7a]
  = help: move the data out with `mem.take` instead
```

## Why

Destruction begins only after the last strong handle has gone away. Retaining
that same object from inside its destructor creates a new owner while fields
and base classes are being torn down, so later code could observe a partly
destroyed object. The runtime detects any path it cannot see, but visible
publication is refused early so that cleanup cannot accidentally turn into
resurrection.

## The fix

Perform cleanup using the destructor's fields or local data; do not store the
destructor's handle in something that can outlive the call. If cleanup needs to
keep a field's contents, take that field out rather than retaining `self`.

```ember,fixed
class Token:
    fn drop(mut self):
        released = 42
        println(released)

fn main():
    token = Token()
```
