# E5061 — a C++ function's exception policy is neither derived nor declared

```toml
[package]
name = "page"
version = "0.1.0"

[cpp.freestanding]
flags = ["-nostdinc"]
```

```cpp,file=engine.hpp
#pragma once

inline int add(int a, int b) noexcept(sizeof(int) == 4) { return a + b; }
```

```ember,file=engine_policy.em
unsafe overlay cpp "engine.hpp":
    @ffi(noexcept)
    fn add(a, b)
```

```ember,fails
import cpp "engine.hpp" with (project = "freestanding")

fn main():
    unsafe:  # SAFETY(ffi): a scalar call
        println(cpp.add(1, 2))
```

```text
error[E5061]: `add` was not imported from `engine.hpp`: its exception policy cannot be derived from the header (Clang could not evaluate its `noexcept(…)`), and no overlay declares one
 --> page.em:5:21
  |
5 |         println(cpp.add(1, 2))
  |                     ^^^
  |
  = note: an overlay entry declares its policy: `@ffi(noexcept)` or `@ffi(noexcept=false)` [FFI-43]
```

## Why

Whether a C++ function can throw decides its Ember signature: one that cannot is called directly and
returns its `T`; one that can returns `Result[T, CppError]`, its thunk catching every exception
(`[FFI-24]`). The importer derives the answer from the declaration, and a `noexcept(expr)` it asks
Clang to evaluate. When Clang cannot — here the project is freestanding, so the question the
importer asks, which uses `std::declval`, finds no standard library — guessing either way would be
wrong: a function called directly that does throw ends the program in `std::terminate`, and one
wrapped in a `Result` that cannot throw makes every caller handle an error that never happens. So
the function is not imported until someone states its policy.

## The fix

Declare the policy in an overlay entry: `@ffi(noexcept)` (its thunk still catches, and a throw then
panics naming the function, `[FFI-24b]`) or `@ffi(noexcept=false)`.

```ember,fixed
import cpp "engine.hpp" with (project = "freestanding", overlay = "engine_policy.em")

fn main():
    println(cpp.add(1, 2))
```
