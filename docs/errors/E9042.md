# E9042 — a link ran past its time limit

The failing example is valid Ember that only a hung linker stops, so it is marked
`ember,fails,toolchain`: it must check clean, and its build fails with `E9042` only when its link does
not finish within the limit.

```ember,fails,toolchain
fn main():
    println("hello")
```

```text
error[E9042]: the link of `target/release/bin/main.exe` ran for 30 minutes, its time limit, and was stopped: `cl.exe @target/release/bin/main.exe.rsp`
  = help: its command file is kept at `target/release/bin/main.exe.rsp`; its threads' stacks when it was stopped are in `target/release/bin/main.exe.rsp.stacks.txt`; a longer limit is `[link] timeout = <seconds>` in `ember.toml` [BLD-15]
```

## Why

A link that never finishes is not a slow build: the linker is stuck. Microsoft's `link.exe` has been
seen spinning for over 40 minutes on a program it links in under a second, and a build waiting on it
waits for ever. So every link the build runs has a time limit, 30 minutes unless the package sets
another (`[BLD-15]`). A link still running at its limit is ended, with every process it started (`cl`
runs `link.exe`), and the build fails with this error. Nothing is tried again by itself: a link run
again until it happens to finish would hide the fault. The program the link was writing is removed,
so no half-written program is run or kept in Ember's program cache. The link's command file is kept,
and where the Windows debugger is installed, the stacks of the linker's threads when it was stopped,
for whoever looks into why it hung.

The limit is far above any link of a real program today (the whole `bigpkg` build takes 16.6
seconds); a project whose link does take longer says how long it may take.

## The fix

Build again; if the link hangs again, keep the command file and the stacks and report them. A project
whose links truly take longer sets a longer limit, in seconds, in its `ember.toml`:

```toml
[link]
timeout = 3600
```

The program itself needs no change:

```ember,fixed
fn main():
    println("hello")
```
