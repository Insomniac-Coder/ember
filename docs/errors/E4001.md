# E4001 — a `@noalloc` function reaches an allocation

```ember,fails
fn collect_visible(xs: Span[int], mut out: Array[int]):
    for x in xs:
        if x > 0:
            out.push(x)

@noalloc
fn cull(xs: Span[int], mut out: Array[int]) -> int:
    collect_visible(xs, out)
    return out.len()

fn main():
    values = [1, -2, 3]
    out: Array[int] = []
    println(cull(values.as_span(), out))
```

```text
error[E4001]: `@noalloc` function `cull` reaches an allocation
  = note: cull -> collect_visible -> `Array.push`
```

## Why

`@noalloc` promises that calling the function never asks the allocator for memory, so it can run
where an allocation would be too slow or not allowed at all: a frame's inner loop, an interrupt
handler, a real-time audio callback. The promise covers everything the function runs, so the
compiler follows every call and every drop, and names the chain that leads to the allocation:
here `push` may grow the list.

## The fix

```ember,fixed
fn count_visible(xs: Span[int]) -> int:
    n = 0
    for x in xs:
        if x > 0:
            n += 1
    return n

@noalloc
fn cull(xs: Span[int]) -> int:
    return count_visible(xs)

fn main():
    values = [1, -2, 3]
    println(cull(values.as_span()))
```

Allocate before the call and pass the storage in, use a fixed array, or count instead of
collecting. A `FixedArena` allocates without `Alloc` (`[ARN-4]`).
