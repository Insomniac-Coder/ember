# E2080 — a derive whose requirement a field does not meet

```ember,fails
class Sensor:
    id: int

@derive(Ord)
struct Reading:
    at: int
    source: Sensor

fn main():
    println(1)
```

```text
error[E2080]: field `source` has type `Sensor`, which is not Ord
 --> page.em:7:5
  |
7 |     source: Sensor
  |     ^^^^^^^^^^^^^^
  |
  = note: `@derive(Ord)` needs every field to be Ord [DRV-1]
```

## Why

`@derive(Ord)` generates a comparison that goes over the fields in declaration order, each by `cmp`
(`[DRV-1]`). That only works when every field can be compared; a class handle has no `Ord`, so the
generated code would have nothing to call for `source`. The compiler refuses the derive and names the
field, rather than generating code that cannot compile.

## The fix

Give the field a type that meets the derive's requirement, or leave the field out of the type:

```ember,fixed
@derive(Ord)
struct Reading:
    at: int
    source: int

fn main():
    println(1)
```
