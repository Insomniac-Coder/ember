# E3064 — a view struct that would need two independent regions

```ember,fails
@view
struct Pair:
    a: Span[i32]
    b: Span[i32]

fn bundle(x: Span[i32], y: Span[i32]) -> Pair:
    return Pair(x, y)

fn first(p: Pair) -> i32:
    return p.a[0]

fn main():
    long: Array[i32] = Array[i32]()
    long.push(1)
    short: Array[i32] = Array[i32]()
    short.push(2)
    p = bundle(long, short)
    short.push(3)
    print(first(p))
```

```text
error[E3064]: `short` is borrowed through a view struct that bundles two views
  --> page.em:20:5
   |
19 |     p = bundle(long, short)
   |                      ----- borrow of `short` starts here
20 |     short.push(3)
   |     ^^^^^^^^^^^^^ conflicting access here
21 |     print(first(p))
   |                  - borrow later used here
   |
   = help: pass the two views as separate parameters rather than bundling them; or copy the shorter-lived data into an owned field
   = note: a view struct has one region: the intersection of its fields' (LT-2)
```

## Why

Read the program and the complaint looks wrong. Nothing ever touches `p.b`.
The only field read is `p.a`, which points into `long`, and `long` is not
being modified — so why is pushing to `short` a problem?

Because `Pair` has **one** region, not one per field. `[LT-2]`: "View structs
have one region parameter. Constructing a view struct from several references
gives it the intersection of their regions… Multiple independent regions inside
one struct are not expressible in v1." So `p` holds the loan of `long` *and*
the loan of `short` for as long as any part of `p` is live, and `first(p)` on
the last line keeps both alive across the `push`.

The compiler is not failing to notice that `p.b` is unused. It is telling you
that the type you wrote cannot express what you want: a `Pair` whose two halves
have different lifetimes. In v1 there is no way to say that, because there is
no way to *write* a second region — named lifetimes are reserved for v2
(`[LT-6]`, `E0007`).

This is why the error is its own code rather than an ordinary borrow conflict.
The advice for a conflict is normally "end the borrow sooner", and here that
advice is useless: the use keeping the loan alive is of the *other field*, so
there is nothing to shorten. The fix is structural.

## The fix

Stop bundling. Two parameters get two regions through `[LT-1]`'s elision, and
each is borrowed for exactly as long as it is used.

```ember,fixed
fn first(a: Span[i32], b: Span[i32]) -> i32:
    return a[0]

fn main():
    long: Array[i32] = Array[i32]()
    long.push(1)
    short: Array[i32] = Array[i32]()
    short.push(2)
    print(first(long, short))
    # `short` is the owner's again: neither borrow outlived the call.
    short.push(3)
    print(short[1])
```

The other route `[LT-2]` names is to **copy the shorter-lived data into an
owned field**. Where the struct really has to travel as one value, and one half
of it is small, owning that half removes it from the region entirely:

```ember
@view
struct Pair:
    a: Span[i32]      # still a view
    b: i32            # owned: contributes no region
```

And where both halves must stay views with genuinely independent lifetimes,
`[LT-2]`'s remaining answer is to nest — put each view in its own struct and
pass the two structs separately, which is the same trick as the first fix with
more names.
