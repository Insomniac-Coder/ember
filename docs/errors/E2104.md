# E2104 — a `let` field is assigned outside its `init`

```ember,fails
class Account:
    let id: int
    balance: int = 0

    fn init(id: int):
        this.id = id

    fn renumber(id: int):
        this.id = id

fn main():
    a = Account(7)
    a.renumber(8)
    println(a.id)
```

```text
error[E2104]: `id` is `let`: it is set in `init` and never changed after; to change it, write the field without `let`: `id: int`
```

## Why

A `let` field is fixed once the object is built (`[CLS-9]`): its constructor
gives it a value, and nothing after that replaces it. Code that reads the field
may rely on it never changing, as it relies on an object's identity.

After `init` nothing is changed through a `let` field, for every type (`[CLS-9a]`): a number or
struct field never changes, a list field is never added to, and a class-object field is never
pointed at another object.

## The fix

Set the field in `init`, or drop `let` if the field is meant to change:

```ember,fixed
class Account:
    id: int
    balance: int = 0

    fn init(id: int):
        this.id = id

    fn renumber(id: int):
        this.id = id

fn main():
    a = Account(7)
    a.renumber(8)
    println(a.id)
```
