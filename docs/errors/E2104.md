# E2104 — a `let` field is assigned outside its `init`

```ember,fails
class Account:
    let id: int
    balance: int = 0

    fn init(self, id: int):
        self.id = id

    fn renumber(self, id: int):
        self.id = id

fn main():
    a = Account(7)
    a.renumber(8)
    println(a.id)
```

```text
error[E2104]: cannot assign to `let` field `Account.id` outside its `init`
```

## Why

A `let` field is fixed once the object is built (`[CLS-9]`): its constructor
gives it a value, and nothing after that replaces it. Code that reads the field
may rely on it never changing, as it relies on an object's identity.

`let` fixes the binding, not the value: a `let` field of a type that is not
`Copy` may still be changed *through* (`self.items.push(v)`, `[CLS-9a]`).

## The fix

Set the field in `init`, or drop `let` if the field is meant to change:

```ember,fixed
class Account:
    id: int
    balance: int = 0

    fn init(self, id: int):
        self.id = id

    fn renumber(self, id: int):
        self.id = id

fn main():
    a = Account(7)
    a.renumber(8)
    println(a.id)
```

* `E2103` — assigning to `self` itself in a class method (`[CLS-7]`).
