# E3090 — an arena allocation would skip a required destructor

```ember,fails
fn main():
    arena = Arena.with_capacity(64)
    values: Array[i32] = Array[i32]()
    stored = arena.alloc(values)
```

```text
error[E3090]: `Array[i32]` needs `drop` and cannot be allocated with `Arena.alloc`
 --> page.em:7:26
  |
7 |     stored = arena.alloc(values)
  |                          ^^^^^^ this value's destructor would never run
  |
  = help: use `alloc_nodrop` only when intentionally skipping `drop`, or allocate an owned value normally
  = note: arena values are reclaimed as bytes and are not dropped individually (ARN-2, ARN-3)
```

## Why

Arena reset and destruction reclaim whole chunks. They do not walk the values
inside those chunks, so an individually owned resource such as an `Array`
would never run its destructor. Silently accepting it would leak the array's
buffer even though the source contains no `unsafe` operation.

`needs_drop` is structural: a type needs destruction when it owns a resource,
declares a destructor, or contains a field that does. Plain scalar and other
drop-free values can use `alloc` directly. Generic calls are checked again
after substitution: an opaque `T` does not make `arena.alloc(value)` valid when
the concrete `T` at a call site needs destruction.

## The fix

Prefer ordinary ownership for a value whose destructor matters. If skipping
destruction is genuinely the intended low-level design, spell that decision
with `alloc_nodrop`; the name records that arena reclamation releases only the
storage bytes.

```ember,fixed
fn main():
    arena = Arena.with_capacity(64)
    stored: ref mut i32 = arena.alloc(7)
    println(stored)
```
