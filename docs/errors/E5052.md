# E5052 — adopting a foreign object its library keeps

```ember,fails
from std.ffi import adopt

unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(adopt=false, destroys(pool_free))
    type Pool
    unsafe fn pool_default() -> *mut Pool
    unsafe fn pool_free(pool: *mut Pool)

fn main():
    unsafe:  # SAFETY(ffi): the default pool lives as long as the library
        pool = adopt(pool_default())
```

```text
error[E5052]: a `Pool` may not be adopted: its declaration says `adopt=false`
  --> page.em:11:16
   |
11 |         pool = adopt(pool_default())
   |                ^^^^^^^^^^^^^^^^^^^^^
   |
   = note: the foreign library keeps ownership of its objects; Ember borrows them [FFI-36b]
```

## Why

`adopt` makes a `ForeignBox` the owner of a foreign object: when the box ends,
it frees the object. Some libraries hand out objects they go on owning — a
default pool, a singleton, an object that lives as long as its parent — and
freeing one of those is a double free, or a free of memory the library is still
using, found much later and far away. The type's contract says so once, with
`adopt=false`, and every `adopt` of that type is then refused where it is
written, instead of each caller having to remember.

## The fix

Borrow the object for the calls that need it, and leave its life to the
library:

```ember,fixed
unsafe extern "C":  # SAFETY(ffi): each declaration below matches its C definition
    @ffi(adopt=false, destroys(pool_free))
    type Pool
    unsafe fn pool_default() -> *mut Pool
    unsafe fn pool_free(pool: *mut Pool)
    unsafe fn pool_size(pool: *mut Pool) -> i32

fn main():
    size = 0
    unsafe:  # SAFETY(ffi): the default pool lives as long as the library
        size = pool_size(pool_default())
    println(size)
```
