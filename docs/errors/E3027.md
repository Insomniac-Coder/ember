# E3027 — a `mut` argument is not a mutable place

```ember,fails
fn double(mut n: i32):
    n = n + n

fn main():
    double(1 + 1)
```

```text
error[E3027]: a `mut` argument is not a mutable place
```

## Why

A `mut` parameter is an inout borrow. Its mode comes from the callee's
declaration, so the compiler must find mutable storage at the corresponding
argument even though the call site writes no `mut` marker. A computed value
such as `1 + 1` has no place for the callee to borrow and update.

This is shape B10 rather than the general `E2140` place-expression error: the
failed operation is specifically the parameter-mode adjustment required by
`[FN-2a]`, and the repair belongs at the call boundary.

## The fix

Bind the value to a local before the call, or pass the owning place directly:

```ember,fixed
fn double(mut n: i32):
    n = n + n

fn main():
    value: i32 = 1 + 1
    double(value)
```

A mutable view value produced from a mutable place remains valid under
`[FN-1a]`; for example, a `MutSpan[T]` returned by `buffer.as_mut_span()` is
not rejected merely because the final expression is a call.

## See also

* `[FN-2a]` — the callee's declaration determines the argument mode.
* `[FN-1a]` — the mutable-view-value exception.
* `[DIA-7a]` — the code-to-shape table assigning `E3027` to B10.
* `E2140` — a general value expression used where a place is required.
