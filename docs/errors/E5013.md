# E5013 — a further argument C would promote

```c,file=sum.h
#ifndef SUM_H
#define SUM_H
#include <stdint.h>
/* The sum of `count` further `int64_t` arguments. */
int64_t sum_wide(int count, ...);
#endif
```

```ember,fails
import c "sum.h" as v

fn main():
    narrow: i16 = 3
    # SAFETY(ffi): `sum_wide` reads `count` further arguments
    unsafe:
        println(v.sum_wide(1, narrow))
```

```text
error[E5013]: C passes `narrow` as an `int` through `...`; if `sum_wide` reads another type, convert it first: `sum_wide(1, narrow as i64)`
 --> page.em:7:31
  |
7 |         println(v.sum_wide(1, narrow))
  |                               ^^^^^^
  |
  = help: what passes is decided by C's default argument promotions, and what is read by the C function's `va_arg`
  = note: C reads a further argument with `va_arg` as the type it expects, after its default argument promotions [FFI-8]
  = note: declared in the header at sum.h:5: `int64_t sum_wide(int count, ...)` [DIA-5]
```

The same holds for a `bool` and for any integer narrower than `int` (C passes each as an `int`), and
for an `f32` (C passes it as a `double`).

## Why

A variadic C function has no parameter types after its `...`: it reads each further argument with
`va_arg(arguments, T)`, as whatever type `T` it expects, and nothing on either side checks that the
caller passed one. What the caller passes is not even what it wrote. C's default argument promotions
widen a `bool`, a `char`, a `short` or a `float` before the call, so the callee sees an `int` or a
`double`. Reading anything else is undefined behaviour, and it often runs: `sum_wide` reads eight bytes
where four were passed and adds whatever lies beside them.

The compiler cannot see the `va_arg` that does the reading; it is in C. So it does not guess what the
function reads. It refuses the argument whose type C would change, and names that change, so that the
type you pass is one you chose for what the function reads (`[FFI-8]`).

## The fix

Convert the argument to the type the function reads, here `sum_wide`'s `int64_t`:

```ember,fixed
import c "sum.h" as v

fn main():
    narrow: i16 = 3
    # SAFETY(ffi): `sum_wide` reads one `int64_t`, and `narrow as i64` is one
    unsafe:
        println(v.sum_wide(1, narrow as i64))
```
