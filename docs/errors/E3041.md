# E3041 — a value moved in a loop

```ember,fails
fn consume(owned xs: Array[i32]) -> i32:
    return xs[0]

fn main():
    a: Array[i32] = Array[i32]()
    a.push(1)
    i: i32 = 0
    while i < 2:
        print(consume(a))
        i = i + 1
```

```text
error[E3041]: `a` is moved in a loop
  --> page.em:10:23
   |
10 |         print(consume(a))
   |                       ^ moved here, and the loop comes back
   |
   = help: reassign it before the end of the loop body on every path, or borrow it instead of moving it, or move a clone
   = note: the first iteration moves it and the second finds it gone; a value moved in a loop must be put back before the next iteration [OWN-4]
```

## Why

The first iteration is fine. `a` is there, `consume` takes it, and the value is
gone — that is what `owned` means. The second iteration is the problem: it
arrives at the same line expecting a value that the first iteration gave away.

This is worth its own code because the fix is different from an ordinary use
after move. `E3040` says you used something you had already given away, and its
advice — clone it, or borrow it — is about *this* use. Here the use is fine; it
is the *return trip* that is wrong. You can obey `E3040`'s advice to the letter
and still have a loop that only works once.

The compiler is not guessing. Inside a loop body a moved local is *maybe* moved
rather than definitely moved, because the state at the top of the loop joins two
paths: "first time round, still here" and "been round once, given away". That
join is what `[OWN-4]` is about, and it is why the diagnostic can tell this apart
from a move and a use in the same iteration.

## The fix

Three, and which one is right depends on why the value is being moved.

**Put it back.** `[OWN-4]` says the loop is fine "unless the value is reassigned
before the next iteration on every path" — *every path*, so a reassignment
inside an `if` does not count unless the `else` does it too.

```ember,fixed
fn consume(owned xs: Array[i32]) -> i32:
    return xs[0]

fn borrow(xs: Array[i32]) -> i32:
    return xs[0]

fn main():
    # 1. Reassign before the next iteration.
    a: Array[i32] = Array[i32]()
    a.push(1)
    i: i32 = 0
    while i < 2:
        print(consume(a))
        a = Array[i32]()
        a.push(9)
        i = i + 1

    # 2. Or do not move at all. `[FN-2]` makes the default mode *borrowed*,
    #    so dropping `owned` from the callee is often the whole fix.
    b: Array[i32] = Array[i32]()
    b.push(5)
    j: i32 = 0
    while j < 2:
        print(borrow(b))
        j = j + 1
```

**Or move the loop out of the way.** If the value genuinely belongs to the
callee, the loop probably wants to run *inside* it, or to move a fresh value
each time rather than the same one.

## See also

* `[OWN-4]` — the rule, and the "on every path" condition.
* `[FN-2]` — a parameter with no mode is *borrowed*, which is what makes most
  of these disappear.
* `E3040` — use after a move, when the second use is on the same path rather
  than the next iteration.
