# E9035 — packages in one process disagree about the object-header layout

The error comes from how a running program and its next image were built, not from the source:
the program below is valid. Built and started with `reload = "all"`, then edited with the manifest
changed to `reload = "bodies"`, the next image is refused:

```toml
[build]
reload = "bodies"
```

```ember,fails,toolchain
fn main():
    println("hello")
```

```text
$ ember build --reload main.em
error[E9035]: the running program's objects have 40-byte headers, and this image's would have 24
```

## Why

Whether a build migrates instances fixes the size of every object's header: a reloadable build
links each object into a live-instance list, which takes 16 more bytes. Every image in a process
shares its objects, so they must all agree; an image that read a 24-byte header where the runtime
wrote a 40-byte one would read each field from the wrong place. The disagreement is caught when the
image is linked, before anything runs.

## The fix

Keep the reload mode the program was started with, or build the program again with `ember build`
and restart it.

```toml
[build]
reload = "all"
```

```ember,fixed
fn main():
    println("hello")
```
