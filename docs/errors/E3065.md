# E3065 — retired: multi-region result provenance

`E3065` is no longer emitted. It refused a function returning a view type (a struct, enum or tuple
holding views) when the compiler could not tell which result field points into which argument, as
through a function value:

```ember
@view
struct Pair:
    left: Span[i32]
    right: Span[i32]

fn apply(f: fn(Span[i32], Span[i32]) -> Pair, left: Span[i32], right: Span[i32]) -> Pair:
    return f(left, right)
```

Since 0.9.15 (`[LT-22]`), such a result points into every view argument it may come from (`[LT-1]`
rule 3): the caller keeps `left` and `right` viewed while the `Pair` lives. Where a result should
point into one argument only, `from` says so after the result type (`-> Pair from left`), and a field
that points into anything else is `E3062` (`[LT-23]`).

## See also

* `[LT-22]` — a result's summary, and rule 3 where it needs more than the first line allows.
* `[LT-23]` — `from` on a result with several regions.
* `E3062` — a returned view that points into what its first line does not allow.
