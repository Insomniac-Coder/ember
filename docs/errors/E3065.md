# E3065 — multi-region result provenance

```ember,fails
@view
struct Pair:
    left: Span[i32]
    right: Span[i32]

fn apply(f: fn(Span[i32], Span[i32]) -> Pair,
         left: Span[i32], right: Span[i32]) -> Pair:
    return f(left, right)

fn bundle(left: Span[i32], right: Span[i32]) -> Pair:
    return Pair(left, right)

fn main():
    left: Array[i32] = Array[i32]()
    right: Array[i32] = Array[i32]()
    pair = apply(bundle, left.as_span(), right.as_span())
    println(pair.left.len())
```

## Why

A multi-region view carries one inferred region slot for each borrowed field.
The compiler must publish an internal relation from every returned field to
the input region or regions that supply it. Here `f` is an opaque function
value: its type says that it returns `Pair`, but it carries no exact
field-to-source provenance summary. Treating both fields as if they borrowed
every input would recreate the obsolete intersection model, while treating
either field as `static` could permit a dangling view.

Ember therefore rejects the wrapper rather than guessing. Unknown calls still
conservatively require every input field while they execute; that conservative
access rule is not evidence for an exact returned-field relation.

## The fix

Return an owned value, return the views separately, or use an existing
`@borrows` contract where that contract is semantically applicable. When the
field relation is visible in a direct function body, the compiler infers it:

```ember,fixed
@view
struct Pair:
    left: Span[i32]
    right: Span[i32]

fn apply(left: Span[i32], right: Span[i32]) -> Pair:
    return Pair(left, right)

fn main():
    left: Array[i32] = Array[i32]()
    right: Array[i32] = Array[i32]()
    pair = apply(left.as_span(), right.as_span())
    println(pair.left.len())
```

Do not add a broader `@borrows` annotation merely to silence this error. For a
multi-region result, the annotation cannot collapse independent fields into
one artificial region.
