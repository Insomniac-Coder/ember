# L3015 — an `unsafe fn` with no `@safety`

```ember,fails
unsafe fn read_first(p: *u8) -> u8:
    # SAFETY: the caller promised a readable byte at `p`
    unsafe:
        return p.read()

fn main():
    pass
```

```text
warning[L3015]: `read_first` is an `unsafe fn` that reads through the raw pointer `p`, and nothing says what its callers must make true for that; say it above the function: `@safety("...")`, with what `p` must point to
```

## Why

`unsafe` before a declaration says that whoever uses it must vouch for something the compiler
cannot check. A caller can only vouch for a condition it can read. The signature does not state it,
and a `# SAFETY:` note inside the body says why the function's own blocks are sound, not what its
callers owe. So every `unsafe fn` says it with `@safety`, private ones too: a private one has callers
in its own module, who need the condition as much as anyone (`[UNS-7]`). The message names the first
unsafe step the body takes, because that is usually what the condition is about.

## The fix

State what callers must make true, as the condition they check:

```ember,fixed
@safety("p points to a readable byte")
unsafe fn read_first(p: *u8) -> u8:
    # SAFETY: the caller promised a readable byte at `p` (`@safety` above)
    unsafe:
        return p.read()

fn main():
    pass
```
