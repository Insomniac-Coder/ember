# E5031 — a C++ function has a parameter that maps to nothing

```cpp,file=canvas.hpp
#pragma once

class Canvas {
public:
    Canvas() noexcept {}
    ~Canvas() {}
    int width() const noexcept { return 3; }
};

inline int area(Canvas canvas) noexcept { return canvas.width() * 2; }
```

```cpp,file=canvas_ref.hpp
#pragma once

class Canvas {
public:
    Canvas() noexcept {}
    ~Canvas() {}
    int width() const noexcept { return 3; }
};

inline int area(const Canvas& canvas) noexcept { return canvas.width() * 2; }
```

```ember,fails
import cpp "canvas.hpp"

fn main():
    unsafe:  # SAFETY(ffi): the box owns the canvas for every call
        canvas = cpp.Canvas.new()
        println(cpp.area(canvas.get()))
```

## Why

Every imported C++ function is called through a thunk, an `extern "C"` function that receives
Ember's arguments as C values and passes them on to C++ (`[FFI-3]`). A parameter whose type has no
Ember form — a class Ember holds only behind a pointer, passed by value; a standard-library type
whose bridge is not built — has no C value the thunk could receive and turn back into the C++
object without running C++ code Ember cannot see (a copy constructor, an allocation). Rather than
guess, the importer leaves the function out, says so at the import, and says which parameter and why
wherever the program names it.

## The fix

Give C++ a function whose parameters map: here, the class by reference, which Ember passes as a
`ref` to the object a `ForeignBox` owns.

```ember,fixed
import cpp "canvas_ref.hpp"

fn main():
    unsafe:  # SAFETY(ffi): the box owns the canvas for every call
        canvas = cpp.Canvas.new()
        println(cpp.area(canvas.get()))
```
