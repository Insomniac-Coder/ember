# E2181 — `?` on an `Option` in a `Result` function, or the reverse

```ember,fails
fn first_even(xs: Array[int]) -> Option[int]:
    for x in xs:
        if x % 2 == 0:
            return Some(x)
    return None

fn half(xs: Array[int]) -> Result[int, String]:
    x = first_even(xs)?
    return Ok(x // 2)

fn main():
    println(half([3, 4]).is_ok())
```

```text
error[E2181]: `?` on an `Option[i64]` in a function returning `Result[i64, String]`
```

## Why

`?` passes a failure on unchanged in kind: a `None` out of a function that
returns an `Option`, an `Err` out of one that returns a `Result`. A `None`
carries no error to put in an `Err`, and an `Err`'s error would be lost in a
`None`, so crossing from one to the other is a decision the code has to write
down rather than one `?` makes silently.

## The fix

Give the `None` an error with `.ok_or(err)` (or let a `Result`'s error go with
`.ok()`), then `?`:

```ember,fixed
fn first_even(xs: Array[int]) -> Option[int]:
    for x in xs:
        if x % 2 == 0:
            return Some(x)
    return None

fn half(xs: Array[int]) -> Result[int, String]:
    x = first_even(xs).ok_or(String.from("no even number"))?
    return Ok(x // 2)

fn main():
    println(half([3, 4]).is_ok())
```
