# E5032 — an opaque C++ class is made other than through its constructors

```cpp,file=counter.hpp
#pragma once
#include <vector>

class Counter {
public:
    explicit Counter(int start) : values_{start} {}
    int count() const noexcept { return static_cast<int>(values_.size()); }

private:
    std::vector<int> values_;
};
```

```ember,fails
import cpp "counter.hpp"

fn main():
    counter = cpp.Counter()
```

```text
error[E5032]: `Counter` is an opaque C++ class: Ember does not know how to make one
 --> page.em:4:19
  |
4 |     counter = cpp.Counter()
  |                   ^^^^^^^
  |
  = help: call one of its imported constructors, `Counter.new(…)`, which returns a `ForeignBox[Counter]`
  = note: a C++ class that is not standard-layout and trivially copyable is opaque, made only through its constructors [FFI-32]
```

## Why

A C++ class that is not standard-layout and trivially copyable has an object only C++ can make:
its constructor may allocate, register the object somewhere, or set up members whose layout differs
between compilers (a `std::vector`'s does). Ember therefore knows such a class only by its address,
as an opaque type, and has no layout from which it could build one itself. Its imported constructors
are the only way to get one; each returns the `ForeignBox` that frees it through the class's
destructor.

## The fix

Call an imported constructor, `Counter.new(…)`; a constructor that may throw returns a `Result`
(`[FFI-24]`).

```ember,fixed
import cpp "counter.hpp"

fn main():
    unsafe:  # SAFETY(ffi): the box owns the counter for every call
        match cpp.Counter.new(5):
            Ok(counter):
                println(counter.get().count())
            Err(error):
                println(error.what)
```
