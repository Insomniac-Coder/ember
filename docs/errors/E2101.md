# E2101 — a derived class with a field that has no default needs an `init`

```ember,fails
open class Script:
    name: String

    fn init(mut self, owned name: String):
        self.name = name

class Door(Script):
    width: int

fn main():
    d = Door("front")
    println(d.name)
```

```text
error[E2101]: class `Door` adds a field `width` with no default, so it must declare `init`
```

## Why

A derived class with no `init` is built by its base's constructor: its own
field defaults are evaluated, and then the base's `init` runs on the new object
(`[CLS-10]`). The base's constructor knows nothing of the fields the derived
class adds, so a field with no default would be left without a value.

## The fix

Give the field a default, or write an `init` that sets it and calls
`super.init(…)`:

```ember,fixed
open class Script:
    name: String

    fn init(mut self, owned name: String):
        self.name = name

class Door(Script):
    width: int = 90

fn main():
    d = Door("front")
    println(d.name, d.width)
```

## See also

* `[CLS-10]` — a derived class with no `init` gets its base's constructor.
* `[CLS-11]` — a derived `init` calls `super.init(…)` exactly once.
