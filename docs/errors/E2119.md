# E2119 — a `weakref` link to a value that does not live on its own

```ember,fails
struct Mesh:
    points: Array[float]

fn main():
    b: owns Mesh = owns Mesh(points=[0.0])
    w = weakref b
```

```text
error[E2119]: `b` holds its mesh in a block with no header, which a link cannot test; a link names a class object or a value held `shares` or `thread_shared`: write `b: shares Mesh = shares Mesh(points=[0.0])` in place of line 5, then `w = weakref b`
```

A `weakref` of a part (a field held in its object, an element stored inline: "a `weakref` link needs
an object that lives on its own; link to the player: `cam.target = weakref player`"), of a new value
("the player would end at the end of the line and the link would find nothing; keep it in a name
first: write `p = Player()` above, then `cam.target = weakref p`"), of a value held `dyn I`, `owns dyn
I` or `some I`, and the type `weakref dyn I`, is `E2119` too.

## Why

A link does not keep its target alive, so every opening of it (`if w exists as p:`) tests the
target's header: does it still live (`[WK-12]`)? Only a value with the header of `[OBJ-1]` can be
tested, and only one that lives on its own can be ended on its own: a class object, or a value held
`shares` or `thread_shared`. A value held `owns` is in a block with no header; a part ends with the
value that holds it; a new value ends at the end of its line. A value held `dyn I` is of a kind known
only while the program runs, and whether its header holds the weak count a link needs is its class's
to fix, so a link names a base class, whose every object carries the count.

## The fix

Hold the mesh `shares`: it lives in a block with the header, and the link names that block:

```ember,fixed
struct Mesh:
    points: Array[float]

fn main():
    b: shares Mesh = shares Mesh(points=[0.0])
    w = weakref b
    if w exists as m:
        println(m.points.len())
```
