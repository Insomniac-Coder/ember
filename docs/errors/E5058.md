# E5058 — a class with no `init` derives from a C++ class with no default constructor

```cpp,file=panel.hpp
#pragma once

class Panel {
public:
    explicit Panel(int width) noexcept : width_(width) {}
    virtual ~Panel() {}
    virtual int width() const noexcept { return width_; }

private:
    int width_;
};
```

```ember,file=panel_overlay.em
unsafe overlay cpp "panel.hpp":
    @ffi(trampoline, virtuals=["width"])
    type Panel
```

```ember,fails
import cpp "panel.hpp" with (overlay = "panel_overlay.em")

class Sidebar(cpp.Panel):
    pass

fn main():
    pass
```

```text
error[E5058]: class `Sidebar` declares no `init`, and its C++ base `Panel` has no default constructor
 --> page.em:3:7
  |
3 | class Sidebar(cpp.Panel):
  |       ^^^^^^^
  |
  = help: declare `fn init(self, …)` calling `super.init(…)` with the arguments of one of its constructors
  = note: `super.init(…)` selects the C++ base constructor by arity and argument types [FFI-39b]
```

## Why

Every object of a class deriving from a C++ class owns a C++ object of the base, made by one of the
base's constructors. A class that declares no `init` is made by its base's default constructor, the
one that needs no arguments; when the C++ class has none, there is nothing to call, and choosing
another constructor would mean inventing its arguments. So the class says how its C++ part is made.

## The fix

Declare an `init` that calls `super.init(…)` with the arguments of one of the C++ constructors; the
call selects the constructor by the number and the types of its arguments.

```ember,fixed
import cpp "panel.hpp" with (overlay = "panel_overlay.em")

class Sidebar(cpp.Panel):
    fn init(self):
        super.init(240)

fn main():
    println(Sidebar().width())
```
