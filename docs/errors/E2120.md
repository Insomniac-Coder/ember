# E2120 — methods of its own for another package's type

```ember,fails
extend i64:
    fn twice(self) -> i64:
        return self * 2

fn main():
    x = 4
    println(x.twice())
```

```text
error[E2120]: `i64` is another package's type, so `extend` cannot give it methods of its own
```

## Why

A type's own methods belong to the package that declares it (`[IFC-2]`). If any
package could add them, two packages could each add a `twice` to `i64`, and a
program using both would have two methods of one name with no way to choose; a
new method in the standard library could break every program that had added one
of its name.

## The fix

Declare an interface and implement it for the type. The interface is yours, so
the implementation may live in your package (`[TYP-20]`), and a caller names it
if another package offers the same method:

```ember,fixed
interface Twice:
    fn twice(self) -> i64

extend i64 implements Twice:
    fn twice(self) -> i64:
        return self * 2

fn main():
    x = 4
    println(x.twice())
```

Or wrap the value in a type of your own, which can have any methods.
