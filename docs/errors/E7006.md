# E7006 — a memory order the atomic operation does not support

```ember,fails
from std.sync import Atomic, MemoryOrder

fn main():
    ready = Atomic(false)
    ready.store(true, MemoryOrder.Acquire)
```

```text
error[E7006]: `store` does not support `MemoryOrder.Acquire`
```

## Why

An order says which of the thread's other memory accesses the operation keeps
in place. A load only reads, so it can acquire (later accesses stay after it)
but has nothing to release; a store only writes, so it can release (earlier
accesses stay before it) but has nothing to acquire. `Acquire` on a store, and
`Release` or `AcqRel` on a load, ask for a half the operation does not have.
An order held in a variable is checked the same way when the operation runs,
and a refused one panics.

## The fix

Give a store `Release` (or `Relaxed`, or the default `SeqCst`), and the load
that reads it `Acquire`:

```ember,fixed
from std.sync import Atomic, MemoryOrder

fn main():
    ready = Atomic(false)
    ready.store(true, MemoryOrder.Release)
    println(ready.load(MemoryOrder.Acquire))
```

A read-modify-write (`swap`, `compare_exchange`, the `fetch_` operations) takes
any order.
