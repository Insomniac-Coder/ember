# E1021 — name is not linked in this build

```toml
[package]
name = "firmware"
version = "1.0.0"
layers = ["core"]
```

```ember,fails
fn readings() -> i32:
    values = [1, 2, 3]
    values.push(4)
    return values.len() as i32

fn main():
    readings()
```

```text
error[E1021]: `readings` needs the `alloc` layer, which is not linked in this build
 = note: readings -> …
 = note: this package declares `[package] layers = ["core"]` [STD-6]
 = help: add "alloc" to the package's layers, or do without it
```

## Why

`std` is layered: **core**, **alloc**, **sync**, **io** and **ffi**, each depending only on the
ones before it (`[STD-6]`). A package that declares `[package] layers` is built with only those
layers linked, which is how firmware and kernels use Ember: with `layers = ["core"]` there is no
allocator, no threads and no console. A function that needs a layer the package leaves out
cannot be built (`[BLD-11]`); the message names the layer and the call chain to the operation
that needs it.

A layer is needed by what a function does, through everything it calls: an allocation needs
`alloc`; an atomic operation, a lock or a wait needs `sync`; the console, files, clocks and
processes need `io`; a foreign function needs `ffi`. A package that leaves a layer out also cannot
depend on a package that declares it.

## The fix

Do without the layer: a fixed-size array lives in core.

```ember,fixed
fn readings() -> i32:
    values: [i32; 4] = [1, 2, 3, 4]
    total: i32 = 0
    for value in values:
        total += value
    return total

fn main():
    readings()
```

Or add the layer, with every layer before it, to `[package] layers`.
