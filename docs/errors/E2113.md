# E2113 — an `override` whose first line differs

```ember,fails
open class Handler:
    virtual fn add(a: i32, b: i32) -> i32:
        return a + b

class Twice(Handler):
    override fn add(a: i32) -> i32:
        return a

fn main():
    println(1)
```

```text
error[E2113]: `Twice.add` takes 1 parameter, and the `Handler.add` it overrides takes 2; write `override fn add(a: i32, b: i32) -> i32:`
```

## Why

A call through the base's slot (`[DSP-2]`) passes what the base declared and reads what it promised, so an `override` has the first
line of the method it replaces: the same parameter names, words and types (a generic base's type parameters standing for the
arguments the derived class gives them), the same words on `this` and the same result.

## The fix

Write the first line the message gives. To handle a more specific kind of value, take the base's type and test the kind inside.

```ember,fixed
open class Handler:
    virtual fn add(a: i32, b: i32) -> i32:
        return a + b

class Twice(Handler):
    override fn add(a: i32, b: i32) -> i32:
        return a

fn main():
    println(1)
```
