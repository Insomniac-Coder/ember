# E1042 — a name of a layer the package does not declare

```toml
[package]
name = "sensor"
version = "1.0.0"
layers = ["core"]
```

```ember,fails
fn read(x: int) -> Result[int]:
    return Ok(x)

fn main():
    read(1)
```

```text
error[E1042]: `Result[int]` means `Result[int, AnyError]`, and `AnyError` needs the `alloc` layer, which `sensor` does not declare
 = help: name the error type: `Result[int, SensorError]`
```

## Why

`std` is layered: **core**, **alloc**, **sync**, **io** and **ffi**, each depending only on the
ones before it (`[STD-6]`). A package that declares `[package] layers = ["core"]` may use only core,
which is how firmware and kernels use Ember. `Result[int]` is written short for `Result[int,
AnyError]`, and `AnyError` holds its message in heap memory, so it belongs to the **alloc** layer:
the short form quietly asks for a layer the package left out. The message names the layer, and the
help gives the line to write with an error type of the package's own.

## The fix

Name the error type, which core can hold:

```ember,fixed
struct SensorError:
    code: int

fn read(x: int) -> Result[int, SensorError]:
    return Ok(x)

fn main():
    read(1)
```

Or add `"alloc"` to `[package] layers`.
