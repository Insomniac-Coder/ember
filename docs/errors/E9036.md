# E9036 — a reloadable package may not link the runtime statically

```toml
[build]
reload = "all"
runtime = "static"
```

```ember,fails
fn main():
    println("hello")
```

```text
error[E9036]: a reloadable package cannot link its own copy of the runtime
```

## Why

A reload loads a new image into a running process and moves the old image's objects, statics and
call table over to it. Those live in the runtime: its allocator, its live-instance list, its table
of thunks. If each image linked its own copy, the new image would see none of what the old one
made, and objects freed by one copy would have been allocated by another. With reload on, one
shared runtime serves every image in the process.

## The fix

Leave `runtime` out, or say `"shared"`: a reloadable build links the shared runtime.

```toml
[build]
reload = "all"
runtime = "shared"
```

```ember,fixed
fn main():
    println("hello")
```
