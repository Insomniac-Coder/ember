# E5057 — a trampoline's `virtuals` names a method that is not virtual

```cpp,file=layer.hpp
#pragma once

class Layer {
public:
    Layer() noexcept {}
    virtual ~Layer() {}
    virtual int on_update(int step) noexcept { return step; }
    int id() const noexcept { return 1; }
};
```

```ember,file=layer_overlay.em
unsafe overlay cpp "layer.hpp":  # SAFETY(ffi): each entry matches its declaration in the header
    @ffi(trampoline, virtuals=["on_update", "id"])
    type Layer
```

```ember,file=layer_fixed.em
unsafe overlay cpp "layer.hpp":  # SAFETY(ffi): each entry matches its declaration in the header
    @ffi(trampoline, virtuals=["on_update"])
    type Layer
```

```ember,fails
import cpp "layer.hpp" with (overlay = "layer_overlay.em")

fn main():
    pass
```


## Why

A trampoline overrides each named virtual in a C++ subclass, so that C++ calls reach Ember. A
non-virtual method cannot be overridden: C++ calls it directly, by the static type, and a trampoline
"override" of it would never run. Accepting the name would let an Ember class appear to replace
`id()` while every C++ caller kept getting the base's answer. The same holds for a name the class
does not declare, and for an overloaded one, where the trampoline could not tell which of the
functions is meant.

## The fix

Name only virtual methods. A non-virtual method of the C++ class is still a method of the Ember
class, which Ember code calls as it is.

```ember,fixed
import cpp "layer.hpp" with (overlay = "layer_fixed.em")

class Doubled(cpp.Layer):
    override fn on_update(self, step: i32) -> i32:
        return step * 2

fn main():
    println(Doubled().on_update(4))
```
