# E5062 — an overlay declares a C++ function both `noexcept` and throwing

```cpp,file=policies.hpp
#pragma once
#include <stdexcept>

inline int risky(int x) {
    if (x < 0) throw std::runtime_error("negative");
    return x;
}
```

```ember,file=both.em
unsafe overlay cpp "policies.hpp":  # SAFETY(ffi): each entry matches its declaration in the header
    @ffi(noexcept, noexcept=false)
    fn risky(x)
```

```ember,file=throwing.em
unsafe overlay cpp "policies.hpp":  # SAFETY(ffi): each entry matches its declaration in the header
    @ffi(noexcept=false)
    fn risky(x)
```

```ember,fails
import cpp "policies.hpp" with (overlay = "both.em")

fn main():
    pass
```

```text
error[E5062]: the entry for `risky` declares it both `noexcept` and throwing
 --> both.em:3:8
  |
3 |     fn risky(x)
  |        ^^^^^
  |
  = note: a C++ function has one exception policy [FFI-43]
```

## Why

A function's exception policy is one fact with two outcomes for its callers: a non-throwing function
returns `T`, a throwing one `Result[T, CppError]` (`[FFI-24]`). An entry that says both, or two
overlays an import composes that say opposite things, leave the signature undecided, and whichever
the compiler picked, half of what the overlays assert would be false. Saying which is the overlays'
job, so the contradiction is an error rather than a silent choice. A later overlay that means to
change an earlier one's word writes `override` before its entry (`[FFI-30c]`).

## The fix

Keep the one policy that is true of the function: `risky` throws, so it is declared throwing and its
calls return a `Result`.

```ember,fixed
import cpp "policies.hpp" with (overlay = "throwing.em")

fn main():
    match cpp.risky(-1):
        Ok(value):
            println(value)
        Err(error):
            println(error.what)
```
