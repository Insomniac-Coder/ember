# E2111 — a method that replaces an inherited virtual one without `override`

```ember,fails
open class Shape:
    virtual fn area(self) -> float:
        return 0.0

class Square(Shape):
    fn area(self) -> float:
        return 4.0

fn main():
    println(Square().area())
```

```text
error[E2111]: `area` replaces an inherited virtual method, so it must say `override`
```

## Why

Replacing a virtual method changes what every call through the base class does,
so Ember makes it visible where it happens (`[CLS-4]`, ODR-028). Without the
word, a method that happens to share a name with an inherited one would change
the behaviour of code far away — or, if the author meant a new method, a later
change to the base would silently start or stop dispatching to it.

## The fix

Say `override`, or give the method another name:

```ember,fixed
open class Shape:
    virtual fn area(self) -> float:
        return 0.0

class Square(Shape):
    override fn area(self) -> float:
        return 4.0

fn main():
    println(Square().area())
```
