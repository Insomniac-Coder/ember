# E2043 — an associated type's default leads back to itself

```ember,fails
interface Graph:
    type Node = Edge
    type Edge = Node
    fn first(self) -> Node

fn main():
    println(1)
```

```text
error[E2043]: the default of `Graph`'s `Node` leads back to `Node`
 --> page.em:2:10
  |
2 |     type Node = Edge
  |          ^^^^
  |
  = help: give one of these associated types no default, or a default that does not name the others
  = note: an implementation takes a default by following it until it reaches a type [IFC-4]
```

## Why

An interface may give an associated type a default, `type Out = Self`: an
implementation that does not say what `Out` is takes the default. A default may
name another associated type, `type Key = Item`, and the implementation follows
it: `Key` is whatever that implementation's `Item` is. When the defaults lead
round in a circle — `Node` is `Edge` and `Edge` is `Node` — following them never
reaches a type, so an implementation that states neither would have none. The
error is reported once for each associated type on the circle.

## The fix

Break the circle: leave one of them without a default, so each implementation
states it, and let the other follow it:

```ember,fixed
interface Graph:
    type Node
    type Edge = Node
    fn first(self) -> Node

struct Line:
    n: int

extend Line implements Graph:
    type Node = int
    fn first(self) -> int:
        return self.n

fn main():
    println(Line(3).first())
```
