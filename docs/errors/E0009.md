# E0009 — malformed literal

```ember,fails
fn main():
    path = "C:\data"
    println(path)
```

```text
error[E0009]: unknown escape `\d`
```

The same code reports the other literals II.5's grammar does not write: a `\x` escape without two
hex digits, or above `0x7F`; a `\u{…}` without its braces, with more than six digits, or naming a
surrogate; a character literal whose escape is not one Unicode scalar value; a raw string with more
than eight `#`, or without its `"`; a non-ASCII character in a byte string; a lone `}` in an
f-string. An unclosed string or f-string hole is `E0101`; a NUL in a `c"…"` literal is `E5064`
(`[TXT-3]`).

## Why

A literal's text is read exactly as the grammar writes it, so that what a program says is what it
holds: an escape the grammar does not know would otherwise be a guess at what was meant (Windows
paths are the usual case), and a byte string with a non-ASCII character would have no single byte
for it.

## The fix

Escape the backslash, or write a raw string:

```ember,fixed
fn main():
    path = r"C:\data"
    println(path)
```
