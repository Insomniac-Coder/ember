# E2030 — `@view` on a type that is not a view

```ember,fails
@view
struct Point:
    x: int
    y: int

fn main():
    p = Point(1, 2)
    println(p.x)
```

```text
error[E2030]: `@view` on `Point`, which holds no view; remove `@view`
  = help: delete the `@view` line; a type is a view when it holds a reference, a `Span`, a `MutSpan`, a `StrView` or another view
  = note: `@view` documents what the compiler infers [TYP-34]
```

## Why

The compiler decides by itself that a struct, enum or tuple holding a view is a view type, and that it lives no longer than what it points into (`[TYP-34]`). `@view` on the declaration is only documentation, and documentation that is checked cannot be wrong: a mark on a type that holds no view says something false about how long its values may live.

## The fix

Remove the mark, or make the type hold a view:

```ember,fixed
struct Point:
    x: int
    y: int

fn main():
    p = Point(1, 2)
    println(p.x)
```
