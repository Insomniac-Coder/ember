# E2150 — `is` on a value

```ember,fails
fn main():
    a = 3
    b = 3
    println(a is b)
```

```text
error[E2150]: `is` needs class handles, and `i64` is not one
```

## Why

`a is b` asks whether two names reach the same object, not whether two values
are equal. A class handle has that identity: two handles may reach one
object, or two objects with the same fields. A number, a struct or an enum
does not: it is copied or moved, never shared, so "the same one" has no
answer apart from its contents. Python answers `3 is 3` one way and
`1000 is 1000` another, depending on how the interpreter happens to cache
integers; Ember refuses rather than answer arbitrarily. The one test of a
value `is` makes is an `Option`'s: `x is None`, `x is not None`.

## The fix

Compare the values:

```ember,fixed
fn main():
    a = 3
    b = 3
    println(a == b)
```
