# E5068 — one live foreign object adopted twice

```ember,fails
from std.ffi import adopt

unsafe extern "C":
    @ffi(destroys(widget_free))
    type Widget
    fn widget_new(id: i32) -> *mut Widget
    fn widget_free(widget: *mut Widget)

fn main():
    unsafe:  # SAFETY(ffi): `widget_new` returns a new widget the caller owns
        widget = widget_new(1)
        _first = adopt(widget)
        _second = adopt(widget)
```

```text
error[E5068]: this foreign object is already adopted
  --> page.em:13:25
   |
12 |         _first = adopt(widget)
   |                        ------ first adopted here
13 |         _second = adopt(widget)
   |                         ^^^^^^ adopted a second time here
   |
   = help: adopt it once and pass the box, or `adopt` a different object
   = note: two `ForeignBox`es would each free it; the second `adopt` panics at run time [FFI-36b]
```

## Why

`adopt` makes a `ForeignBox` the owner of a foreign object, and the box frees the object when it
ends. Two boxes of one object would free it twice: the second free is of memory the allocator may
already have handed to something else. The runtime records every object Ember owns and stops the
second `adopt` with a panic, but when both calls take the same local in one function the mistake is
visible in the source, so it is reported where it is written instead of when that path first runs.

## The fix

Adopt the object once and pass the box to whatever else needs it:

```ember,fixed
from std.ffi import adopt, ForeignBox

unsafe extern "C":
    @ffi(destroys(widget_free))
    type Widget
    fn widget_new(id: i32) -> *mut Widget
    fn widget_free(widget: *mut Widget)

fn keep(widget: ForeignBox[Widget]):
    pass

fn main():
    unsafe:  # SAFETY(ffi): `widget_new` returns a new widget the caller owns
        widget = widget_new(1)
        keep(adopt(widget))
```
