## 5. Defects found in the compiler (D-014..D-025)

Every one of these let a program do something the specification forbids.

| # | What | Status |
|---|---|---|
| D-014 | a `##` doc comment above an `import` was `E0100`; `[LEX-11]` says it is discarded in silence | fixed |
| D-015 | interfaces collected **per module**, so a module checked first could not implement one declared later. `[MOD-4]` allows import cycles, so no load order would have worked | fixed |
| D-016 | a bound, an `implements` clause and a supertrait each recorded the name **as written**, so an imported `Ord` did not match its implementation | fixed |
| D-017 | `Self` resolved in no signature, so Part IV §8's nine interfaces could not be written at all | fixed |
| D-018 | `[RNG-4]`'s range tracking derives a range for **constants only** | **open — precision, not soundness** |
| D-019 | **field visibility was not enforced at all** — every field of every struct read from every module | fixed |
| D-020 | `pub(read)` was parsed and dropped; `E1050` was emitted by nobody | fixed |
| D-021 | `[STR-1]`'s memberwise constructor ignored its fields' visibility, so a `pub(read)` field could be written by constructing | fixed |
| D-022 | **`[SPN-1]`'s coercion took no borrow**, so `v: Span[i32] = a` then `a.push(…)` compiled and read freed memory — a use-after-free from Safe Ember | fixed |
| D-023 | `lower_span_get` assumed `Some` was `Option`'s variant 0; `option_of` builds `None` first | fixed |
| D-024 | a call argument parsed as a full expression, so a lambda's `:` body inside brackets swallowed a block | fixed |
| D-025 | `RangeError` is not a name a program can write, so `[RNG-3]`'s own signature cannot be written | **open — small** |

**D-022 is the one to remember.** It was found by *asking whether the borrow
checker saw the view*, not by a test going red — nothing tested it, because the
feature was an hour old. The fix: `[SPN-1]`'s coercion emits
`SpanFrom(&container)`, because `Rvalue::Ref` is what `collect_loans` looks
for, and the call terminator's elision carries the loan's region to the view.

## 6. Open problems, in the order they should be picked up

### 6.1 The deviation that matters — ADR-018

`[CLO-3]`: "A parameter declared `f: fn(A) -> R` is a generic over `Callable`
(static dispatch, monomorphised)." This compiler makes `TyKind::Fn` a
**concrete function pointer**. Consequences:

* a **capturing closure is refused by name** — it has no environment to live in;
* a call through one is an **indirect** call, where `[COST-3]` classes a
  specialised generic call as *not observable* (a direct call).

**The upgrade is the same work as capturing closures**, and three of its four
steps are existing machinery:

1. a closure literal builds a **synthetic struct** of its captures — `ref T`
   for a read-only capture, `ref mut T` for a mutated one (`[CLO-2]`) — with a
   synthesised `call` method. `[CLO-1]`'s "view type if it captures by
   reference" then falls out of `is_view`, and `[CLO-4]` out of `[TYP-15]`;
2. **new work**: a parameter written `f: fn(A) -> R` becomes a synthetic
   generic parameter carrying that signature as its bound;
3. `f(args)` resolves to the parameter's `call` — `synth_bound_method` already
   does this for a bound's method;
4. instantiation re-checks the body with the parameter bound to the closure's
   struct — `check_instantiations` already does this for every other generic.

### 6.2 The rest of Ember Core (`[CONF-2]`), roughly in dependency order

* **`Cell` / `RefCell`** (`[CELL-1..11]`) and **`Arena`** (`[ARN-1..7]`) both
  need the same missing primitive: **interior mutability**. `[CELL-1]`'s `set`
  takes `self` (a *shared* borrow) and writes; `[ARN-1]`'s `alloc*` methods
  take `self` and bump the pointer. Either write them as compiler-known types
  with builtins (as `Array` and `Span` are), or add the `UnsafeCell` `[CELL-9]`
  names. **Decide that once, for both.**
* **`[DSJ-*]`** `assert_disjoint` — deliberately not started. `[DSJ-2]` says
  the proof is "attached to the **returned values**, not to a program point",
  and the type system has no place to carry a fact on a value. Half of it would
  be the API and the runtime comparison with the *fact* unenforced, which is
  the half that matters.
* **`[RNG-4]`** range tracking (D-018). Half of it waits for a generic
  `min`/`max` over a numeric bound, which waits on interface generics.
* **`[TXT-*]`** the string and text model; **`[CTL-3b]`/`[CTL-3c]`** guaranteed
  iteration lowering with the emitted-C assertions.
* **`[DIA-7]`'s shape catalogue with `tests/ui/` snapshots** — a **Phase 2
  exit criterion**. `compiler/ember_diag/src/shapes.rs` holds every shape;
  `tests/ui/` is empty and `[DIA-13]` requires a rendered snapshot per shape
  plus `[PHIL-8a]`'s `.fixed.em` companion.

## 7. Traps paid for, in this session

* **A trailing `##` is a doc comment**, not a comment: `x = 1  ## note`
  attaches to the next declaration and changes what parses. Use `#`.
  This cost time three separate times.
* **Line endings.** `.gitattributes` pins LF and the Edit tool writes CRLF on
  this host. Normalise before committing; a mixed file makes the *next*
  scripted edit fail silently. `git ls-files --eol | grep "w/crlf\|w/mixed"`.
* **A Python triple-quoted string treats `\<newline>` as a continuation**, so
  a Rust string written that way loses its backslash and keeps the
  indentation. One diagnostic shipped with eighteen spaces in the middle of a
  sentence. Use `concat!`.
* **`option_of` builds `None` first.** Read a variant index from the type
  table, never assume it.
* **The conformance harness requires an `accept_*` case per directory**
  (`[TST-4a]`), and every file must carry `#$ rules:`.
* A module path segment cannot contain `-`, so a conformance test under
  `tests/conformance/MOD-7/` imports its support module relative to the entry
  file (`from support.health import …`), not by a path through the directory.
